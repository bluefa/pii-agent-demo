R23 패널 데모 — 인터랙티브 + 실제 API 응답

좌측 패널은 클릭 가능합니다 — 시도 이력 행 클릭 → Attempt 상세(← 뒤로), [로그] → 뷰어 오버레이 (Terraform 로그 | 상태 응답 원문 토글), Esc는 뷰어 → 상세 → 루트 순으로 접힙니다. 우측은 이 패널을 그리는 실제 API 응답 원문 — 필드명·형태는 orchestrator의 DtoSnakeCaseSerializationTest·DTO 코드에서 그대로 가져왔고, 값은 mock-infra 계약 (job id = 숫자, terraformState = RUNNING/COMPLETED/FAILED, failReason = "mock forced failure")을 따릅니다.

파이프라인 상세 > Task 패널 (400px) — 캔버스는 생략

이 패널을 그리는 API 응답

아래 JSON이 곧 좌측 패널의 데이터 소스입니다(같은 객체를 렌더). 시나리오를 바꾸면 함께 갱신됩니다.

GET/api/v1/pipelines/{pipelineId}/tasks/{taskId} — Task 상세 (P5) 

      
attempt마다 terraform_results[](종결 결과 메타) · job_states[](진행 관측) ·
        check(폴 카운터)가 인라인. response는 어댑터가 정규화한 job id 배열 원문.

    

    

      GET…/attempts/{n}/jobs/{jobId}/result — Terraform 로그 본문 (P11)
      
뷰어에서 [로그]를 열면 그 job의 응답이 여기 표시됩니다.

      
content가 로그 원문(최대 16MB, truncated면 tail 우선 절단).
        content: null = 본문 수집 실패 포인터 행(200). 행 자체가 없으면 404
        ORCHESTRATION_TERRAFORM_RESULT_NOT_FOUND.

    

    

      GET…/attempts/{n}/jobs/{jobId}/state — 상태 응답 원문
      
뷰어에서 [상태 응답 원문] 탭을 열면 그 job의 응답이 여기 표시됩니다.

      
last_response = InfraManager status 응답 body 전문(전 필드 보존, compact JSON).
        last_state는 정규화 전 원시 terraformState.
