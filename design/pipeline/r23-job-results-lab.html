R23 v2 시안 랩 — Terraform Job · Condition Job 결과 노출

파이프라인 상세 > Task 패널에 orchestrator job 결과를 배치하는 시안 — v2.2 (오너 피드백 반영): 2탭(실행 정보 | 정의·계약, Figma 70-35 유지) + 시도 기록은 실행 정보 안 Attempt 드릴다운(← 뒤로)으로 통합, job 실패 메시지 텍스트 제거(칩만), 로그 뷰어에 상태 응답 원문 토글 + 실시간 폴백.
데이터 계약: P5 attempts[].terraform_results[] · job_states[] · check, 로그 본문 …/jobs/{jobId}/result(P11), 상태 응답 원문 …/jobs/{jobId}/state.

1정보 계층 — 운영자 질문 → 표면 매핑

표면은 셋이다: 실행 정보 탭(현재 상태 + 시도 이력), Attempt 상세(드릴다운), 정의·계약 탭(참조 정보 — Figma 원 디자인 유지). 시도 기록만 탭에서 드릴다운으로 접었다.

계층운영자 질문보여줄 정보 · 표면데이터 소스
L1"이 task 성공했어? 실패했어?" status pill + error_code 배지 + 진행 기록 kv — 루트 패널 상단 TaskDetail.status / error_code / started·finished_at
L2"job 단위로는 어디까지 갔어?" Job 목록(최신 attempt) — 칩 4종(성공/실패/진행 중/기록 없음)만, 메시지 텍스트 없음. Condition은 판정 요약 kv + 폴 이력 — 루트 패널 본문 terraform_results ∪ job_states (job_id join) / check
L3"원문 보여줘 (로그·응답)" 뷰어 — job 행 [로그] → 캔버스 오버레이, [Terraform 로그 | 상태 응답 원문] 토글. 클릭 시에만 fetch P11 result.content / state.last_response
L4"이전 시도에선 무슨 일이?" 시도 이력 리스트(한 줄 요약) — 행 클릭 → Attempt 상세로 패널 전환, ← 뒤로 attempts[] (행) → attempts[n] (상세)

2패널 내비게이션 — 루트 ⇄ Attempt 상세

스택 내비게이션: 패널은 뷰 스택 하나를 가진다 — 루트(Task) → Attempt 상세. 드릴다운하면 패널 헤더가 [←] + 컨텍스트 crumb로 바뀌고, ←(또는 Esc 1회)로 루트 복귀, 루트에서 Esc는 패널 닫기. 뷰어(로그/원문)는 스택이 아니라 캔버스 오버레이 — 패널 상태를 건드리지 않아 job 간 비교가 쉽다. refetch 없음: 두 뷰 모두 이미 로드된 TaskDetail 하나에서 그린다.

열릴 때 스크롤은 맨 아래(tail)에서 시작 — terraform 오류는 로그 끝에 있고, 절단도 tail 우선이다. 원문은 escape 처리된 <pre>로만 렌더(설계 §4.6). "상태 응답 원문" 탭은 JSON pretty-print + 같은 복사/저장 버튼 — job 실패의 구조화된 사유(failReason 등 전 필드)가 여기 들어 있다.

서버가 구분하는 두 개의 "없음"은 다른 empty state로 — 안내가 다음 행동을 짚어야 한다.

4결정 로그 · 열린 질문

질문결정
탭 구조 (v2.2)2탭 — 실행 정보 | 정의·계약 (Figma 70-35 유지). 시도 기록 탭만 접어서 실행 정보 안 드릴다운(← 뒤로)으로 통합, 정의·계약은 원 디자인대로 별도 탭 (오너: "기존 디자인을 무너트리지 마라"). Attempt 상세 뷰에는 탭 없음 — ← 헤더가 대체
실패 메시지 노출 (v1 → v2)텍스트 제거 — job 칩 4종(성공/실패/진행 중/기록 없음) + 시도 error_code 배지까지만. failure_detail·last_fail_reason은 기본 UI에서 제외, 구체 원인은 뷰어(로그·상태 응답 원문)가 경로 (오너 피드백)
Message 원문 접근뷰어 안 토글 [Terraform 로그 | 상태 응답 원문] — result.content(P11)와 state.last_response를 같은 표면에서. job 행 버튼은 [로그] 하나 유지
job 목록 구성terraform_results ∪ job_states job_id join. response 원문 파싱 금지(사적 계약) — 둘 다 없는 job은 UI가 존재를 모르는 게 계약상 맞다
드릴다운 refetch없음 — 루트·Attempt 상세 모두 로드된 TaskDetail 하나에서 렌더. 뷰어만 lazy fetch
두 개의 "없음"content:null(포인터) ≠ 404(행 없음) — empty state 문구 분리
로그 접근 범위 (v2.1)저장본 + 실시간 폴백 — P11이 저장 행(terraform_result)을 우선 서빙하고, 없으면 InfraManager result API를 즉석 프록시(source: "live" 표시). RUNNING·호출 오류 종결 시도에서도 로그 확인 가능(오너 요구). orchestrator 변경 필요 — exposure 설계 문서가 "별도 결정"으로 지목한 항목
CONDITION_CHECK드릴다운 없음 — 판정·외부상태를 진행 기록 kv에 흡수, 폴 이력 인라인(최근 5 + 전체 보기)
오너 확인 필요:
① Esc 계층 — 뷰어 열림 > Attempt 상세 > 패널 닫기 순 3단으로 가정 (LIN-22 카탈로그 패널의 Escape 계층 분리와 같은 규칙).
② 상태 응답 원문 토글 — job당 두 원문(로그·응답)을 뷰어 토글로 묶는 안. 응답 원문 수요가 거의 없다고 보면 토글 빼고 로그 단독으로 시작해도 됨.
③ 16MB [파일로 저장] — 필요 없으면 복사만.
④ Figma 반영 — 이 v2는 Figma 70-35의 3탭과 다른 구조. 방향 확정되면 Figma 쪽도 맞출지.
