# 디자인 결정 프로세스

> LIN-20 회고에서 도출. "정확하지만 멋없는" 결과의 원인은 실행력이 아니라
> **결정 순서와 게이트의 부재**였다. 이 문서는 admin 디자인 작업이 따라야 할
> 단계·산출물·게이트를 고정한다.
> 참고: [awesome-claude-design](https://github.com/rohitg00/awesome-claude-design)의
> DESIGN.md 단일화 / anti-slop / variant 분기 / 채점식 audit 관행.

## 원칙 3개

1. **결정은 되돌리기 비싼 것부터** — 인상(캐릭터) → 시스템(토큰·스케일) → 레이아웃(IA) →
   컴포넌트 → 폴리시. 아래 단계에서 위 단계를 재논의하지 않는다.
2. **취향 결정은 오너가 "고르고", 측정 결정은 내가 "맞춘다"** — 오너에게 백지 질문("어떤 게 좋아요?")
   금지. 항상 **실물 비교물 2~3개**를 만들어 선택지로 제시한다. 반대로 측정 가능한 것
   (크기 정렬, 대비비, 자간)은 물어보지 않고 시스템 값으로 맞춘다.
3. **게이트 없이 다음 단계 진입 금지** — 특히 구현·커밋은 오너 체크포인트 뒤에만.

## 단계

### Phase 0 — 캐릭터 결정 (프로젝트당 1회)

- **산출물**: 인상 선언 1줄 — "참조 제품 1~2개 + 인상 형용사 3개"
  (예: "n8n 실행 화면 + Grafana — 어둡고, 밀도 있고, 상태색이 주인공")
- **방법**: 실제 제품 스크린샷 3~5개를 보드로 제시 → 오너가 고름.
  내가 만든 시안이 아니라 **실물**로 비교 (취향 결정의 기준점을 진품에 둔다)
- **게이트**: 오너 선택. 이 선언이 이후 모든 단계의 심판 기준.
- **✅ 결정 (2026-07-03, 오너)**: **n8n 실행 화면(구조) + Linear(표면·밀도 감각)**
  — "정밀하고, 조용하고, 상태색이 주인공". 밝기(다크 수위)는 Phase 3 variant로 확정.

### Phase 1 — 디자인 시스템 파일 (DESIGN.md 역할)

- **산출물**: `admin-pipeline-design-system.md` — 아래를 전부 표로:
  - 표면 밝기 사다리 (배경 단계 수, 다크 앵커 위치)
  - 타이포 롤 (기존 [admin-pipeline-typography.md](admin-pipeline-typography.md) 편입)
  - **사이징 스케일**: 컨트롤 높이 3단 고정, 아이콘 크기 1종, radius 2종, 칩/배지 높이,
    카드 규격 + **나란한 카드 높이 정렬 규칙**, 고정 높이 컴포넌트 목록(Task 노드 등)
  - anti-slop 금지 목록 (AI 디폴트 지문: 무의미한 pulse dot, 배지 3중첩,
    장식용 좌측 컬러 바, 근거 없는 파랑 액센트 남용 …)
- **게이트 (기계)**: 치수 audit 스크립트 — 렌더된 화면에서 스케일 밖 값 0건이어야 통과.
  "모든 크기는 표에서 나온다"가 검증 가능해야 함.

### Phase 2 — 페이지 IA / 레이아웃

- 기존 방식 유지 ([admin-pipeline-detail-ia.md](admin-pipeline-detail-ia.md) 패턴):
  정보 인벤토리 → 운영자 질문 우선순위 → 강조 계층 → 스케치
- **게이트**: 오너 스케치 승인

### Phase 3 — Variant 시안 (신규 — 핵심)

> **✅ 결정 (2026-07-03, 오너)**: 상세 페이지(#/pipeline/124)와 대시보드를 A(전면 다크) /
> B(다크 크롬+라이트 캔버스) / C(고대비 라이트) 3종으로 렌더 비교 → **B 선택.**
> variant 파일(`admin-pipeline-variant-*.html`)은 Phase 4 적용 완료 후 제거한다.

- 시스템+IA 확정 후 **대표 페이지 1곳**을 2~3개 변형으로 실제 렌더
  (로직 무변경, 스타일 오버라이드만 얹은 별도 파일)
- **산출물**: 같은 화면·같은 데이터의 스크린샷 나란히 + 각 변형의 한 줄 성격
- **게이트**: 오너가 고름. **한 방향으로 바로 구현하는 것 금지.**

### Phase 4 — 구현 + 3중 검증

선택된 variant를 전 페이지에 적용한 뒤, 게이트 3개를 순서대로:

| 게이트 | 검증자 | 내용 |
|---|---|---|
| A. 기계 | audit 스크립트 | 스케일 밖 치수 0건 · 같은 행 컨트롤 높이 불일치 0건 · 콘솔 에러 0 · §4.5 규칙 동작 |
| B. 비평 | codex/서브에이전트 | **md가 아니라 렌더 스크린샷**을 채점 — 계층·slop·일관성·Phase 0 선언 부합. P0/P1 소진까지 라운드 |
| C. 오너 | 오너 | before/after 나란히 확인 후 승인 — **승인 후에만 커밋** |

## Phase별 모델 배정

판단 밀도가 필요한 단계에만 상위 모델을 쓴다 (오너 합의, 2026-07-03).

| Phase | 업무 성격 | 배정 |
|---|---|---|
| 0 캐릭터 | 레퍼런스 큐레이션 (판단은 오너) | 저비용 모델로 충분 |
| 1 시스템 | 제약 설계 — 스케일 안에 예외 없이 욱여넣기 | **상위 모델 (Fable급)** |
| 2 IA | 정보 계층 분석 | 상위 모델 |
| 3 Variant | 성격이 뚜렷이 다른 방향을 실물로 저작 | **상위 모델 — 최핵심 투입 구간** |
| 4A 기계 게이트 | audit 스크립트 실행·치수 수정 반복 | 저비용 서브에이전트/스크립트 |
| 4B 픽셀 비평 | 스크린샷 채점, 선언 부합 판정 | **상위 모델 + 독립(fresh-eyes) 비전 에이전트 교차** — codex CLI는 이미지 불가라 문서 교차 전용 |
| 4C 오너 게이트 | 승인 | 모델 무관 |
