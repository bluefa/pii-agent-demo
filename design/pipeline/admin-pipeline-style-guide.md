# Admin Pipeline — 스타일 가이드 (타이포·간격·배치의 근거)

> 오너 제공 기준(2026-07-04: 표준 폰트 세트·행간 2단·여백·케이스 축소·근거 있는 디자인)을
> 이 어드민에 맞게 구체화한 문서. **크기·간격 값의 단일 권위** —
> [admin-pipeline-typography.md](admin-pipeline-typography.md)의 9롤 크기 표와
> [admin-pipeline-design-system.md](admin-pipeline-design-system.md) §1의 폰트 관련 값은
> 본 문서가 대체한다 (컨트롤·행 높이 등 비폰트 치수는 design-system §1 유지).

## 0. 원칙 (오너 가이드의 3장)

1. **공통이 먼저** — 페이지마다 새로 정하지 않는다. 여기 있는 세트에서만 고른다.
2. **케이스 축소** — 크기·간격·무게의 가짓수가 적을수록 시스템이 된다.
   실측: 이 가이드 적용 전 폰트 크기 **11종**(10.5/11/12/12.5/13/14/15/16/18/20/26) → **6종**.
3. **모든 값에 근거** — 감으로 정한 값은 한 달 뒤 촌스러워진다. 값마다 이유를 남긴다.

## 1. 타입 스케일 — 계층 수를 먼저 세고, 계층당 크기 하나

이 화면에서 텍스트의 역할은 6개뿐이다. 역할 밖의 크기는 존재할 수 없다.

| 역할 | 크기 | 무게 | 행간 | 색 | 사용처 |
|---|---|---|---|---|---|
| 페이지 제목 | **24** | 700 | 120% | strong | `h1` — 페이지당 1개 |
| 섹션 제목 | **20** | 600 | 120% | strong | `.section-title` |
| 서브 제목 | **16** | 600~700 | 120% | strong | 모달 h3 (다이얼로그 제목) |
| 본문·데이터 | **14** | 400~600 | 140% | strong/medium | 테이블 셀·버튼·입력·kv 값·노드명 |
| 캡션·메타 | **12** | 400~600 | 120~140% | weak/faint | 라벨·시각·배지(pill/ftag/kindchip)·th·mono |
| 디스플레이 숫자 | **32** | 600 | 120% | strong (상태색) | stat 값 — tabular-nums |

(2026-07-05 오너 피드백: 20/16 제목 대비가 본문 14와 충분히 안 벌어짐 → 24/20으로 한 단씩 승격.
16은 다이얼로그 제목 전용으로 강등.)

규칙:

- **크기는 표준 세트 {12, 14, 16, 20, 24, 32}에서만** — 12.5·13·10.5 같은 값 자체를 금지.
- **라벨 문구는 한 언어로** — "실패 (FAILED)" 같은 한·영 병기 금지. 상태 배지가 표시하는
  enum 원문(FAILED 등)은 데이터 값이라 예외.
- **12 미만 금지** — 작아 보이게 하려면 크기 대신 무게↓·색 약화·대문자+자간으로.
- **인접 계층은 레버 2개 이상 차이** (크기·무게·색 중) — 1px 차이는 계층이 아니라 오차.
- 행간은 **2단만**: 한 줄 성격(제목·라벨·숫자) 120%, 읽는 글(본문·멀티라인) 140%.
- 숫자는 항상 `tabular-nums`.
- 무게 4단(400/500/600/700) 정리는 후속 백로그 — 500의 용처 통폐합 검토.

## 2. 간격 스케일 — 가까운 것은 붙이고, 먼 것은 떼라

간격 세트: **4 / 8 / 12 / 16 / 24 / 64**. 소속은 거리로 읽힌다:

> **섹션 간 여백(64) ≫ 섹션 안 블록 간(12~16) > 요소 간(4~8)** — 3계층 거리 체계

| 자리 | 값 | 근거 |
|---|---|---|
| 요소↔요소 (아이콘↔텍스트 등) | 8 | 오너 가이드 "요소 간 8" |
| stat 라벨↔디스플레이 숫자 | 12 | 32px 숫자는 캡션과 한 단 더 띄워야 답답하지 않음 (2026-07-05 오너) |
| 섹션 제목↔내용 | 12 (+desc는 제목과 4) | 제목은 내용에 소속 — 아래로 붙는다 |
| **나란한 카드·그리드 gap** | **12** | 같은 행 = 가장 가까운 형제 |
| **같은 섹션 안 위아래 블록** | **16** | 나란함(12)보다 멀고 섹션(64)보다 가깝게 — 12/16 혼용 정리 (2026-07-05) |
| 페이지 제목 아래 | 24 (+첫 섹션 제목 mt 0) | 페이지 제목↔첫 섹션은 섹션 간 관계가 아님 |
| 카드 내부 패딩 | 상 20 · 좌우 24 · 하 24 | 오너 가이드 카드 여백 그대로 |
| **섹션↔섹션(덩어리)** | **64** | 계층 분리의 주 레버 — 40도 부족(2026-07-05 오너: "현황과 목록이 더 떨어졌으면"). 여백 7원칙 ①: 넓게 시작해 좁힌다 |

- 섹션 제목에 설명문을 같은 줄에 붙이지 않는다 — 제목은 제목만.
  부연은 캡션(12)으로 해당 요소에 붙이거나 `title` 툴팁으로.

## 3. 박스 폭 — 내용이 정하지, 화면이 정하지 않는다

- 숫자 하나+라벨인 stat 카드가 `1fr`로 화면을 채우면 4.5:1 납작 카드가 된다 (실측 400×89).
- stat 카드 폭 상한 **260px** (`repeat(3,minmax(0,260px))`, 좌측 정렬, 남는 공간은 비움)
  → 260×109, 비율 2.4:1. 카드는 콘텐츠 크기다.
- 테이블·흐름 같은 "행 스캔" 콘텐츠만 가로를 채운다.
- 표면 문법: **회색 타일(--gray-100·그림자 없음) = 읽기 전용 요약**(stat),
  **흰 카드+그림자 = 콘텐츠·상호작용 표면**(목록·상세). 표면 색이 곧 "만질 수 있는가"의 신호.

## 4. 컨트롤 — 위치는 지배 범위와 일치시킨다

- **컨트롤은 자기가 지배하는 데이터 옆에 산다.** 지배 범위가 페이지 전체면 페이지 헤더에,
  한 블록이면 그 블록에.
- 사례(기간 seg — 3차 최종, 2026-07-05 오너+벤치마크 리서치): 대시보드 성격을
  **전역 기간 조회형**으로 확정 — GA4·Grafana형 "상위 하나의 시간 컨트롤이 화면 전체를 지배".
  기간 seg는 페이지 헤더 우측 + "기간 · 대시보드 전체 적용" 스코프 라벨. 현황(실패·성공)과
  목록이 같은 기간을 보고, **동기화 안 되는 요소는 스스로 밝힌다**(동작 중 카드 = "· 현재").
  섹션마다 `.section-desc` 캡션으로 스코프·건수·정렬을 상시 텍스트 표기(필터 상태 가시성).
  비시간 필터(검색·상태·CSP)는 목록 로컬 필터바 유지 — 전역 시간과 차원 필터는 분리.
  ⚠️ 이 결정은 두 번 뒤집혔다(전역→분리→전역). 원인은 1단계(유즈케이스) 부재였음 —
  재논의가 필요하면 usecases.md부터 고친다.
- 높이: 데스크톱 밀도형이라 현행 3단 유지 — ctl 32 / ctl-sm 28 / chip 20
  (design-system §1). 오너 가이드의 52~36 세트는 모바일 터치 기준이라 비적용;
  "select·input = 버튼과 동일 높이" 규칙은 이미 준수.
