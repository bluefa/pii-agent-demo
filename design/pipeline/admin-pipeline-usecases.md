## 0. 이 문서가 답을 정하는 방식

화면의 모든 결정(무엇을 보여줄지, 어디에 둘지, 얼마나 크게)은
**"어떤 태스크가, 얼마나 자주, 얼마나 급하게 그것을 필요로 하나"**로 판정한다.
- 빈도 높고 급함 → 즉시 보임 (T1)
- 빈도 높고 안 급함 → 스캔 가능 (T2~T3)
- 드묾 → 클릭 뒤 (T4) 또는 제외 (X)

## 1. 액터

**파이프라인 운영자** 1종 — PII 수집 인프라의 설치/삭제 파이프라인을 관리하는 내부 관리자.

- 도메인 지식: CSP(AWS/Azure/GCP/IDC)·테라폼 개념을 안다. 백엔드 내부 구조(테이블·상태 기계 세부)는 모른다.
- 권한: 파이프라인 생성·취소. (서비스 자체의 권한 관리는 이 화면 범위 밖)
- 환경: 데스크톱, 사내망. 모바일 비대상.
- ❓추정: 동시 사용자 수 명 이내, 전담이 아니라 겸무(항상 띄워놓는 화면이 아님).

## 2. 진입 트리거 — 운영자는 왜 이 화면을 여나

| # | 트리거 | 시작 위치 | 빈도(추정) | 긴급도 |
|---|---|---|---|---|
| T1 | **장애 대응** — 실패 알림·문의를 받고 원인 확인 | 대시보드 → 파이프라인 상세 | 주 수회 | **높음** |
| T2 | **작업 수행** — 특정 서비스/대상에 설치·삭제 실행 | 서비스·대상 검색 → target | 주 수회 | 중간 |
| T3 | **진행 확인** — 걸어둔 작업이 끝났는지 확인 | 대시보드 or 상세 재방문 | 일 수회 (작업 있는 날) | 낮음 |
| T4 | **정기 순찰** — 전반 상태 훑기 | 대시보드 | 일 1회 미만 | 낮음 |

❓확인 필요: T1의 "알림"이 실제로 존재하나(Slack/메일/없음)? 없다면 T1의 시작도
대시보드 순찰이 되고, 실패 가시성의 무게가 지금보다 더 커진다.

## 3. 페이지별 태스크

### 3.1 대시보드 `#/dashboard`

| 태스크 | 트리거 | 성공 조건 | 현 UI 지원 |
|---|---|---|---|
| 실패 건 존재 인지 → 상세 진입 | T1·T4 | 진입 3초 내 실패 유무 인지, 1클릭 진입 | ✅ 실패 카드(유일 강조색) + FAILED 우선 정렬 |
| 동작 중 작업과 진행률 확인 | T3 | RUNNING 건수·각 건 N/M 확인 | ✅ 동작중 카드 + 목록 진행 열 |
| 특정 파이프라인 찾기 | T3 | target/상태/Provider/기간으로 좁혀 발견 | ✅ 필터바(Round 9에서 기간 포함) |
| 전반 처리량 감 잡기 | T4 | 최근 24h 성공/실패 확인 | ✅ 고정 24h 카드 |

| (드묾) 서비스 권한 보유자 확인 | ? | — | 🟡 IA §2에서 제외 후보 — **태스크 자체가 존재하나? 오너 확인** |

### 3.3 Target 상세 `#/target/:id`

| 태스크 | 트리거 | 성공 조건 | 현 UI 지원 |
|---|---|---|---|
| 설치/삭제 실행 (모달 → 생성) | T2 | recipe 미리보기 확인 후 실행, 실행 중이면 차단 | ✅ 버튼 매트릭스 + preview 모달 |

### 3.4 파이프라인 상세 `#/pipeline/:id`

| 태스크 | 트리거 | 성공 조건 | 현 UI 지원 |
|---|---|---|---|
| **실패 원인 파악** | T1 | 어느 task가, 어떤 에러로 죽었는지 30초 내 특정 (FAILED task 자동 선택, error_code·raw response) | ✅ 상태 바 + FAILED 자동 선택 + 사이드 패널 |
| 실패 후 다음 행동 결정 | T1 | 재시도 가능? 누구에게 문의? | 🔴 **gap — §4** |

## 4. 태스크가 아직 답 못 받는 것 (gap — 우선순위 결정 필요)

1. **알림→상세 딥링크**: T1의 시작이 알림이라면 알림에 `#/pipeline/:id` 링크가 있어야
   한다. 알림 채널 존재 여부부터 확인 (→ §2 ❓).
2. **실패 후 행동 부재**: 파이프라인 재시도 API는 없다(ADR-016 — 새로 생성이 원칙).
   상세 페이지 FAILED 상태에 "이 대상으로 새 파이프라인 생성" 경로 또는 안내가 없다.
3. **권한 사용자 목록**: 지원하는 태스크가 확인되지 않음 — 태스크가 없으면 IA §2대로 제외.
4. **D1 연동 전제**: 실데이터 연결 시 목록이 수백 건이 되면 "최근 24h" 창과 페이지네이션
   기본값(5행)의 적정성 재검토 필요. (LIN-19 CORS 미해결이 선행 차단 요소)
