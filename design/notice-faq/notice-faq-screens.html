대부분 보안 그룹 또는 방화벽에서 Pass 스캔 대역이 열리지 않은 경우입니다. 아래 순서로 확인해 주세요.

  • 대상 DB의 인바운드 규칙에 스캔 대역이 포함되어 있는지
  • 계정에 SELECT 권한이 부여되어 있는지
  • 포트가 기본값과 다른 경우 등록 정보에 반영되어 있는지

IDC는 클라우드와 달리 역할(Role) 위임이 없으므로, 스캔 전용 계정을 직접 발급해 등록해야 합니다. 읽기 권한만 있으면 되고 쓰기 권한은 필요 없습니다.

스캔 대상 테이블 수가 아니라 실제 읽은 데이터량 기준으로 산정됩니다. 연동 제외 DB를 지정하면 그만큼 줄어듭니다.

관리자 승인까지 보통 1영업일, 승인 이후 인프라 작업과 첫 스캔에 2~3시간이 걸립니다. 진행 상황은 서비스 목록에서 확인할 수 있습니다.

1 Pass 소개 배너 — 고정 콘텐츠. 별도 API 없이 프론트가 소유합니다. Admin 편집이 필요해지면 기존 Admin Guides Tag 재사용을 먼저 검토합니다.
2 공지사항 카드 — 자기 유형만 담은 독립 목록입니다. GET /install/v1/posts?type=NOTICE
3 펼친 본문 — 펼치는 시점에 단건 조회로 가져옵니다. 목록 응답에는 본문이 없습니다. 받는 동안 스켈레톤을 두고, 한 번 받은 본문은 다시 펴도 재요청하지 않습니다. GET /install/v1/posts/{postId}
4 FAQ 카드 — 같은 엔드포인트에 type만 다릅니다. GET /install/v1/posts?type=FAQ
· 행 하나가 담는 것 — 왼쪽에 Category 배지와 Title, 오른쪽 끝에 게시일자(위)와 펼침 표시(아래). 본문은 펼쳤을 때 나옵니다.

두 카드가 각자 정렬됩니다 — 카드별 정렬 검증 케이스입니다

고정 글은 자기 카드 안에서만 위로 갑니다. 두 카드 사이에는 순서 관계가 없습니다. 왼쪽 공지사항 카드에서 3번째 08-11이 2번째 고정 글 08-10보다 최신인데도 아래에 있고, 오른쪽 FAQ 카드에서도 2번째 08-11이 고정 글 08-08 아래입니다. 구현 후 이 순서가 나오지 않으면 정렬이 잘못된 것입니다.

카드가 나뉘어도 BFF 계약은 그대로입니다. 단일 posts 리소스에 type만 붙이면 되므로, 통합 목록이든 분리 카드든 엔드포인트를 새로 만들 일이 없습니다.

Admin을 사용자 화면과 같은 카드 구조로 맞췄습니다

이전 안은 표 하나에 유형·Category·숨김 필터를 얹고 Category를 옆 패널로 뺀 형태였습니다. 사용자 화면은 카드 두 장인데 Admin만 표라서, 같은 데이터를 두 가지 방식으로 읽어야 했습니다. 지금은 공지사항(좌) · FAQ(우)로 같은 구조를 쓰고, 유형 필터가 카드 분리로 대체됩니다. 행 레이아웃도 동일합니다 — 왼쪽에 배지와 Title, 오른쪽 끝에 게시일자(위)와 작업 버튼(아래).

Category는 모달로 뺐습니다. 항상 펼쳐진 옆 패널은 자리를 계속 차지하는데, Category 추가·삭제는 게시글 관리보다 훨씬 드물게 하는 일입니다.

숨김은 삭제가 아니라 되돌릴 수 있는 상태이므로, 마지막 행은 회색으로 죽이는 대신 빗금 배경 + 숨김 배지 + 숨김 해제 버튼으로 표시했습니다. 같은 이유로 숨김 행에는 상단 고정이 없습니다 — 사용자에게 보이지 않는 글을 상단에 고정하는 동작은 의미가 없습니다.

툴바에 없는 것이 곧 계약입니다

글꼴·색·크기 버튼이 없습니다. allow-list에 style과 class 속성이 없어서, 있어도 저장 단계에서 거부됩니다. "관리자는 폰트 스타일을 수정할 수 없다"는 요구사항이 UI 제약이 아니라 계약 제약으로 지켜집니다.

이미지에도 정렬·크기 핸들이 없습니다. 선택하면 나오는 것은 위치를 옮기는 핸들뿐입니다. 표시 폭은 CSS가 정하고, width/height는 업로드 응답이 준 원본 픽셀 크기를 그대로 기록한 값입니다 — 펼칠 때 이미지가 늦게 떠서 본문이 밀리는 것을 막습니다.

캡션(figcaption)도 allow-list에 없습니다. 이미지 설명이 필요하면 이미지 아래 문단으로 씁니다.
