Design Benchmark · 004

레일은 카드가 아니다

/pass/notices?type=NOTICE 의 Category 레일을 다시 만든다. 지금은 회색 상자가 카드 안에 얹혀 있고, 스크롤이 없고, 항목 수만큼만 자란다. 잘 만든 레일 13곳을 재서 그 셋을 어떻게 해결했는지 본다.

2026-08-13 대상 · NoticeBoardView / postStyles.catNav 레퍼런스 13 · 실측 4 시안 5
01

지금 무엇이 잘못됐나

브라우저에서 직접 잰 값이다(뷰포트 1710 × 947). 앞의 셋은 사용자가 지적한 것이고, 나머지는 재면서 같이 나온 것이다.

#문제측정값과 근거등급
1 레일이 카드로 읽힌다 회색 면(#F3F4F6)이 254px 에서 끝난다. 카드 바닥까지 가지 않으니 구조물이 아니라 카드 안에 놓인 또 하나의 상자다. 아래 흰 바닥과 선택 항목의 흰 알약이 같은 색이라 레일이 짧을수록 둘이 붙어 보인다. UX 원칙
2 스크롤이 없다 overflow-y: visible. Category 가 20 개가 되면 레일이 800px 로 자라 목록을 아래로 밀어낸다. 계약에 Category 상한이 없다. 구조 결함
3 화면을 안 쓴다 마스터-디테일 영역이 256px — 뷰포트 947px 의 27%. 아래 508px 이 죽은 캔버스다. UX 원칙
4 항목 높이가 그리드 밖 py-[9px] → 항목 39px. 4의 배수가 아니다. 벤치마크는 전부 32 나 36. 수치 위반
5 폭이 좁다 224px. 잰 것 중 가장 좁은 GitHub 필터 목록이 239, 앱 사이드바는 256~320. 제안
6 레일에 머리가 없다 "Category" 라는 말이 화면에 없다 — aria-label 안에만 있다. 첫 항목 "전체" 가 그룹 이름 없이 목록을 시작한다. UX 원칙
7 건수가 계층을 못 만든다 건수와 이름이 같은 색(#4E5968). 크기만 12 대 14 라 스캔할 때 한 덩어리로 읽힌다. 제안
회색 면 자체는 유죄가 아니다. 같은 앱의 InstallStatusDetail 레일이 이미 224px · 가라앉은 회색 · 흰 알약 선택 표시를 쓰고, 이건 오너가 한 번 고쳐 준 결과다. 문제는 색이 아니라 그 면이 어디서 끝나는가 다. 바닥까지 가면 구조물, 중간에 끊기면 상자.

A 위에 shadcn 의 3부 구조를 얹는다. 머리에 "Category" 와 총건수를 박아 두면 스크롤해도 지금 뭘 고르는 중인지 가 사라지지 않는다(진단 6). GitHub 사이드바가 머리를 고정하고 몸통만 흐르게 한 이유가 이거다.

발(Footer) 은 채택하지 않는다. 지금 거기 놓을 액션이 "선택 해제" 하나뿐인데, 그건 레일 첫 항목 "전체" 가 이미 하는 일이다. 같은 일을 하는 두 번째 컨트롤은 계층이 아니라 중복이다.

추천 — E (= A + 머리), 발은 뺀다

A 가 사용자가 말한 셋을 계약 변경 없이, 기존 합의를 하나도 안 건드리고 덮는 유일한 안이고, E 의 머리는 그 위에 요소 하나를 더해 진단 6 까지 가져간다. B 와 C 는 덮는 범위가 같거나 하나 많은데 각각 오너가 이미 내린 결정(테두리 하나로 묶기)과 셸 자리의 의미를 건드린다 — 같은 값을 더 비싸게 산다. D 는 반대 방향이라 단독 채택은 안 되지만, A 를 넣고도 회색이 무거우면 그때 면만 바꾸면 되는 독립 손잡이로 남긴다.

같이 고칠 잔돈. 항목 py-[9px]→py-1.5 로 39→32 (레퍼런스 02 의 실측값), 폭 224→240, 선택 항목에 aria-current="page"(레퍼런스 06), 건수 색을 한 칸 낮춰 이름과 갈라 주기(진단 7). 폭은 256 이 벤치마크 중앙값이지만, 우리 레일은 앱 내비가 아니라 한 화면 안의 필터라 가장 가까운 역할인 GitHub 필터 목록(239)에 맞춘다.
05

답하지 않은 것

  • 고정 높이와 지난주 결정의 관계. 며칠 전 이 화면의 2카드 뷰에서 min-h 대신 고정 높이를 쓰면 내용이 잘린다고 적었다. A 는 고정 높이를 쓰지만 안쪽에 스크롤을 걸어서 자르지 않는다 — 두 결정은 충돌하지 않는다. 다만 같은 파일에 반대로 보이는 주석이 두 개 남으므로 A 를 넣을 때 그 주석을 함께 손봐야 한다.
  • Category 0 건 처리. 레퍼런스 12 는 결과가 없는 필터를 빼라고 하지만, 지금 레일은 받아 온 목록에서 세기 때문에 0 건 Category 는 애초에 나타나지 않는다. Admin 이 만든 빈 Category 를 보여줄지는 계약(PostCategory)을 봐야 정해진다.
  • Material 3 와 Fluent 는 못 읽었다. 두 문서 모두 본문이 JS 로 그려져서 수치를 확인하지 못했고, 기억으로 채우지 않았다. 그래서 레퍼런스가 13곳이지 15곳이 아니다.
  • 모바일. 이 앱은 데스크톱 전용이라 GitLab 의 1200px 오버레이 전환은 가져오지 않았다.
