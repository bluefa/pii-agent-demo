왜 게시판으로 읽히나

브라우저에서 잰 현재 값이다. "게시판 같다"는 인상은 취향이 아니라 요소 배치가 실제로 표(table)의 배치이기 때문에 생긴다.

#문제측정값과 레퍼런스 대조등급
1제목이 본문 크기 제목 14px. Linear 실측은 항목 제목 24~32px, 본문 17px. 12곳 중 제목이 14px 인 곳은 없다. 제목이 본문과 같은 크기면 목록이 아니라 표로 읽힌다. UX 원칙
2읽기 폭이 없다 행 폭 1630px. Linear 본문 컬럼 실측 624px. 제목은 왼쪽 끝, 날짜는 1400px 건너편이라 눈이 좌우로 왕복한다 — 이게 표를 읽는 동작이다. UX 원칙
3배지가 그룹을 반복 "서비스 점검" 그룹 안 모든 행에 "서비스 점검" 배지가 붙는다. 같은 사실을 두 번 말하면서 자리를 두 번 쓴다. 중복
4읽을 것이 없다 행에 제목뿐. 12곳 중 9곳이 한 줄 요약을 준다(GitHub·Vercel·Shopify·Sentry·Notion…). 요약이 없으면 목록은 "펼쳐 봐야 아는 제목 모음"이 된다. UX 원칙
5날짜가 기계 포맷 26-08-10. 12곳 전부 사람 포맷("August 11", "12 Aug"). yy-mm-dd 는 로그 포맷이지 읽는 포맷이 아니다. 제안
6변화의 종류를 말 안 함 Shopify 는 New · Improvement · Changed · Removed, GitHub 는 Release · Improvement · Retired 를 배지로 낸다. 우리는 Category(주제)만 있고 "무슨 종류의 소식인가" 축이 없다. 제안
7시간축이 사라짐 Category 로만 묶는다. 12곳 중 6곳이 월·날짜로 묶는다(GitHub·Sentry·Vercel·Notion·Slack·Raycast). 공지는 본래 연대순 매체인데 우리 목록에는 시간 구조가 없다. UX 원칙
8FAQ와 공지가 같은 옷 질문과 발표는 다른 물건인데 행 디자인이 같다. 레퍼런스에서도 changelog(9곳)와 help center(2곳)는 레이아웃이 완전히 다르다. UX 원칙
9고정과 분류가 같은 무게 "고정"과 "서비스 점검"이 둘 다 12px 알약. 고정은 순서를 바꾸는 사실, Category 는 분류 — 다른 층인데 같아 보인다. 제안
10긴 글도 아코디언 글당 이미지 10장·10MB 를 허용해 놓고 인라인으로 편다. Figma 는 도움말을 인라인 확장하지 않고 페이지로 보낸다. 이전 벤치마크에서 미해결로 남긴 항목이다. UX 원칙

이미지 10장·10MB 짜리 글을 목록 안에서 펼치면 다른 글이 전부 화면 밖으로 밀린다. Sentry 와 Figma 는 둘 다 목록에서 펼치지 않고 보낸다.

문제는 임계값을 목록 시점에 알 수 없다는 것이다. PostSummary 에 본문이 없으니 길이도 이미지 수도 모른다 — 열어 봐야 안다. 전부 페이지로 보내면 계약 없이 가능하지만, 아코디언은 합의된 설계(tag guide §5, 본문 지연 로딩)라 이 안은 그 결정을 되돌리는 제안이다. 이전 벤치마크에서도 같은 이유로 미결로 남겼다.
