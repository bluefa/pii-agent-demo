> 작성 2026-08-08 · 근거 화면 `/pass/target-sources/1006` (AWS Step 1) · 브랜치 `feat/ec2-instance-add`
> 상위 권위: `.claude/skills/design-guide/SKILL.md` · [`typography-and-spacing.md`](typography-and-spacing.md)
> 토큰: `lib/theme.ts` 의 `ec2Styles` · `modalStyles.toss` — 값의 근거는 그쪽 JSDoc에 있다.

## 0. 무엇을 만들었나

스캔이 찾지 못하는 대상이 있다. EC2 위에 직접 설치해 쓰는 DB는 AWS API로는 보이지 않으므로,
사용자가 Instance ID로 찾아 접속 정보를 직접 적어 연동 대상에 넣어야 한다. IDC의 수동 추가와
같은 흐름이지만, 여기서는 **스캔이 이미 확인한 값(Private IP)** 이 있다는 점이 다르다.

흐름은 두 단계 모달이다.

```
[EC2 추가] → ① 검색 모달 (Instance ID 접두 검색, 최대 5건)
           → ② 접속 정보 설정 (접속 주소 · Database Type · Port · Oracle SID)
           → 표 맨 위에 행으로 착지
```

`GET …/ec2-resources/search` 는 오너 제공 계약이지만 `docs/swagger/install-v1.yaml` 에 아직
없다 — 승인된 계약 갭이므로 `lib/bff/mock/aws.ts` 로 mock-first 했고, 라우트는 로컬 loose
zod 스키마를 들고 있다. swagger가 들어오면 그 스키마를 지운다.

## 1. 모달 크롬 — 콘텐츠가 아니라 틀이 고정이다

| | before | after | 무엇을 고쳤나 |
|---|---|---|---|
| 크기 | 내용 높이만큼 | 두 단계 모두 `h-[452px]` 고정 | 검색 결과 0~5건, SID 필드 유무로 모달이 커졌다 작아졌다 했다. 같은 자리의 버튼이 매번 다른 좌표에 서서 화면이 흔들렸다 |
| 우상단 ✕ | 있음 | 없음 | 푸터에 `닫기` 가 이미 있다. 같은 동작을 두 자리에 두면 어느 쪽이 취소인지 물어보게 된다 |
| 푸터 구분선 | 있음 | 없음 | 본문이 스크롤하지 않으면 그 선은 "여기서 내용이 끝난다"를 표시하지 않는다. 그냥 선이다 |
| 제목→부제 | 16px (`subtitle`) | 12px (`subtitleTight`) | 부제가 모달의 주제를 *설명*하는 게 아니라 *이름 부르는* 한 줄일 때는 제목에 더 붙어야 한 덩어리로 읽힌다 |
| 부제→첫 컨트롤 | 28px | 20px | 본문 기본 `pt-7` 이 헤더 여백과 합쳐져 벌어져 있었다. `stepFrame` 의 `-mt-3.5` 로 당겼다 |

고정 높이에는 함정이 하나 있다. `overflow-y-auto` 는 세로만 자르지 않는다 — CSS 상 한 축이
`visible` 이 아니면 다른 축도 `auto` 가 되어 **가로도 클립된다**. 입력창의 focus 테두리가
좌우로 잘려 나갔다. 본문 좌우 40px 안쪽으로 8px을 빌려(`-mx-2 px-2`) 링이 설 자리를 만들었다.

헤더/본문 패딩은 toss 크롬 그대로다: 헤더 `px-10 pt-9`(위 36 / 좌우 40), 본문 `px-10 pt-7 pb-2`.

## 2. 검색 — 값을 담는 칸이 아니라 여는 입구

| | before | after | 무엇을 고쳤나 |
|---|---|---|---|
| 형식 안내 | 입력창 아래 helper 한 줄 | placeholder 안쪽 (`i-0a1b2c3d4e5f67890 형식의…`) | 형식은 입력하기 *전에* 필요한 정보다. 아래에 있으면 이미 늦다 |
| 면 | 폼 필드와 같은 회색(#F7F8FA) | 흰 면 + 실선 테두리 | 다른 입력과 같은 회색이면 "채워야 할 칸"으로 읽힌다. 검색은 채우는 칸이 아니다 |
| 활성 표시 | `focus:ring-4` + 테두리 | 테두리 색 하나 (`focus:border-[#0064FF]`) | 굵기가 다른 파란 선 두 줄이 겹쳐 보였다 |
| 아이콘 | 15px | 19px | 52px 필드 안에서 15px 글리프는 장식으로 읽힌다 |
| 지우기 | 없음 | 값이 있을 때만 원형 ✕ | 질의와 결과를 함께 비운다 |
| 개수 상한 | 없음 | 검색바 바로 아래 "최대 5건 표시" | 6번째가 없는 게 아니라 안 보여주는 것이라는 사실을 결과 *앞에서* 말해야 한다 |
| 검색어 길이 | 무제한 | 50자 (input `maxLength` + 라우트 `slice`) | 접두 검색이므로 Instance ID 19자를 넘는 입력은 검색이 아니다 |

`focus:outline-none` 이 듣지 않는 문제가 있었다. `globals.css` 의 `*:focus-visible` 은
**레이어 밖**이고 Tailwind 유틸리티는 `@layer utilities` 안이라, 특이도와 무관하게 레이어 밖이
이긴다. 같은 레이어 밖 문맥에 `.ec2-search-field:focus-visible { outline: none }` 을 두어 풀었다.

**빈/대기 상태도 같은 면적을 쓴다.** 결과 목록이 차지하는 자리를 `h-full` 로 끝까지 채워,
결과가 오가도 모달 안이 뛰지 않는다. 로딩 휠은 스캔 화면의 것을 그대로 쓴다(32px) — 같은
"기다리는 중"에 다른 그림을 그릴 이유가 없다.

## 3. 설정 폼 — 잠긴 값은 입력이 아니라 표기다

Private IP는 스캔이 확인한 값이라 고칠 수 없다. 처음엔 그 사실을 카드로 감쌌다.

| before | after |
|---|---|
| 회색 카드 안에 `수정 불가` + 설명 두 줄 | **`수정 불가`** 를 12px bold #191F28 로 세우고, 이유는 그 아래 12px #6B7280 보조 텍스트 |

카드는 "여기 별개의 무언가가 있다"는 신호다. 여기 있는 건 별개의 무언가가 아니라 바로 위
필드에 대한 단서다. 강한 계층 하나 + 보조 텍스트 하나면 충분하고, 카드는 오히려 필드와
설명 사이를 갈라놓았다.

- **종속 필드는 원인 옆에 나타난다.** Oracle을 고르면 SID 입력이 그 자리에서 등장하고,
  보라 링(`revealedField`)이 잠깐 남는다 — 내가 한 선택 때문에 생긴 칸임을 잇는 표시다.
- **셀렉트 화살표는 20px.** OS 기본 화살표는 크기를 지정할 수 없어 11~13px로 그려지고,
  52px 필드 안에서는 눌러서 여는 컨트롤로 읽히지 않는다. 기본을 끄고 직접 세웠다.
- **입력 상한은 두 곳에서 자른다.** SID 100자, 질의 50자 — 필드의 `maxLength` 는 타이핑
  보조일 뿐이고 라우트는 그것 없이도 도달 가능하다.

## 4. 표 진입 — 어디로 들어갔는지가 보여야 한다

| | before | after | 무엇을 고쳤나 |
|---|---|---|---|
| 진입 버튼 | 표 위 독립 영역 | 툴바 안, 필터 왼쪽 · 작은 크기 | 버튼이 조작할 대상(표)에서 멀수록 무엇에 대한 버튼인지 흐려진다 |
| 착지 위치 | 목록 순서대로 | 맨 위 (최신 우선) | 방금 넣은 것을 찾으러 스크롤하게 만들면 안 된다 |
| 종류 표기 | 이름 옆 | **이름 위** (`EC2` 태그) | 이 열이 행의 정체성을 여는 자리다. "무엇인가"를 먼저 말하고 이름이 뒤따른다. RDS Cluster와 같은 문법 |
| 태그 색 | — | 연보라 `#F3EEFF` / `#6D28D9` (`tagStyles.resourceKind`) | 리소스 *종류* 는 상태도 경고도 아니다. RDS Cluster 태그도 같은 색으로 통일 |
| 설치 구분 | 중립 | 앰버 (`설치 선택`) | 설치가 필요한 대상은 승인 이후 할 일이 따로 있다 |
| 행 조작 | Port 열 노출 | hover 시 32px 수정/삭제 아이콘 → 설정 모달 | Step 1의 다른 행은 Port를 보여주지 않는다. EC2만 열을 더 만들면 표가 EC2 때문에 넓어진다 |
| 리드 문단 | 스캔 설명만 | EC2 문장 한 줄 추가 | 처음 온 사람이 "스캔에 없는 DB는 어떻게 하나"를 물을 자리가 없었다 |

## 5. 방금 추가 — 모션과 글자, 두 층

대안 5개를 놓고 고른 안이다. **모션 하나만으로는 부족하다** — 모달이 닫히는 순간을 못 본
사람, 모션을 끈 사람에게는 아무 일도 일어나지 않은 화면이 된다.

| 층 | 무엇 | 길이 | 누구를 위한 것 |
|---|---|---|---|
| 모션 | 행을 왼→오로 한 번 훑는 틴트 스윕 | 1.1s | 지금 보고 있는 사람 — 시선을 표 위쪽으로 데려온다 |
| 글자 | `방금 추가` 배지, EC2 태그 오른쪽 | 4s | 늦게 도착한 시선 — 읽어서 같은 사실을 안다 |

- 스윕은 `background-color` 가 아니라 **gradient**다. 행은 선택·hover로 자기 배경을 바꾸므로
  색을 칠하면 애니메이션이 끝나는 순간 그 배경을 덮어버린다. `background-image` 는
  fill-mode 없이 끝나면 흔적 없이 사라진다.
- 평면 페이드였을 때는 리렌더처럼 읽혔다. 한 방향으로 지나가야 "도착했다"로 읽힌다.
- 배지는 처음에 이름 옆이었다. 이름은 200px에서 잘리므로 긴 이름일 때 배지가 말줄임에
  밀렸다 — 폭이 고정인 종류 태그 옆으로 옮겼다.
- `motion-reduce` 에서는 **애니메이션만** 끄고 배지는 그대로 선다. 움직임을 끈 사용자가
  정보를 잃지 않는다.
- 같은 사실을 `aria-live` sr-only 로도 한 번 알린다.

## 6. 다음 모달이 물려받을 계층

여기까지가 이 화면의 기록이고, 아래는 **다른 화면에도 그대로 적용할 규칙**이다.

1. **틀은 콘텐츠와 무관하게 고정한다.** 결과 수·조건부 필드로 모달이 커졌다 작아지면
   같은 버튼이 매번 다른 좌표에 선다. 가장 큰 상태에 맞춰 잠근다.
2. **고정 높이 + `overflow-y-auto` 는 가로도 자른다.** 링·아웃라인이 잘리므로 좌우로
   8px을 빌려둔다.
3. **닫는 길은 하나.** 푸터에 `닫기` 가 있으면 우상단 ✕은 없앤다.
4. **선은 스크롤 경계를 표시할 때만.** 본문이 안 넘치면 푸터 구분선도 없앤다.
5. **부제가 주제를 부르는 한 줄이면 12px, 설명하면 16px.**
6. **형식 안내는 placeholder 안쪽, 개수/범위 안내는 입력 바로 아래.** 형식은 입력 전에,
   상한은 결과 전에 필요하다.
7. **검색 입력은 폼 필드와 다른 면.** 흰 면 + 실선. 폼과 같은 회색이면 채워야 할 칸으로 읽힌다.
8. **포커스 표시는 한 겹.** 링과 테두리를 겹치지 않는다.
9. **잠긴 값에 카드를 두르지 않는다.** 강한 라벨 + 보조 텍스트. 카드는 "별개의 무언가"라는
   신호이고, 필드에 대한 단서는 별개가 아니다.
10. **종속 필드는 원인 옆에 나타나고, 잠깐 표시를 남긴다.**
11. **입력 상한은 UI와 라우트 양쪽에서 자른다.**
12. **종류 태그는 이름 위.** 행의 정체성은 "무엇인가"가 먼저다.
13. **성공 피드백은 모션 + 글자 두 층.** 모션은 1초 남짓, 글자는 몇 초 더.
    `motion-reduce` 에서 글자 층이 살아남아야 한다.
14. **네이티브 셀렉트 화살표는 끄고 20px로 직접 세운다.** 큰 필드에서 기본 화살표는
    컨트롤로 읽히지 않는다.

### 토큰 다룰 때

- `cn()` 은 **단순 join** 이다. 같은 속성을 두 번 쓰면 클래스 순서가 아니라 Tailwind가 CSS에
  찍는 순서로 승부가 난다. 겹쳐 쓰지 말고 `mt` 만 다른 **완전한 문자열**을 하나 더 만든다
  (`subtitle` / `subtitleTight` 가 그 예다).
- `globals.css` 의 레이어 밖 규칙은 Tailwind 유틸리티를 특이도와 무관하게 이긴다. 유틸리티로
  못 이기면 같은 레이어 밖 문맥에 예외를 둔다.
