prop·모달 파일을 한꺼번에 지웠다. 표현을 정리했으면 남았을 것들이다.

## 2. Source IP — 별도 열 → 한 셀 병합 → **다시 별도 열(NLB 옆)**

시도한 5안 중 A안(NLB 셀이 Source IP 흡수)을 구현했다가 되돌렸다.

| 단계 | 결과 |
|---|---|
| Before: `연동 대상 · DB · Port · **Source IP** · 여부 · NLB 배정 · …` | 원인(NLB)과 결과(IP)가 88px짜리 열을 사이에 두고 떨어져 있음 |
| A안: NLB 셀에 `NLB #3` 위 / source IP 아래 세로 스택 | 열 −160px. 그러나 **성격이 다른 두 값이 한 열에 겹쳐 어느 쪽도 세로로 훑을 수 없음** |
| After: 열은 유지하되 **NLB 배정 바로 오른쪽**으로 이동 | 인접해서 인과가 읽히고, 각 열의 세로 스캔은 살아 있음 |

**교훈: 인접이 병합보다 싸다.** 두 값이 관련 있다는 사실은 "같은 셀"이 아니라
"옆 열"로 충분히 말할 수 있고, 열을 합치면 스캔성이라는 표의 본질을 판다.

**또 하나 — 병합은 값까지 바꾸면 안 된다.** A안 목업에는 NLB 테이블의 `nlbIpList`를
그렸지만, 구현은 행의 `idc_source_ips`를 옮기기만 했다. 계약이 선언하지 않은 조인을
UI가 발명하면 안 된다. (반대로 `ServiceAssignmentModal`의 `NLB IP` 열은 "NLB #3의 IP는
무엇인가"를 NLB 테이블 자신에게 묻는 것이라 정당한 조인이다.)

> ⚠️ 미해결: 행의 `idc_source_ips`가 그 행의 `nlb_index` 파생값인지, 서비스별 배정
> 전체의 합집합인지 확인 안 됨. 목 데이터는 두 값이 다른 대역(10.20.9.x vs 10.30.0.x)이다.

## 3. 열 이름 — `연동 대상` → `접속 주소` (IDC 6개 화면)

`연동 대상`은 제품 전체에서 **행**을 가리킨다 (`연동 대상 DB 선택`, `연동 대상 승인 대기`,
`전체 연동 대상`, `연동 대상 논리 DB`). 그 말을 주소 열에도 쓰니 한 표 안에서
`연동 대상`(주소)과 `요청 대상 여부`(판정)가 같은 단어를 두 뜻으로 썼다.

Port를 별도 열로 분리한 뒤 이 셀에 남은 건 정확히 주소 하나 → **`접속 주소`**.

적용: Step 1 표 / 자격증명 모달 / 완료 승인 모달 / 대상 목록 표 / 방화벽 모달 / admin P3.
복사 버튼 라벨(`접속 주소 복사`)과 툴팁도 함께.

**행을 뜻하는 자리는 안 건드렸다** — `표시할 연동 대상이 없습니다`, `전체 연동 대상` 타일,
`연동 대상 추가/수정`, 클라우드 표의 판정 열.

**교훈: 같은 단어가 행과 셀을 동시에 가리키면 둘 중 하나는 틀린 이름이다.**

## 5. 섹션 — 카드 제거, 스택이 스스로 테두리를 그림

`연동 대상 리소스 · NLB 배정` → **`연동 요청 조회`** (프로바이더 분기 제거) + 보조 설명.

`<Card>` 래퍼를 걷었다. 타일은 이미 각자 카드고 툴바·표·페이저는 자기 프레임을 갖고
있어서, 바깥 카드는 카드 안에 카드를 넣는 일만 했다 (표 가용폭 +48px).

**그런데 카드를 걷자 헤더 띠가 사라졌다.** 툴바 배경 `--pl-gray-50`(#F9FAFB)과 페이지
배경 `--pl-bg-page`(#F9FAFB)가 **같은 값**이었다. 흰 카드 위에서만 보이던 띠였던 것.

- 툴바 `gray-50` → `gray-100`, **위·좌·우 테두리 추가**
- 표 영역에 좌우 테두리(`CONNECTED_FRAME`은 Step 1과 공유라 불가 → 섹션이 소유)
- 페이저는 이미 3면 테두리 + 아래 둥근 모서리

**교훈: 이 디자인 시스템은 면을 테두리로 나눈다.** 페이지·카드 tier가 1.05:1이라
휘도만으로는 어떤 면도 경계지을 수 없다. 카드를 걷는다는 건 테두리를 옮긴다는 뜻이다.

## 6. 표 헤더 색 — 3:1을 좇다가 되돌아온 기록

사용자 지적 "헤더가 안 보인다" → 4단계를 내려왔다.

| 값 | 띠 vs 본문 | 헤더 글자 | 판정 |
|---|---|---|---|
| `#F7F8FA`(공용) | 1.06:1 | 6.69:1 | 카드 없으면 안 보임 |
| `#7E8FAE` | **3.27:1** | 5.07:1(근검정 필수) | 너무 강함 — 제목 바처럼 읽힘 |
| `#C9D4E8` | 1.49:1 | 4.76:1 | 여전히 강함 |
| `#E9EEF6` | 1.17:1 | 6.10:1 | 근접 |
| **`--pl-gray-100`(#F2F4F7)** | 1.10:1 | 6.45:1 | **채택** — 위 필터 툴바와 동일 |

`approvalHeaderChrome` 신설(admin P3 전용). 공용 `approvalHeader`는 Step 1·2·3·6이
쓰므로 손대지 않았다.

**교훈: 대비는 면의 경계를 긋는 것이지 순위를 매기는 게 아니다.** 3:1을 만족시키려
할수록 헤더가 자기가 이름 붙이는 행들보다 앞에 나섰다. 열 레이블은 표에서 가장 조용해야
한다. 그리고 회색 두 개가 1.03:1 차이로 다른 건 최악이다 — 눈에 띄기엔 부족하고 실수로
보이기엔 충분하다. 필터와 **같은 값**으로 맞춰 하나의 크롬으로 읽히게 했다.

## 7. 모달 — 조용한 표 + footer 없는 모달의 탈출구

`ServiceAssignmentModal`(신설, 서비스별 NLB 배정 20~30건 → `PAGE_SIZE=10` 페이지네이션).

- **표 문법을 `ScanDetailModal`에서 가져왔다** — 프레임·띠 없이 헤더 아래 선 하나,
  헤더 12/500 weak, 값 12px mono. 한 조회에 답하는 모달인데 테두리 있는 카드 안에
  테두리+띠 있는 표를 넣으니 크롬이 담고 있는 3열보다 커졌다.
- **읽기 전용 모달은 footer를 없앴다.** `TqModal.footer`를 optional로 바꾸고, 없으면
  헤더에 X를 렌더한다 — 규칙은 "footer 아니면 헤더 X, 둘 다 없는 경우는 없음"(`modal-escape`).
- 그 과정에서 `modal.body`가 `pb-0`(아래 여백을 footer가 만듦)인 걸 놓쳐 본문이 r20
  모서리로 파고들었다 → footer 없을 때 body가 `pb-8`을 직접 진다.
- 모달 eyebrow(`연동 요청 · #1031`) 삭제 — 제목이 이미 맥락을 말한다.
  P3 모달 5개에서 `targetSourceId` prop이 고아가 되어 함께 제거.

**교훈: 공용 컴포넌트에 optional을 열 때는 그 값이 지고 있던 레이아웃 책임도 같이 옮긴다.**

## 8. 헤더 계층 — 5단 → 3단

```
Before                                After
주문서비스 #1031        (24, id도 24)  주문서비스 [ORD] #1031   (24 / chip / 14)
[IDC ●] ORD [승인 대기]                주문/결제 원장 Oracle…    (14 weak)
요청 시각  요청자                       Provider  요청 시각  요청자 (12 라벨 / 12 값)
```

- **`승인 대기` pill 삭제** — 우측 `반려`/`승인` 버튼이 이미 미결을 말한다.
- **`ORD` → chip, 제목 옆** — 서비스 코드는 분류가 아니라 이름의 약어다. 프로바이더 같은
  분류 태그와 한 줄에 있을 값이 아니었다.
- **`#1031` 24 → 14px** — 같은 대상의 id지만 24px에서는 두 번째 제목처럼 읽혔다.
- **Provider: 도트 태그 → 메타 쌍** — 요청 시각·요청자와 같은 성격의 사실인데 자기만의
  줄에서 한 칸짜리 층을 만들고 있었다. 브랜드 도트도 제거(라벨이 이미 필드를 말한다).
- **description 신설** — `TargetSourceInfo.description`은 계약에 있었지만
  `toRequestListRow`가 **받아놓고 버리고 있었다**. 발명이 아니라 연결.

## 9. 대비 감사 — 색을 잘못 고른 게 아니라 고른 적이 없었다

| 토큰 | 흰 배경 | 조치 |
|---|---|---|
| `--pl-text-strong` #101828 | 17.75:1 | — |
| `--pl-text-medium` #344054 | 10.46:1 | — |
| `--pl-text-weak` #667085 | 4.97:1 | — |
| `--pl-text-faint` #98A2B3 | **2.58:1** | 텍스트로 쓰던 곳 전부 weak로 |
| `gray-400` #9CA3AF | **2.54:1** | `sidKey` → gray-500(4.83:1) |

고친 것: textarea placeholder(미선언) / CharCount / 검색·필터 placeholder 2곳 /
점유 리스너 `/50` / 모달 닫기 X(아이콘 3:1도 미달) / Oracle `SID` 라벨.

**가장 나쁜 버그는 마지막에 나왔다.** `modal.textarea`가 **입력 텍스트 색을 선언하지
않았다.** Tailwind preflight가 폼 요소에 `color: inherit`을 걸고, `body { color:
var(--foreground) }`인데 `globals.css:196`이 `prefers-color-scheme: dark`에서
`--foreground`를 `#ededed`로 뒤집는다. **OS가 다크 모드면 흰 카드 위 #ededed = 1.07:1.**

**교훈: 라이트 전용 제품에 다크 미디어쿼리가 남아 있으면, 색을 선언하지 않은 모든
요소가 잠재적 버그다.** 앱 전역 정리 필요(별건).

### font size — 짝수 아님, 그리고 그게 맞다

이 화면에 남은 홀수/소수 px: **13 / 12.5 / 11.5 / 11**. 전부 `origin/main` 시점부터
있던 값이고(13px×16, 12.5px×15, 11.5px×5, 11px×10), `lib/theme.ts:658`이 명시한다 —
"⚠️ admin 파이프라인(Figma R24) 화면은 대상이 아니다. 그쪽 홀수·소수 px는 디자이너
램프의 충실 반영이라 이 램프로 덮으면 안 된다." 이번에 **새로 넣은 크기는 전부 짝수**
(14 / 12 / 10)이며, 기존 13px 값을 따라간 2곳(NLB 텍스트 버튼)은 표 본문 13px과 맞춘
것이다. 짝수 스윕은 디자이너 램프를 덮는 행위라 보류했다.

## 다음 화면에 들고 갈 것

1. **개념을 줄여라, 표현 말고** — 원자적 저장 하나가 리듀서·경고·prop·파일을 지웠다.
2. **인접 > 병합** — 관련 있다는 사실은 옆 열로 충분하다. 합치면 스캔성을 판다.
3. **면은 테두리로 나눈다** — 이 팔레트에서 휘도 대비로 면을 경계지을 수 없다.
4. **대비는 경계용이지 순위용이 아니다** — 열 레이블은 가장 조용해야 한다.
5. **UI는 계약에 없는 조인을 발명하지 않는다** — 어댑터가 버리고 있는 필드는 연결하되,
   없는 관계는 만들지 않는다.
6. **선언하지 않은 색은 상속된다** — 다크 미디어쿼리가 남은 제품에서는 그게 곧 버그다.
