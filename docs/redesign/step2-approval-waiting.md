## 1. 통계 타일 — 표시에서 필터로

| | Before | After |
|---|---|---|
| 정렬 | 좌측 | 가운데 |
| 숫자 | 26px | **40px** |
| 라벨 | 13 / 600 / #8B95A1 | **14 / 700 / #4E5968** |
| 단위 `건` | 13 / 600 / #8B95A1 (라벨과 동일) | **12 / 400 / #6B7280** |
| 퍼센티지 `66.7%` | 표시 | **삭제** |
| 색 스와치(녹/회 사각형) | 라벨 앞 | **삭제** |
| 역할 | 읽기 전용 숫자 | **클릭 = 필터** (선택 시 흰 배경 + 검정 링) |

**좋아진 점**

- 타일과 툴바 세그먼트가 `전체 / 대상 / 비대상`으로 **같은 라벨·같은 카운트를 두 번**
  보여주고 있었다. 타일을 필터로 만들고 세그먼트를 제거해 중복이 사라졌다(툴바에서
  약 190px 회수).
- 라벨과 단위가 동일 스타일이라 `3` `건`이 한 덩어리로 안 읽혔다. 단위를 값의 꼬리표
  계층으로 내려 `40px 숫자 + 작은 단위`가 하나로 읽힌다.
- 퍼센티지는 3건 중 2건에서 아무 판단도 돕지 못하는 정보였다.
- 라벨이 "연동 요청 대상 / 연동 요청 제외대상"이라고 이미 말하므로 색 스와치는
  같은 말의 반복이었다. 색은 이제 **선택 상태**만 표현한다.

## 2. 용어 통일

| 위치 | Before | After |
|---|---|---|
| 타일 / 필터 | 전체 · 대상 · 비대상 | 전체 요청 · **연동 요청 대상** · **연동 요청 제외대상** |
| 표 컬럼 헤더 | 연동 대상 | **요청 대상 여부** |
| 표 셀 값 | 대상 / **비대상** | 대상 / **제외** |
| Step 3 병합 헤더 | 연동 대상 / 제외 사유 | 요청 대상 여부 / 제외 사유 |

**좋아진 점**

- `연동 대상` 컬럼 안에 `대상` 값이 들어가 헤더가 질문이 아니라 답의 절반이었다.
  헤더=질문 / 셀=답으로 역할이 갈렸다.
- Step 2는 아직 연동 전이다. 실제로 표시하는 값은 "이 요청에 포함/제외됐는가"이므로
  `요청 대상 여부`가 사실과 맞다.
- `제외`가 바로 옆 `제외 사유` 컬럼으로 이어져 시선이 왼→오른쪽으로 흐른다
  (제외 → 왜? → 사유). 부정어 `비대상`을 한 번 더 뒤집어 읽을 필요도 없어졌다.

## 3. 카드 헤더 — 카드 속 카드 제거

**Before**: 제목 + 우측 끝 상태 배지 → 그 아래 파란 `StepBanner`(카드 안의 카드) →
보조 문장 전체가 파란색 → 요청 메타가 한 줄에 `요청일시 … · 요청자 …`

**After**: 좌측 정렬 1단 스택

```
연동 대상 승인 대기  [승인 대기]                    [🔄 다시 요청하기]
관리자 승인을 기다리고 있어요. 평균 1영업일 내 검토되며, …   ← 16px, 첫 문장만 파랑
연동 대상을 다시 고르고 싶다면 우측 상단 다시 요청하기를 …   ← 16px, 버튼명만 강조
                                                    ↕ 16px
요청일시              요청자                          ← 12 / 400 / #6B7280
2024. 01. 18. 오후 08:00   관리자                     ← 12 / 600 / #4E5968
                                                    ↕ 12px
[표 카드]
```

**좋아진 점**

- `StepBanner`를 없애 카드 안에 카드가 겹치는 구조가 사라졌다. 배너 문구와
  기존 부제("요청하신 DB 목록을 관리자가 확인하고 있어요")는 같은 뜻이라 하나로 합쳤다.
- 상태 배지를 제목 옆으로 옮기고 주황 점을 제거 — 화면 양끝으로 시선이 갈라지지 않는다.
- 보조 문장 전체가 파랑이면 강조가 아니라 배경색이다. **파랑은 상태를 알리는 첫 문장에만**
  남기고, 나머지는 보조색 + 버튼명만 진한 회색으로 3단 강조를 만들었다.
- 요청 메타는 한 줄 4토막(`라벨 값 · 라벨 값`)에서 **라벨 위 / 값 아래 2열**로 바꿔
  무엇이 라벨이고 무엇이 값인지 즉시 구분된다.

## 4. CTA — 파괴에서 되돌리기로

| | Before | After |
|---|---|---|
| 위치 | 카드 하단 sticky 액션바 | **제목 우측** |
| 라벨 | 전체 요청 취소 | **다시 요청하기** |
| 스타일 | 빨강 + 휴지통 아이콘 | **warnOutline(노랑) + 새로고침 아이콘** (기존 토큰 재사용) |
| 모달 | "…요청을 취소할까요?" | "연동 대상을 다시 선택할까요? / 현재 승인 요청은 취소되고 1단계로 되돌아갑니다" |

**좋아진 점**

- 사용자의 의도는 "취소"가 아니라 "다시 고르기"다. 빨강·휴지통은 데이터가 삭제되는
  동작의 신호인데 여기선 되돌아갈 뿐이라 색이 겁만 주고 있었다.
- 버튼이 표 아래에 있으면 행이 3건이든 300건이든 다 지나야 만난다. 판단 시점(표를 보기 전)에
  버튼이 보인다.
- **취소가 일어난다는 사실은 숨기지 않았다** — 모달 본문에 명시하고 확인 버튼은 danger 유지.
- 안내문에 "연동 대상을 다시 고르고 싶다면 우측 상단 **다시 요청하기**를 눌러주세요" 한 줄을
  추가해 버튼의 존재와 용도를 문장으로 연결했다.

## 5. 툴바 — select 2개에서 필터 아이콘 1개로

| | Before | After |
|---|---|---|
| 필터 UI | `DB Type · 전체` / `Region · 전체` select 나열 | 우측 **16×16 필터 아이콘** → 팝오버 |
| 대상 세그먼트 | 전체/대상/비대상 버튼 | 삭제 (상단 타일이 대신함) |
| 건수 표기 | 우상단 `1–3 / 3건` | 삭제 (푸터와 중복) |
| 팝오버 내용 | — | 그룹별 목록 + 체크, `max-h-280px` 스크롤, sticky 헤더, 필터 초기화 |

**좋아진 점**

- 툴바에 항상 떠 있던 컨트롤 4개가 검색창 + 아이콘 1개로 줄었다. 조건은 **필요할 때만** 펼쳐진다.
- 칩 wrap 대신 세로 목록 + 높이 상한이라, **DB Type/Region이 20개씩 늘어도 패널이 깨지지 않는다**.
- 필터가 걸리면 아이콘이 파란색으로 남아 닫아도 필터 중임을 알 수 있다.
- 건수는 페이지네이션 푸터에 이미 `1–3 / 전체 3건`으로 있었다.

## 6. 🐞 DB Type 필터 버그 수정

- **증상**: 필터 목록에 `RDS_CLUSTER`가 뜨는데 표의 Database Type 컬럼엔 `PostgreSQL`이 보였다.
  선택해도 매칭되는 행이 없었다.
- **원인**: 옵션은 `resource_type`에서, 셀은 `metadata.database_type`(→ `getDatabaseShortLabel`)에서
  값을 뽑아 **서로 다른 축**을 보고 있었다.
- **수정**: `useApprovalTableState`에 `dbTypeLabel()`을 두고 **옵션 생성·필터 매칭·셀 렌더가
  같은 문자열**을 쓰도록 통일.

## 7. 표

| | Before | After |
|---|---|---|
| 컬럼 순서 | Database Type · Resource ID · Region · Resource Name · … | **Resource Name · Resource ID · Database Type · Region · …** |
| Database Type | 파란 태그 | 평문 12px |
| Resource Name | 12.5px | **14px** (스캔 기준점) |
| 제외 사유 없음 | `—` | **빈 칸** |
| 페이지네이션 | 표와 12px 간격, 별개 요소 | **간격 0, 카드 푸터로 결합** (아래 라운드를 푸터가 담당) |

**좋아진 점**

- 식별(이름→ID) → 속성(타입·리전) → 결정(대상 여부→사유) 순. 맨 왼쪽 기준점이 값 3종짜리
  분류(Database Type)에서 **행마다 다른 이름**으로 바뀌어 세로 스캔이 가능해졌다.
- 이름과 ID가 인접해 서로를 보조한다(기존엔 Region이 끼어 있었다).
- 파란 태그는 상태도, 클릭 대상도 아니면서 행에서 가장 먼저 눈에 들어왔다. 이제 행의 배지는
  판정(대상/제외) 하나뿐이라 봐야 할 것이 먼저 보인다.
- 대상 행에는 제외 사유가 존재할 수 없다. `—`는 "값이 빠졌다"는 잘못된 신호였다.
- 툴바 + 표 + 페이지네이션이 하나의 카드로 붙어 경계가 한 번만 그어진다.

## 8. 접근성 (WCAG AA)

계층을 낮추는 과정에서 대비가 무너진 것을 실측으로 확인하고 되돌렸다.

| 요소 | Before | After |
|---|---|---|
| 메타 라벨 | #B0B8C1 · **2.01:1** ❌ | #6B7280 · **4.83:1** ✅ |
| 메타 값 | #8B95A1 · **3.04:1** ❌ | #4E5968 · **7.11:1** ✅ |
| 단위 `건` | #B0B8C1 · **2.01:1** ❌ | #6B7280 · **4.83:1** ✅ |
| 강조 문장 | blue-500 · **3.68:1** ❌ | #0064FF · **4.92:1** ✅ |
| 필터 아이콘 클릭 영역 | 16×16 ❌ | **32×32** ✅ (WCAG 2.5.8 ≥ 24×24) |

**교훈**: "계층을 낮춘다"를 색을 옅게 하는 것으로만 처리하면 대비가 먼저 깨진다.
**크기·굵기로 낮추고 색은 4.5:1을 지킨다** — 12px/400과 16px/600의 차이만으로 계층은 충분히 갈린다.

## 9. 타이포 · 간격 (짝수 px)

이 카드의 컴포넌트 4개에 한해 홀수·소수 px를 제거했다.

- 타일 라벨 13 → **14**, 단위 13 → **12**, 모달 라벨 11.5 → **12**
- 표 Resource Name 12.5 → **14**, Database Type 12.5 → **12**
- 툴바 검색·팝오버 항목 12.5 → **14**, 그룹 헤더·카운트 11.5 → **12**
- 본문 안내문 13.5 → **16**

헤더 세로 리듬: 제목 → 안내문 **8px**, 안내문1 → 안내문2 **4px**(한 덩어리),
안내문 → 요청 메타 **16px**, 요청 메타 → 표 카드 **12px**.

> ⚠️ 공유 토큰(`idcStyles.table.*`, `Pagination`, `identityBarStyles`)은 다른 화면까지 번지므로
> 건드리지 않았다. 표 헤더 색(#8B95A1 · 3.04:1)이 여기 남아 있다.
