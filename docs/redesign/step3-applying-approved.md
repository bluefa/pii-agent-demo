# Step 3 · 연동 대상 반영중 화면 리디자인

> 작성 2026-07-31 · 근거 화면 `/pass/target-sources/2001` (AWS) · `/2003` (Azure) · `/2008` (GCP)
> 선행 기록: `docs/redesign/step2-approval-waiting.md` (PR #590)
> 적용 컴포넌트: `ApplyingApprovedCard` / `WaitingApprovalTable` / `WaitingApprovalToolbar` /
> `useApprovalTableState` / `WaitingApprovalCard`(공유분) / `shared/MetaField`(신설)

Step 2에서 이미 공유 컴포넌트로 반영된 것(컬럼 순서, `요청 대상 여부` 헤더, 값 `대상`/`제외`,
빈 제외 사유, 필터 아이콘 팝오버, 표↔페이지네이션 결합)은 여기서 다시 다루지 않는다.

**이 화면의 결론은 "Step 3 전용 UI를 만들지 않는다"였다.** Step 3만 갖고 있던 세 가지(연동 이력
컬럼, 연동 상태 필터, 툴바 세그먼트)가 전부 삭제로 끝나면서, Step 2와 같은 카드가 승인 메타만
바꿔 끼운 형태가 됐다. 삭제 339줄 / 추가 117줄.

---

## 1. 🐞 `연동 이력` 컬럼 — 계약에 없는 값이었다

**증상**: 4행이 전부 주황 `Pending` 태그. 정보는 없고 색만 튀었다.

**원인**: `integration_status`는 `docs/swagger/install-v1.yaml` **어디에도 없다**. 값을 만드는 곳은
`lib/bff/mock/confirm.ts`의 `deriveIntegrationStatus()` 하나뿐 — 목이 발명한 필드다.
실 BFF에서는 전 행이 `—`로 뜨고, 아래 배너의 `N건 중 0건 완료`는 **영원히 0건**이었다.

| | Before | After |
|---|---|---|
| `연동 이력` 컬럼 | `Integrated`(녹) / `Pending`(주황) / `—` | **삭제** |
| 툴바 `연동 상태` 필터 그룹 | `Integrated (N)` / `Pending (N)` / `제외` | **삭제** |
| 배너 진행 카운트 | `전체 7건 중 0건 완료` | **삭제** |
| 대상/사유 컬럼 | `요청 대상 여부 / 제외 사유` 병합(사유가 알약 아래 쌓임) | **`요청 대상 여부` + `제외 사유` 분리** (= Step 2와 동일) |
| `WaitingApprovalTable` variant | `waiting` \| `applying` | **prop 삭제** (분기가 사라짐) |

**좋아진 점**

- 없는 사실을 있는 것처럼 그리던 컬럼이 사라졌다. 행마다 배지는 판정(`대상`/`제외`) 하나가 되어
  Step 2의 "행당 배지 1개" 예산과 같아졌다.
- 병합 컬럼을 유지할 이유가 `연동 이력`이 마지막 칸을 차지했기 때문이었다. 그게 없어지자
  Step 2의 컬럼 구성이 그대로 맞아떨어졌고 `variant` 분기 전체가 없어졌다.
- 이 컬럼을 지키던 테스트 4개가 전부 **계약에 없는 필터를 고정하는 테스트**였다. 지우고,
  "연동 상태 필터가 없을 것 / 연동 이력 컬럼이 없을 것"을 확인하는 회귀 테스트로 바꿨다.

> ⚠️ `integration_status`는 `lib/types.ts`·`lib/bff/mock/confirm.ts`에 아직 남아 있다.
> 이번엔 **노출만** 지웠다 — 목 데이터·타입 정리는 별도 작업(LIN-51 계열)이다.

## 2. 툴바 세그먼트 → 상단 타일 (Step 2와 동일)

| | Before | After |
|---|---|---|
| 카운트/필터 UI | 툴바 세그먼트 `전체 4 / 연동 대상 4 / 연동 제외대상 0` | **상단 타일 3개** (클릭=필터) |
| 용어 | 연동 대상 / 연동 제외대상 (#590 이전 표기) | **전체 요청 / 연동 요청 대상 / 연동 요청 제외대상** |
| Region 필터 | Step 3에서만 숨김 | **노출** (Step 2와 동일) |
| `WaitingApprovalToolbar` variant | `waiting` \| `applying` | **prop 삭제** (`FilterSeg`·`Divider`도 함께 삭제) |

**좋아진 점**

- 타일과 세그먼트를 **둘 다 두지 않는다**는 것이 이번 결정의 전부다. Step 2가 이미 타일을
  필터로 정했으므로 Step 3만 다른 조작 모델을 쓸 이유가 없다. 2→3 이동 시 같은 자리에 같은
  컨트롤이 있다.
- 세그먼트가 들고 있던 구표기가 화면에서 사라졌다(라벨은 이제 한 곳, 타일에만 있다).
- Region 필터를 Step 3에서 숨긴 근거는 v16 시안이었는데, 표는 Region 컬럼을 그대로 보여준다.
  **보이는 컬럼은 거를 수 있어야 한다** — 숨김을 유지할 이유가 없었다.

## 3. 카드 헤더 — Step 2의 스택으로 통일

**Before**: 제목 + 우측 끝 `● 반영중` 배지 → 제목 아래 한 줄에
`관리자 승인 후 … · 승인일시 2024. 01. 19. 오후 06:00 · 승인자 김보안(kim.security)` → 그 아래 초록 배너

**After**

```
[3번째 단계]                                        ← primary 태그 (INSTALL_STEPS 순서)
연동 대상 반영중  [반영중]                            ← 배지가 제목 옆, 주황 점 제거
승인이 완료됐어요. Agent 설치에 필요한 준비를 …          ← 16px, 첫 호흡만 파랑
                                                   ↕ 16px
승인일시                승인자                        ← 12 / 400 / #6B7280
2024. 01. 19. 오후 06:00  김보안 (kim.security)        ← 12 / 600 / #4E5968
```

| | Before | After |
|---|---|---|
| 단계 태그 | 없음 | **`3번째 단계`** (`INSTALL_STEPS` 순서에서 읽음) |
| 상태 배지 | 우측 끝, 주황 점 있음 | **제목 옆, 점 제거** |
| 초록 `StepBanner` | 있음 | **삭제** |
| 승인 메타 | 안내문 뒤에 `· 라벨 값 · 라벨 값` | **라벨 위 / 값 아래 2열** (`MetaField`) |

**좋아진 점**

- 같은 말이 **세 번** 있었다: 헤더 문장("관리자 승인 후 … 사전 작업이 자동으로 진행됩니다"),
  초록 배너("승인이 완료되어 시스템에 반영 중입니다 … 평균 5분"), 우측 가이드 패널.
  배너를 지우고 **2호흡**으로 합쳤다 — `승인이 완료됐어요.`(파랑) + `Agent 설치에 필요한 준비를
  최대한 빠르게 진행하고 있어요.`
- **소요 시간을 지웠다.** `평균 5분 내외`는 근거 없는 약속이었다(진행률 API도 없다).
  지킬 수 없는 수치 대신 태도만 말한다. 종결어미도 `~합니다`/`~해요` 혼용에서 **해요체로 통일**했다.
- 배너가 없어지면서 카드 안의 카드가 사라지고, 타일이 헤더 바로 아래로 올라왔다.
- 메타가 안내문 꼬리에 붙어 있어 어디부터 값인지 안 보였다. 라벨/값 2열로 갈랐다.
- `MetaField`는 Step 2 카드 안에 있던 로컬 컴포넌트였다. Step 3이 같은 것을 필요로 해서
  `_components/shared/MetaField.tsx`로 옮겼다(**두 번째 사용처가 생긴 뒤에** 옮겼다).

## 4. 로딩 중 상태 태그·보조 문구 보류

**Before**: `반영중` 배지와 안내 문장이 `getApprovedIntegration` 응답 전에 먼저 그려졌다.
데이터가 도착하기 전에 헤더가 상태를 단정하고, 실패하면 그 문장 아래에 에러 행이 붙었다.

**After**: `state.status === 'ready'` 전까지 배지·문장 자리에 **스켈레톤**을 둔다.
자리를 잡아두므로 값이 들어와도 카드가 밀리지 않는다.

- 제목과 `3번째 단계` 태그는 **응답과 무관**하게 참이므로(부모가 이미 `processStatus`로 이
  카드를 골랐다) 그대로 즉시 그린다. 보류하는 것은 **응답이 결정하는 것뿐**이다.

## 5. 🐞 제외 사유 컬럼이 표를 가로 스크롤시켰다

**증상**: Azure `/2003`에서 표에 가로 스크롤바가 생기고 마지막 사유 칩
(`Legacy archive · 2024년 EOL 예정…`)이 오른쪽 끝에서 잘렸다.

**원인**: `ReasonChipInline`의 기본 요약 길이가 40자다. Step 2의 픽스처(`/1007`)는 **제외 사유가
비어 있어서** 이 컬럼 폭이 한 번도 검증된 적이 없었다. Step 3에서 사유를 별도 컬럼으로 되돌리자
6개 컬럼 + 40자 칩이 카드 폭을 넘겼다.

**수정**: `WaitingApprovalTable`에서 `summary`를 클램프해 넘긴다(공유 칩 컴포넌트의 기본값은
건드리지 않았다 — 다른 화면까지 번진다). 전문은 그대로 호버 팁에 있다.
처음엔 22자였고, §6에서 Region을 안 접게 만들면서 폭이 다시 모자라 **15자**로 좁혔다.

> 교훈: "20건이 되면?"만이 아니라 **"값이 길면?"**도 같은 질문이다. 그리고 픽스처가 빈 값이면
> 그 컬럼은 검증된 적이 없는 것이다.

## 6. 표 — 줄바꿈 제거 (Step 2와 공유)

라이브 리뷰에서 "값들이 너무 강하게 느껴진다 / Region이 줄바꿈된다"는 지적이 나와 **먼저 측정했다**.
결과: 폰트 계층은 Step 2와 **완전히 동일**했다(Name 14/400 mono #191F28, ID·Region 12/400 mono
#4E5968, DB Type 12/400). 행 높이는 오히려 Step 2가 더 컸다(87px vs 75px).

원인은 계층이 아니라 **줄바꿈**이었다.

| | Before | After |
|---|---|---|
| Region | `white-space: normal` → `ap-northeast-2`가 두 줄 | **`whitespace-nowrap`** |
| Resource Name | 2~3줄로 wrap (행에서 가장 진한 컬럼이 검은 덩어리) | **1줄 truncate + Tooltip** (`max-w-200px`) |
| Resource ID 상한 | 260px | **220px** (Region이 안 접히면서 카드 폭 초과) |
| 사유 칩 클램프 | 22자 | **15자** (같은 이유) |
| 행 높이 | 59 / 69 / 75px 들쭉날쭉 | **전 행 59px** |

**좋아진 점**

- 행 높이가 균일해지면서 세로 스캔의 기준선이 생겼다. "강해 보이던" 것의 정체는 굵기가 아니라
  **근검정 mono가 3줄로 쌓인 면적**이었다.
- Region은 값 집합이 정해진 토큰이라 접을 이유가 없었다.
- **폰트 토큰은 하나도 안 바꿨다.** Resource Name의 `font-mono`를 한 번 뺐다가 되돌렸다 —
  `WaitingApprovalTable.test.tsx`가 Name/ID/Region의 mono를 계약으로 고정하고 있었다.
  테스트가 "이건 합의된 결정"이라고 알려준 셈이다.

> ⚠️ 공유 컴포넌트라 **Step 2에도 그대로 적용된다.** `/1007`(9행) 확인: 오버플로 0, 전 행 59px.

## 7. 행 hover — 배경이 아니라 대비를 올린다

"리소스가 많아질수록 hover한 행이 더 선명했으면 좋겠다"는 요청. **먼저 쟀다.**

| | 대비 | 판정 |
|---|---|---|
| 기존 hover `#F7F8FA` vs 흰 배경 | **1.063:1** | 사실상 안 보임 |
| 제외 행 hover | **없음** — `rowExcluded`가 `row`를 통째로 대체 | 🐞 |
| (있었더라도) `#F9FAFB` → `#F7F8FA` | **1.017:1** | 무의미 |

| | Before | After |
|---|---|---|
| 대상 행 hover | `#F7F8FA` (1.06:1) | **`#F2F4F6`** (1.10:1) |
| 제외 행 hover | 없음 | **`#ECEFF3`** (제외 tint 기준 1.10:1) |
| 보조 컬럼 텍스트 | #4E5968 고정 | **hover 시 #191F28** (6.45:1 → **15.0:1**) |
| Resource Name | 무반응 (색이 이미 15.9:1로 max) | **400 → 600 + primary 파랑** (폭 변화 0) |
| 툴팁 | 값이 다 보여도 항상 뜸 | **잘린 셀에서만** (`truncatedOnly`) |
| 키보드 | hover 전용 | **`focus-within` 동일 적용** |
| 전환 | `transition-colors` | + `duration-150` · **`motion-reduce:transition-none`** |

**좋아진 점**

- **배경만 진하게 하는 건 "선명해지는" 게 아니라 "칠해지는" 것이다.** 위치는 표시되지만 읽기는
  더 쉬워지지 않는다. 보조 컬럼을 근검정으로 올리는 쪽이 요청의 실제 내용(`선명하게`)에 맞고,
  대비 수치로도 6.45:1 → 15.0:1이다.
- 제외 행에 hover가 없던 것은 눈으로는 안 잡히고 **코드를 봐야 보이는 결함**이었다.
  각 분기가 자기 rest/hover 색을 모두 소유하도록 바꿔 두 상태 모두 1.10:1을 확보했다.
- 행에는 복사 버튼과 툴팁 트리거가 있다. `focus-within`을 같이 걸어 **탭으로 이동해도 마우스와
  같은 하이라이트**를 받는다 (ui-ux-pro-max: `focus-states` · `hover-vs-tap`).
- **컬럼마다 여유가 남은 축을 쓴다.** Resource Name은 색이 이미 상한(#191F28 · 15.9:1)이라
  올릴 곳이 없었다 — 행에서 실제로 읽는 앵커 컬럼이 hover에 무반응이었다. 여기만 **굵기**를 쓴다.

  | 컬럼 | 폰트 | 쓰는 축 |
  |---|---|---|
  | Resource Name | Geist Mono | **굵기 400→600 + 파랑 #0050D6** |
  | Resource ID · Region | Geist Mono | 색 |
  | Database Type | Pretendard | 색 |

  굵기가 mono 컬럼에서만 공짜인 이유: **Geist Mono는 가변 폰트인데 advance width가 굵기와
  무관**하다(14px 실측 400=520.80px, 700=520.79px). 모든 이름 셀에 `font-semibold`를 동시에
  강제해도 컬럼 폭이 소수점 둘째 자리까지 그대로다. Pretendard는 400→600에서 4% 넓어지므로
  (352→366px) Database Type은 색만 쓴다.
- **파랑은 `#0064FF`가 아니라 `#0050D6`(primaryDark)를 쓴다.** `#0064FF`는 흰 배경에서 4.92:1로
  통과하지만, hover 배경이 깔리면 **4.46:1(대상) / 4.27:1(제외)로 AA 미달**이 된다. 14px는
  semibold여도 WCAG large text가 아니라 4.5:1이 그대로 적용된다. `#0050D6`은 6.11:1 / 5.84:1로
  여유가 있고, 토큰 계열도 이미 hover용으로 쓰던 색이다
  (`primaryColors.textGroupHover` 신설 — 이유를 토큰 주석에 남겼다).
- **툴팁은 값이 잘린 셀에서만 연다.** 전체 이름이 다 보이는데도 툴팁이 뜨는 건 정보가 아니라
  방해였다. `Tooltip`에 `truncatedOnly` opt-in을 추가하고 **열리는 순간에 `scrollWidth >
  clientWidth`를 잰다** — 셀마다 ResizeObserver를 두지 않아도 되고, 그 값은 그 순간에만 필요하다.
  컨테이너와 **첫 자식 둘 다** 검사한다: Resource ID는 컨테이너가 `192=192`인데 자식 span이
  `961 > 192`라 한쪽만 봤으면 정작 필요한 툴팁을 죽일 뻔했다.
- **다른 행을 흐리게(dim) 하는 방식은 버렸다.** #4E5968를 opacity 0.75로 낮추면 4.0:1,
  0.5면 2.4:1 — **WCAG AA 미달**이다. 게다가 포인터가 표 위에 있는 내내 화면 대부분이
  기준 미달 상태가 된다. 하나를 띄우려고 나머지를 못 읽게 만드는 거래는 성립하지 않는다.
- 공유 토큰 `idcStyles.table.row`는 **안 건드렸다** — IDC 표 3종·모달 3종·ConnectionTestCard까지
  7곳이 쓴다. 이 표에만 선언했다.

> ⚠️ `cn`은 단순 join이다. 처음엔 `ROW_BASE`에 `focus-within:bg-[#F2F4F6]`를 두고 제외 분기에
> `focus-within:bg-[#ECEFF3]`를 얹었는데, **같은 엘리먼트에 두 값이 겹쳐 CSS 순서가 승자를
> 정하는 상태**였다. 각 분기가 두 색을 모두 갖도록 분리했다.

## 8. 시도했다가 되돌린 것

- **Resource Name의 `font-mono` 제거**: "값이 너무 강하다"는 지적에 mono를 빼봤는데,
  테스트가 바로 깨졌다(Name/ID/Region mono는 고정된 계약). 되돌리고 **줄바꿈만** 잡았더니
  그것으로 충분했다. → 체감이 무거우면 **폰트를 건드리기 전에 레이아웃(줄 수·행 높이)을 의심**한다.
- **`3001` 포트 재사용**: 다른 세션의 워크트리(`step4-aws-install-detail`) dev 서버가 물고 있었다.
  죽이지 않고 `3013`으로 옮겼다. → 워크트리가 많은 리포에서 **포트는 공용 자원**이다.
