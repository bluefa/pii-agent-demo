# PASS 로고 — 아웃라인 자산

> `app/components/layout/PassLogo.tsx` · 브랜치 `feat/pass-wordmark-outfit`

TopNav 로고는 **라이브 텍스트가 아니라 SVG 아웃라인**입니다. 폰트 바이너리에서
글리프 외곽선을 추출해 경로로 박아 넣었습니다. 이 문서는 **왜 그랬는지**와
**어떻게 다시 만드는지**만 담습니다. 치수·색의 근거는 컴포넌트 주석에 있습니다.

> **한 줄입니다.** 워드마크 `PASS` 하나뿐입니다. 디스크립터
> `PII Agent Self Service` 는 아래 줄에 15px로 붙어 있었지만, 락업이 76px 바의
> 콘텐츠 박스를 통째로 채우고 있었고 벤치마크한 콘솔 5곳 중 2줄 락업을 바에 넣은
> 곳이 하나도 없어서 제거했습니다. 원래도 `hidden xl:block` 이라 1280px 아래에서는
> 안 보이던 줄입니다. 경로 데이터는 git 히스토리에 남아 있습니다 — 로그인·랜딩
> 화면처럼 락업 전체가 필요한 자리가 생기면 거기서 꺼내 쓰면 됩니다.
> 아래 §1·§3·§4 의 디스크립터 언급은 **그때의 기록**이지 현재 구현이 아닙니다.

## 1. 왜 아웃라인인가

| 이유 | 내용 |
|------|------|
| 없는 웨이트 | `app/fonts`는 Pretendard **400–800**만 싣습니다. 이전 로고는 `font-black`(900)을 선언하고도 실제로는 800으로 그려지고 있었습니다. |
| 폰트 로드 의존 | 웹폰트로 그린 로고는 폰트 로드만큼만 신뢰할 수 있습니다. 폴백·힌팅 차이가 그대로 브랜드에 드러납니다. |
| 서체 불일치 | 워드마크만 Outfit이고 디스크립터가 Pretendard이던 동안, 두 줄이 **문자 그대로 다른 서체**라 로고 밑에 UI 라벨이 붙은 것처럼 읽혔습니다. |

## 2. 서체와 라이선스

- **Outfit** — 워드마크 900 (디스크립터가 있던 동안은 500도 함께)
- **SIL Open Font License 1.1**. OFL은 로고 사용을 명시적으로 허용하고, 오히려
  **아웃라인 변환을 권장 방식**으로 안내합니다. 이미지로 굽는 결정과 정확히 맞물립니다.

> ⚠️ macOS 번들 서체(SF Pro · DIN · Futura · Avenir · Helvetica Neue)는 **로고에 쓸 수 없습니다.**
> 화면에 글을 쓰라고 준 라이선스지 로고용이 아닙니다. 서체를 바꾼다면 OFL이거나
> 별도 로고 라이선스를 확보한 것이어야 합니다.

## 3. 다시 만드는 법

경로 데이터는 손으로 못 고칩니다. 문구·서체·웨이트를 바꾸려면 재생성해야 합니다.

```
1. 폰트 확보      OFL 원본 (예: google/fonts 의 ofl/outfit/Outfit[wght].ttf)
2. 인스턴스화     fontTools.varLib.instancer 로 wght 고정 (900 / 500)
3. 셰이핑         uharfbuzz 로 문자열 셰이핑 → 커닝이 디자이너 의도대로 들어감
                  (advance 단순 합산 금지 — 커닝이 사라집니다)
4. 아웃라인       글리프별 SVGPathPen + TransformPen
                  transform = (s, 0, 0, -s, cursorX*s, 100)   ← y 뒤집기
                  s = 100 / OS/2.sCapHeight                    ← 캡하이트 100 정규화
5. viewBox        전체 경로의 실제 잉크 bbox 로 지정
6. 좌표 정리      소수점 2자리 반올림 (파일 47% 감소, 5배 확대에서 최대 8/255 차이)
```

### viewBox 는 캡하이트 정사각형이 아니라 잉크 박스여야 합니다

처음에 `0 0 W 100`(캡하이트 정사각형)으로 넣었다가 두 가지가 깨졌습니다.

- **S 가 잘렸습니다.** S는 캡과 베이스라인을 위아래로 1.7단위씩 넘어가는데,
  SVG 루트는 기본으로 클리핑해서 곡선 끝이 평평해졌습니다.
- **두 줄이 어긋났습니다.** P의 왼쪽 사이드베어링 8.3단위가 워드마크를
  디스크립터보다 2px 오른쪽으로 밀었습니다.

잉크 박스로 잡으면 둘 다 사라지고, **`h-*` 유틸리티가 곧 그려지는 높이**가 됩니다.

## 4. 비율은 협상 대상이 아닙니다

높이가 폭을 결정합니다. 임의의 W×H 박스에 맞출 수 없습니다.

| 요소 | 비율 | 현재 높이(32px)일 때 |
|------|------|----------------------|
| 워드마크 `PASS` | 3.34 : 1 | 107px |

32px 은 실측에서 나온 값입니다. 2026-08-12 에 GitHub · Google Cloud · Vercel ·
Stripe · Atlassian 상단 바를 브라우저에서 재보니 콘솔은 마크를 바 높이의
**28–50%** 에 두고 있었고, 32 / 64 = 50% 가 GitHub 이 마크·메뉴 항목·아바타에
똑같이 쓰는 값입니다. 참고로 이전 값은 40px(워드마크 134px)이었습니다.

## 5. ⚠️ TopNav 높이는 지역 값이 아닙니다

로고를 키우려면 바가 커지고, 바 높이는 **6개 파일에 9번 리터럴로 박혀 있습니다.**
Tailwind 클래스는 완전한 문자열이어야 해서(동적 조합 금지) 공유 토큰을 못 읽습니다.

현재 **64px**. 바꾸면 아래가 전부 같이 움직여야 합니다 — 하나라도 빠뜨리면
그 페이지만 스크롤이 어긋납니다.

- `app/components/layout/TopNav.tsx` — 값의 주인. 의존처 목록도 여기 주석에 있습니다
- `lib/theme.ts` — `pipelineStyles` shell / sidebar
- `app/admin/layout.tsx` — `FullPageNotice` (ADMIN 게이트 전체 화면 안내)
- `app/admin/pipelines/_services/styles.ts` — `split`, `railSticky`
- `app/services/_components/ServiceManagementView.tsx`
- `app/target-sources/[targetSourceId]/_components/ProjectDetail.tsx` (×2)

검증은 `/services` · `/admin/pipelines/ops/services` · `/target-sources/1003`
세 화면에서 콘텐츠가 바 높이에서 시작해 뷰포트 바닥까지 닿는지 보면 됩니다.

> 이 목록과 `TopNav.tsx` 주석의 목록은 **같은 사실의 사본 두 개**입니다. 한쪽만
> 고치면 다음 사람이 틀린 쪽을 봅니다. 실제로 76 → 64 작업 때 `app/admin/layout.tsx`
> 가 두 목록 모두에서 빠져 있었고, 충돌도 실패도 없이 그대로 머지될 뻔했습니다.
> 지점을 늘리거나 줄이면 **두 곳을 같이** 고치세요.

## 6. 남은 것

- **다크 면 전용 1종뿐입니다.** 소비처가 TopNav(slate-900)뿐이라 잉크 값도 다크 면
  형태(`#4D94FF`)만 있습니다. 흰 면에 올릴 일이 생기면 `navStyles.brand` 에
  라이트 형태(`#0064FF`)를 짝으로 추가해야 합니다. 디스크립터가 쓰던 보라
  (`#A78BFA` / 라이트 `#6D28D9`)는 그 줄과 함께 제거됐습니다.
- **워드마크는 번역·리플로우·선택이 안 됩니다.** 접근성 이름은 `aria-label="PASS"`
  로 갑니다. 아웃라인이라 문자열이 아니기 때문입니다.
