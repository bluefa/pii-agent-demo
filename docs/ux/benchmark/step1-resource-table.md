## 채택안 — 시안 H 변형 (기본 접힘 + 인라인 아코디언)

| 항목 | 구현 내용 |
|---|---|
| 기본 접힘 | Athena 그룹 · RDS Cluster 모두. `collapsedGroups`(닫힌 키) → `expandedKeys`(열린 키)로 뒤집어, 필터·재스캔으로 새로 생긴 그룹도 접힌 채 시작하고 사용자가 편 그룹은 세션 내내 열려 있다 |
| 인스턴스 = 아코디언 본문 | 인스턴스 행 제거 → `RdsInstancePanel`(클러스터 행 **바로 아래** colspan 본문). **1 인스턴스 = 1줄**, 본문은 그 합만큼 길어진다. 본문 자체 3열(인스턴스 · 가용 영역 · 엔드포인트)을 인스턴스가 전부 채운다 — 엔드포인트·AZ는 바깥 표에 열이 없어 이번에 처음 보인다. 역할 칩만 열을 갖지 않고 이름 옆에 붙는다 |
| 본문에 없는 것 | **제목 줄·안내문 없음** — 클러스터 이름과 건수는 위 행이 이미 말하고, 안내문은 체크된 라디오와 Reader 우선 정렬이 스스로 말하는 것을 반복했다. **엔진(Database Type)도 줄마다 반복하지 않는다** — 클러스터의 모든 멤버가 같은 엔진이고, 그 사실은 클러스터 행의 Database Type 칸이 한 번 말한다 (오너, 2026-08-12) |
| 아코디언으로 읽히게 | 여백·라운드·그림자 **없음**. 헤더 행과 본문이 **틈 0**으로 붙고 **같은 열림 틴트**(`bgColors.panel`)를 공유해 한 덩어리로 읽힌다. 들여쓰기는 이 표의 기존 계층 값(체크박스 열 52 + 자식 단 54 = 106px) |

### 판례 갱신

PR #630의 "부모 행 `· x 선택` 요약 제거 — 선택 표기는 자식 행 칩으로 단일화(재도입 금지)"는 **자식이 늘 보인다는 전제** 위의 결정이었다. 기본 접힘으로 그 전제가 사라져 접힌 부모가 선택 결과를 표시한다. 다만 되돌아온 것은 **선택 결과**(`↳ Reader demo-aurora-mysql-2`)이지, 기각된 **개수 요약**(`인스턴스 3 · 1 선택`)이 아니다 — 기각 사유였던 "같은 말을 두 군데서 한다"는 발생하지 않는다.

같은 PR의 "기본 펼침 항상 유지(체크 무관)" 확정은 2026-08-11 오너가 뒤집었다.

### 우측 스플릿 패널 → 인라인 아코디언 (오너 뒤집기, 2026-08-12)

시안 H 원안은 인스턴스 비교를 **우측 400px 스플릿 패널**(Cloudscape Split view)로 뺐다. 구현해서 보니 두 가지가 깨졌고 오너가 뒤집었다 — "RDS Cluster는 설정을 할 수 있다는 것 자체를 사용자가 인지를 못 할 것 같다", "설정 패널이 RDS Cluster 근처에 노출되어야 하는 것 아닌가".

1. **발견 가능성** — 표에 있는 다른 행과 생김새가 같아서, 그 안에 고를 것이 있다는 신호가 없었다. `↳ Reader …` 점선 밑줄 하나로는 부족하다.
2. **근접성** — 표가 뷰포트보다 크면 패널이 자기 행과 멀리 떨어진 곳(화면 상단)에 뜬다. sticky로 붙잡아도 "저 행의 것"이라는 연결은 회복되지 않는다.

또 하나, 첫 구현의 **3열 카드 그리드**도 뒤집혔다 — "instance가 8개면 어떻게 하려고 그러냐? 가변적인 길이의 아코디언." Aurora 클러스터는 writer 1 + reader 최대 15다. 타일 그리드는 8건에서 3줄 × 자투리로 깨지고, 무엇보다 **개수가 적다고 가정한 레이아웃**이다. 1 인스턴스 = 1줄이면 밴드는 그냥 길어지고, 열이 정렬돼 있어 AZ 8개·엔드포인트 8개를 눈 한 번에 훑는다. 실측: 3건 254px · 8건 480px (줄당 45px).

세 번째로, 첫 인라인 구현이 **띄워 놓은 카드**(여백 + 라운드 + 그림자)였던 것도 반려됐다 — "아코디언 테이블 같지는 않아요". 카드는 "행 아래 어딘가에 패널이 떴다"로 읽히지, 그 행이 열렸다로 읽히지 않는다. 아코디언으로 읽히게 하는 것은 **틈 0 + 공유 틴트 + 계층 들여쓰기** 세 가지다.

**셰브런 + 인라인 아코디언**이 앞의 둘을 한 컨트롤로 해결한다. 셰브런은 이 앱에 이미 있는 "여기 더 있다" 신호이고(`toggleClosed`가 primary hue를 쓰는 이유가 정확히 이것), 밴드는 자기 행 말고 다른 곳에 뜰 수가 없다. Athena 그룹과 같은 문법이라 표 안에 접힘 어휘가 하나로 유지된다.

본문의 **아래 여백이 위보다 크다**(`pt-4` 16px / `pb-6` 24px, 오너: "아래 공간이 윗 공간보다 최소 8픽셀은 더 크게"). 본문은 위의 클러스터 행에 속하므로, 그 행에 바짝 붙고 다음 리소스 앞에 자리를 남기는 것이 소속을 말한다. 두 값 모두 간격 세트 위 — 20px은 아니다.

**틴트는 gray-50이 아니라 gray-100**(`bgColors.panel`)이다. gray-50은 흰 바탕과 ΔE00 1.20 — 두 색이 다르다고 인지되는 하한(~2.3)에도 못 미쳐서, 헤더와 본문을 안 보이는 틴트로 묶는 셈이 된다. 대신 이 토큰은 제약을 하나 달고 온다: 이 표면 위 `tertiary`는 4.37:1로 AA 미달이라 본문의 열 라벨·엔드포인트는 `secondary`로 읽는다.

비용은 **열었을 때만** 세로 201px(인스턴스 3건). 기본 접힘이라 평소에는 0이고, 이것이 아코디언을 고른 대가다.

(폐기된 sticky 구현 메모: 패널을 `absolute inset-y-0`으로 붙이면 뷰포트보다 큰 표에서 잘려 나가서 레일+sticky 카드가 필요했고, offset parent의 `overflow-hidden`이 스크롤포트가 되어 sticky를 죽였다. 나중에 이 앱에 스플릿 패널을 다시 만들 일이 있으면 같은 함정에 걸린다.)
