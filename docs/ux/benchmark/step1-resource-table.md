| 항목 | 구현 내용 |
|---|---|
| 기본 접힘 | Athena 그룹 · RDS Cluster 모두. `collapsedGroups`(닫힌 키) → `expandedKeys`(열린 키)로 뒤집어, 필터·재스캔으로 새로 생긴 그룹도 접힌 채 시작하고 사용자가 편 그룹은 세션 내내 열려 있다 |
| 인스턴스 = 아코디언 본문 | 인스턴스 행 제거 → `RdsInstancePanel`(클러스터 행 **바로 아래** colspan 본문). **1 인스턴스 = 1줄**, 본문은 그 합만큼 길어진다. 본문 자체 3열(인스턴스 · 가용 영역 · 엔드포인트)을 인스턴스가 전부 채운다 — 엔드포인트·AZ는 바깥 표에 열이 없어 이번에 처음 보인다. 역할 칩만 열을 갖지 않고 이름 옆에 붙는다 |
| 본문에 없는 것 | **제목 줄·안내문 없음** — 클러스터 이름은 위 행이 이미 말하고, 안내문은 체크된 라디오와 Reader 우선 정렬이 스스로 말하는 것을 반복했다. **건수는 위 행이 대신 말하지 않는다** — 아래 판례대로 부모 행의 개수 요약은 기각된 표기이고, 열린 본문에서 줄을 세면 되는 값이라 본문 제목에도 부모 행에도 두지 않는다. **엔진(Database Type)도 줄마다 반복하지 않는다** — 클러스터의 모든 멤버가 같은 엔진이고, 그 사실은 클러스터 행의 Database Type 칸이 한 번 말한다 (오너, 2026-08-12) |
| 아코디언으로 읽히게 | 여백·라운드·그림자 **없음**. 헤더 행과 본문이 **틈 0**으로 붙고 **같은 열림 틴트**(`bgColors.panel`)를 공유해 한 덩어리로 읽힌다. 들여쓰기는 이 표의 기존 계층 값(체크박스 열 52 + 자식 단 54 = 106px) |
| 트리 레일 | Athena 그룹과 **같은 레일**을 그린다 (오너, 2026-08-12). 세로 트렁크 x=68(= 클러스터 셰브런의 중심)이 클러스터 이름 셀(`group.parentCell`)에서 시작해 밴드를 관통하고, 인스턴스마다 가로 팔꿈치가 나온다. 마지막 줄에서 트렁크가 끊긴다(`lineLast`) — 계속 이어지면 아래로 더 있다는 말이 된다. 토큰은 `idcStyles.table.instanceBand`: 그룹 토큰의 오프셋은 이름 셀 기준이고 밴드는 colspan 셀 기준이라 재사용이 불가능해, **같은 축을 다시 앵커한 것**. 두 축이 어긋나지 않도록 `design-guard.test.ts` 가 지킨다 |
| 인스턴스 이름 = 자식 단 | 라디오를 흐름에서 빼내 계층 틈에 건다(`instanceBand.radio`, 셰브런이 이름 셀 패딩에 걸리는 것과 같은 거래). 흐름에 두면 이름이 106 → 130 으로 밀려, 바로 위 Athena 자식들과 **다른 x에서 시작하는 열**이 된다. 눈이 훑는 건 이름이므로 단에 앉아야 하는 건 이름이다 |
| 역할 인접 | 역할 칩이 인스턴스 이름 **바로 옆**. 접힌 클러스터 행도 `↳ [Reader] demo-aurora-mysql-2` |
| 선택 표시 = 라디오만 | 선택된 줄에 **배경 틴트를 주지 않는다** (오너, 2026-08-12). 라디오가 이미 말하고, 읽기 전용에서는 `선택됨` 칩이 말한다. 틴트는 같은 말을 하는 세 번째 목소리였고 대가가 있었다 — 역할 칩의 면(`statusColors.pending.bg`)이 본문 면(`bgColors.panel`)과 **같은 gray-100** 이라, 틴트가 깔린 줄에서만 칩이 알약으로 보이고 나머지 줄에서는 배경에 녹았다. 한 목록에서 한 줄만 칩이 다르게 보이는 건 뜻이 없는 차이다 |
| 접힌 행이 정보를 들고 있음 | 클러스터는 `↳ [Reader] <instance>`(선택 결과). **Athena 부모는 하위 DB 이름을 나열하지 않는다** — 처음엔 3개 + `외 N개`로 넣었다가 뺐다(오너, 2026-08-12). 행 수를 줄이려고 접었는데 접힌 행이 자식 이름을 늘어놓으면 아낀 만큼을 글자로 되돌려준다. 부모가 드는 건 **몇 건이 어느 쪽인지**(`데이터베이스 대상 1 · 제외 0`)이고, 이름은 셰브런 한 번 거리다 |
| 그룹 행 = colspan 한 칸 | 부모 행의 열 값이 전부 사라졌다 — Database Type·Region 은 그룹의 **키**라 정체성이 이미 말하고, 설치 구분은 그룹이 받은 적 없는 판정이며, 집계는 정체성으로 옮겼다(오너, 2026-08-12). 빈 칸만 남은 행이 정체성까지 좁은 이름 열에 밀어넣고 있었으므로, 정체성이 그 폭을 가져간다. ⚠️ 두 표 다 `[&_td:not([colspan])]:py-5` 라 spanning 셀은 세로 패딩을 스스로 다시 선언해야 리듬이 맞는다 |
| 그룹 행 = 3단 스택 | **RDS Cluster 행과 같은 문법**: 종류 태그 → 이름 → 디테일. 한 줄에 늘어놓으니 회색 세 개가 크기만 다른 채로 순위가 없었다(오너, 2026-08-12: "계층이 이상함", "Region 태그도 회색이라 이상함") — 회색 **칠**이 자기를 소유한 라벨보다 리전을 크게 외쳤고, 14px 숫자가 14px 라벨과 같은 층에 앉았다. 단을 나눠 **크기 대신 채널**을 준다: 종류=면(`tagStyles.resourceKind`, `RDS Cluster`·`EC2` 와 같은 티어), 리전=이름 목소리, 집계=조용한 meta 톤. **리전이 이름이다** — 리전당 Athena 카탈로그 하나가 곧 그룹이라, 두 그룹을 가르는 건 리전이다 |
| 자식 행도 Region 을 말함 | 그룹 자식(Athena Database)의 Region 칸을 채운다(오너, 2026-08-12). 부모가 리전을 **이름**으로 들고 있어 한동안 자식에서 뺐지만, **열은 세로로 읽는 것**이라 데이터베이스마다 빈 칸이면 "리전 없음"으로 읽히고, 그룹이 길어지면 값을 든 유일한 행(부모)은 스크롤 밖이다. 부모 값을 되풀이하는 게 열이 하는 일이다. Resource ID 는 여전히 뺀다 — 그건 되풀이가 아니라 부모 경로 + 자식 이름이라 **같은 칸에서 두 번** 말하는 것 |
| 집계 문구 | `데이터베이스 · 대상 1 · 제외 0`. `데이터베이스 대상 1 · 제외 0` 은 명사구가 명사구로 이어지며 두 카운트의 병렬이 깨졌다(오너, 2026-08-12: "말이 되게 이상한듯"). 단위를 **독립 구간**으로 떼면 주어 하나 + 대응하는 사실 둘이 된다. 단위를 부르는 이유는 `대상 1` 만으로는 Athena 라고 적힌 행에서 "1이 뭔데"를 유추해야 하고 답이 Athena 도 리전도 아닌 **아래 접힌 데이터베이스**이기 때문 |
| 열림 상태 | 페이지 로드 시 접힘. **셰브런**(Athena 그룹과 같은 문법·같은 토큰)이 라벨 있는 컨트롤이고, 행 어디를 눌러도 열린다. 접힘 상태는 그룹 키와 클러스터 id를 한 `Set`에 담아 정책을 하나로 유지 |

### 판례 갱신

PR #630의 "부모 행 `· x 선택` 요약 제거 — 선택 표기는 자식 행 칩으로 단일화(재도입 금지)"는 **자식이 늘 보인다는 전제** 위의 결정이었다. 기본 접힘으로 그 전제가 사라져 접힌 부모가 선택 결과를 표시한다. 다만 되돌아온 것은 **선택 결과**(`↳ Reader demo-aurora-mysql-2`)이지, 기각된 **개수 요약**(`인스턴스 3 · 1 선택`)이 아니다 — 기각 사유였던 "같은 말을 두 군데서 한다"는 발생하지 않는다.

같은 PR의 "기본 펼침 항상 유지(체크 무관)" 확정은 2026-08-11 오너가 뒤집었다.

### 우측 스플릿 패널 → 인라인 아코디언 (오너 뒤집기, 2026-08-12)

시안 H 원안은 인스턴스 비교를 **우측 400px 스플릿 패널**(Cloudscape Split view)로 뺐다. 구현해서 보니 두 가지가 깨졌고 오너가 뒤집었다 — "RDS Cluster는 설정을 할 수 있다는 것 자체를 사용자가 인지를 못 할 것 같다", "설정 패널이 RDS Cluster 근처에 노출되어야 하는 것 아닌가".

1. **발견 가능성** — 표에 있는 다른 행과 생김새가 같아서, 그 안에 고를 것이 있다는 신호가 없었다. `↳ Reader …` 점선 밑줄 하나로는 부족하다.
2. **근접성** — 표가 뷰포트보다 크면 패널이 자기 행과 멀리 떨어진 곳(화면 상단)에 뜬다. sticky로 붙잡아도 "저 행의 것"이라는 연결은 회복되지 않는다.

또 하나, 첫 구현의 **3열 카드 그리드**도 뒤집혔다 — "instance가 8개면 어떻게 하려고 그러냐? 가변적인 길이의 아코디언." Aurora 클러스터는 writer 1 + reader 최대 15다. 타일 그리드는 8건에서 3줄 × 자투리로 깨지고, 무엇보다 **개수가 적다고 가정한 레이아웃**이다. 1 인스턴스 = 1줄이면 밴드는 그냥 길어지고, 열이 정렬돼 있어 AZ 8개·엔드포인트 8개를 눈 한 번에 훑는다. 실측: 3건 254px · 8건 480px (줄당 45px).

세 번째로, 첫 인라인 구현이 **띄워 놓은 카드**(여백 + 라운드 + 그림자)였던 것도 반려됐다 — "아코디언 테이블 같지는 않아요". 카드는 "행 아래 어딘가에 패널이 떴다"로 읽히지, 그 행이 열렸다로 읽히지 않는다. 아코디언으로 읽히게 하는 것은 **틈 0 + 공유 틴트 + 계층 들여쓰기** 세 가지다.

**셰브런 + 인라인 아코디언**이 앞의 둘을 한 컨트롤로 해결한다. 셰브런은 이 앱에 이미 있는 "여기 더 있다" 신호이고(`toggleClosed`가 primary hue를 쓰는 이유가 정확히 이것), 밴드는 자기 행 말고 다른 곳에 뜰 수가 없다. Athena 그룹과 같은 문법이라 표 안에 접힘 어휘가 하나로 유지된다.

본문의 **아래 여백이 위보다 크다**(`pt-4` 16px / `pb-6` 24px, 오너: "아래 공간이 윗 공간보다 최소 8픽셀은 더 크게"). 본문은 위의 클러스터 행에 속하므로, 그 행에 바짝 붙고 다음 리소스 앞에 자리를 남기는 것이 소속을 말한다. 두 값 모두 간격 세트 위 — 20px은 아니다.

**틴트는 gray-50이 아니라 gray-100**(`bgColors.panel`)이다. gray-50은 흰 바탕과 ΔE00 1.20 — 두 색이 다르다고 인지되는 하한(~2.3)에도 못 미쳐서, 헤더와 본문을 안 보이는 틴트로 묶는 셈이 된다. 대신 이 토큰은 제약을 하나 달고 온다: 이 표면 위 `tertiary`는 4.37:1로 AA 미달이라 본문의 열 라벨·엔드포인트는 `secondary`로 읽는다.

비용은 **열었을 때만** 세로 201px(인스턴스 3건). 기본 접힘이라 평소에는 0이고, 이것이 아코디언을 고른 대가다.

(폐기된 sticky 구현 메모: 패널을 `absolute inset-y-0`으로 붙이면 뷰포트보다 큰 표에서 잘려 나가서 레일+sticky 카드가 필요했고, offset parent의 `overflow-hidden`이 스크롤포트가 되어 sticky를 죽였다. 나중에 이 앱에 스플릿 패널을 다시 만들 일이 있으면 같은 함정에 걸린다.)

### 다른 Step·Admin 으로 전파 (오너, 2026-08-13)

오너 요청 "모든 Step에 적용할 부분은 적용" — 전 화면을 실측해 갭을 세 개로 좁히고 둘을 적용했다.

**적용 ①: 인스턴스 밴드를 2·3단계와 Admin 두 표가 공유**한다. 이 화면들은 인스턴스를 **바깥 표의 행**으로 그리고 있었다. 대가가 컸다 — 6열 중 3열(Resource ID·판정·제외 사유)은 **클러스터의 단일 결정**이라 멤버마다 비었고, 사용자가 실제로 비교하는 **엔드포인트는 열이 아예 없었으며**, AZ는 갈 곳이 없어 `Region` 헤더 밑에 들어가 있었다. 밴드 안에서는 셋 다 자기 라벨을 단 열을 갖는다. `RdsInstancePanel` 은 이미 `selectable`/`readonly` 가 갈려 있어 그대로 재사용했고(위치만 `shared/` 로 이동), 검토 화면은 라디오 없이 `선택됨` 칩이 선택을 말한다.

곁따라온 것 둘: **열린 클러스터 행이 밴드의 면을 함께 입는다**(`bgColors.panel`) — 틴트가 갈리면 "행이 열렸다"가 아니라 "아래에 패널이 떴다"로 읽히고, 이건 이 화면이 계속 반려해온 바로 그 모양이다. 그리고 **클러스터 행의 레일 hover 를 뗐다** — 멤버가 행이 아니게 되면서 같이 켤 두 번째 행이 없어졌고, 남겨두면 포인터가 지나갈 때마다 아무것도 칠하지 않는 클래스를 위해 표 전체가 리렌더된다. 이 변경으로 `RdsInstanceIdentity` 는 소비자가 0이 되어 삭제했다.

**적용 ②: 5·6·7 접힌 지역 행의 자식도 Region 을 되풀이**한다(위 「자식 행도 Region 을 말함」과 같은 규칙, 같은 이유).

**적용 ③: 접힌 클러스터 행이 선택된 인스턴스를 말한다** — 2·3단계와 Admin 두 표 모두(오너: "Step2 이상부터는 접었을 때도 instance 정보가 step1처럼"). 이 화면들은 `3개 인스턴스` 라는 **개수**만 들고 있었는데, 두 가지가 틀렸다. 하나, 그 개수 요약이 PR #630 에서 기각된 바로 그 표기다. 둘, **검토 화면에서 검토 대상은 개수가 아니라 선택**이다 — "어느 멤버로 붙는가"가 승인/반려의 근거인데 행은 몇 개인지만 말하고 있었다. `RdsChosenInstanceLine`(`RdsInstanceChips`)으로 빼서 네 소비처가 한 줄을 공유한다. 선택이 없는 제외 클러스터에서만 `인스턴스 N건` 으로 떨어진다 — 그때는 명명할 선택이 없으므로 개수가 정직한 말이다. 3줄이 되면서 `stackedIdentityLift`(2줄용 보정)는 뺀다 — 이름이 이미 가운데 줄이고, 그게 셰브런이 맞추는 줄이다.

**적용 안 함(오너 판단)**: ⓐ 2·3 기본 접힘 — 승인 표는 지금도 그룹이 펼쳐진 채 뜬다. ⓑ Admin 요청 큐(`CloudResourceTable`)의 Athena 그룹 — 자체 표라 트리가 없고 DB가 평면으로 깔린다. 4단계는 애초에 적용 대상이 없다: region 이 곧 리소스라 Database Type·Region 열 자체가 없고 멤버 인스턴스도 안 보인다.

## 리뷰 반영 (2026-08-13, 3중 리뷰)

opus 리뷰 1회 + codex 2모델(terra·sol) 교차 리뷰에서 나온 지적을 반영했다. 셋 다 실결함을 짚었고, 하나는 화면에서 재현됐다.

**접힘이 승인 CTA를 막는 컨트롤을 숨겼다 (실결함, 재현됨)** — 미선택 `TARGET` 에 제외 사유가 없으면 승인 CTA가 비활성인데(`listMissingExclusionReasons`), 그 사유를 넣는 유일한 컨트롤인 `사유 입력` 은 **그 자식 행 위**에 있다. 기본 접힘이 그 행을 `<tbody hidden>` 안에 넣었고, `hidden` 은 접근성 트리에서도 뺀다. 결과: 1006 에서 9건을 고르면 CTA 는 `제외 사유 미입력 1건: test_raw` 라고 이름까지 대면서, 그 `test_raw` 에는 **어느 그룹을 열어야 할지 추측하지 않으면 닿을 수 없었다**.

고친 방식은 **기본값을 파생시키는 것**이다 — 시드가 아니라. 열림 키 집합을 시드하면 최초 렌더에서 한 번 계산되는데, 그 시점엔 fetch 가 후보를 하나도 내려놓지 않았다. `useClusterFold`(다른 화면들이 이미 쓰는 훅)로 바꿔 **CTA를 막는 행을 가진 그룹은 스스로 열린다**. 셰브런은 여전히 이긴다 — 죽은 컨트롤이 접힌 그룹보다 나쁘다. 선택이 0건이면 CTA 는 "선택부터" 를 말하고 아직 사유를 빚지지 않으므로, **손대지 않은 표는 여전히 전부 접힌 채로 뜬다**(오너 규칙 유지).

**밴드가 열 의미를 잃었다** — 세 열을 아래로 훑으라고 만든 밴드인데 `role` 이 없어서, 스크린리더에는 라벨 세 개 뒤에 문자열이 흩어진 것으로 들렸다. 바깥 행이던 시절엔(잘못 걸려 있었어도) 연결이 있었으니 회귀다. `role="table"/"row"/"columnheader"/"cell"` 을 기존 div 에 얹었다 — 정렬은 헤더와 모든 줄이 공유하는 `LINE_GRID` 하나가 만들고, 진짜 `<table>` 은 그 폭 계산을 다시 짜야 한다.

**부수 효과가 테스트를 깨끗하게 만들었다**: 밴드를 `td.px-0` 클래스로 집던 것이 `getByRole('table', { name: '접속 인스턴스 목록' })` 이 됐고, codex 두 모델이 함께 짚은 AP-A2(`as HTMLElement`) 11곳이 사라졌다. 역할이 실제로 하중을 받는지는 `role="table"` 을 떼서 4개 테스트가 깨지는 것으로 확인했다.

**colSpan 드리프트 가드** — 밴드의 `colSpan` 은 호스트 표가 손으로 센다(7/6/6). 세 표 각각에 `<th>` 개수와 밴드 `colspan` 을 대조하는 테스트를 달고, 세 곳 모두 값을 바꿔 깨지는 것을 확인했다. `theme.ts` 가 "한 군데만 놓쳐도 열이 어긋난다"고 이미 경고하던 실패 양식이다.

**낡은 권위 주석 2건** — `theme.ts:group` 과 `resource-grouping.ts` 가 여전히 "부모는 열을 공유하는 REAL row 이고 colspan 은 없다" 고 적고 있었다. 지금 `ResourceGroupRow` 는 스패닝 셀 하나다. 다음 사람이 읽을 불변식을 현재 상태로 고쳤다.

**기각 1건**: `instance.port` 를 `typeof === 'number'` 로 좁히자는 지적. 현행 truthy 검사는 문자열 포트도 그대로 찍는데, 숫자로 좁히면 그 경우 **포트가 사라진다** — 지적대로 고치면 동작이 나빠진다. 템플릿 보간은 throw 하지 않는다.
