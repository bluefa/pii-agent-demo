## 구현 (PR #747, 커밋 2)

**경로 = h1.** 링크가 하나도 없으므로 브레드크럼(`<nav>`)이 아니라 **경로 모양의 제목**이다.
접근성 이름은 `PII Agent 설치 / {서비스명} / #{id}` 로 직무와 대상을 함께 말한다.

**바 = 스코프 전용.** `[브랜드 마크] {프로바이더}(+gloss) │ {계정 라벨} {계정 값} [서비스 코드]`

| 결정 | 값 | 출처 |
|---|---|---|
| 크럼 | `12px / #4E5968 / gap-1.5`, 이름 `max-w-[280px] truncate`+`title`, `#id` semibold `#191F28` | `opsStyles.crumb`/`crumbHere` |
| 프로바이더 마크 | `ProviderGlyph tone="brand"` **20px, 판 없음** | 운영 대시보드 `identityGlyphMark` (오너 지시 #4) |
| 계정 슬롯 | `min-w-0 truncate` + 네이티브 `title` | 벤치마크 공통 규칙 |
| 바 | `flex-nowrap` — 나머지 전부 `flex-none` | P5 재발 방지 |

### 시안과 다르게 간 세 가지

1. **`설치 모드` 칩을 바에 안 넣었다.** 목업엔 있었지만 오너 요구는 프로바이더·계정 둘이고,
   칩을 넣으면 1360에서 계정 슬롯이 132px(UUID 6자)로 잘린다. 칩은 접힘 안에 그대로 있다.
2. **계정 슬롯에 `max-w-[140px]` 상한을 두지 않았다.** 고정 상한은 1710px 화면에서도 UUID 를
   자른다. `min-w-0 truncate` 만 두면 **여유가 있으면 전부 찍고 없을 때만 줄인다** —
   실측 1710px에서 36자 전부, 744px 열에서 216px, 620px 열에서 92px, **어디서도 바는 40px**.
3. **접힘 블록에서 프로바이더 행을 뺐다.** 바가 프로바이더를 말하는데 블록이 같은 글리프와
   이름을 60px 아래에서 다시 말해서, 열자마자 중복이 보였다(구현 중 브라우저에서 발견).
   블록은 이제 **바가 못 하는 것만** 진다 — 복사 버튼(누름 안에는 버튼을 못 넣는다),
   두 번째 식별자(Azure Tenant ID), 설치 모드. 사실이 하나도 없으면(IDC) **그룹째 사라진다**.
   계정 값이 바와 블록에 두 번 나오는 것은 남겼다 — 블록 쪽이 **복사 가능한 기록**이라서.

### 진단 — 「약하다」가 가리킨 것

1차 카드는 **워시 위에 선만 그은 빈 사각형**이었다(`border-[#E1E4EB]`, 배경 없음, hover 에만 흰색).
같은 색 위에 같은 색을 두르면 물체가 아니라 필터 툴바로 읽힌다. 나머지 셋:

- 제일 큰 대비가 **내용이 아니라 컨트롤**이었다 — 오른쪽 끝 파란 `설치 대상 정보`
- **서비스 코드 칩만 면을 가져서** 면 없는 상자 안에서 칩이 더 단단해 보였다 (포함 관계 역전)
- 사실들이 전부 `gap-2` — 라벨↔값 거리와 사실↔사실 거리가 같아 네 토큰이 네 개의 동급으로 읽혔다

### 바꾼 것

| | 값 | 근거 |
|---|---|---|
| 면 | `bg-white` | 이 저장소가 이미 쓰는 조합(흰 면+선). 헤더에서 **유일한** 판 |
| 선 | `#D6DEEC` | 파랑 기운 중립 램프의 다음 칸. 저장소에 이미 있던 값 |
| 그림자 | `tossShadow.sm` | 이름 붙은 사다리의 첫 칸. hover 는 `md` 한 칸 더 |
| 경로 | **카드 안으로** | 8px 위에 맨몸으로 떠 있던 걸 들여놓은 것뿐 — 이게 두 계층을 **+5px** 에 산 방법 |
| 사실 간격 | 12px / 라벨↔값 6px | 아래 블록과 같은 1:2 |
| 코드 칩 | 삭제 | 코드가 경로로 올라가서 슬롯 자체가 빔 (5-c) |

**hover 는 그림자만 올린다.** 면을 틴트하면 카드 위 모든 계층이 새 바닥에 서게 되어
design-guard 의 고정 쌍을 전부 다시 재야 한다 — 한 칸 올리자는 지시에 그 비용은 과하다.

### Azure 2줄 → 클라우드 정보행 삭제 (지시 6)

식별자를 `grid-cols-[auto_1fr]` 로 깐다. **wrap 하는 flex 행이 아니라 그리드**인 이유:
`auto` 가 라벨 열을 제일 긴 라벨에 맞춰서 `Subscription ID` 와 `Tenant ID` 의 값이 같은 x 에서
시작한다. 두 줄이 **목록으로 읽히는지, 자리 모자라 접힌 줄로 읽히는지**가 여기서 갈린다.
행은 구조에서 나오므로 **식별자가 둘이라 두 줄**이지, 화면이 좁아서가 아니다.

그래서 접힘의 `클라우드 정보` 그룹이 사라졌다 — 값도 복사 버튼도 전부 카드에 있으니
같은 세 값을 60px 아래에서 다시 찍고 있을 뿐이었다. 접힘에 남은 것: **설명 · 설치 모드**
(SDU 는 연동 방식). 둘 다 설명 블록과 같은 문법의 독립 블록.

### 누름의 범위가 바뀌었다

**복사 버튼이 카드로 올라온 대가.** `<button>` 안에 `<button>` 은 못 넣으므로,
행 전체가 누름일 수는 없다. 디스클로저는 **제목 행 오른쪽의 `설치 대상 정보` 컨트롤**이 됐다.
행을 계속 누름으로 두려면 식별자에서 복사를 뺐어야 했고, 그건 카드가 유일한 출처가 된
지금은 기능 손실이다. 카드 전체 hover 는 그대로 살아 있다(그림자 상승).

### 라벨에서 보라를 뺐다 (지시 7-a)

두 라벨 층이 **색상 계열(hue)로** 갈리고 있었다 — `blockLabel` 라벤더 `#4C3F7A`,
`kvLabel` `#6B5E93`. 계층은 등급이지 계열이 아니므로, 카드의 흰 바닥에서
저장소가 이미 쓰는 중립 램프로 같은 말을 한다.

| 토큰 | 이전 | 지금 | 흰 바닥 명도비 |
|---|---|---|---|
| `blockLabel` (블록 눈썹) | `#4C3F7A` | **`#4E5968`** | **7.11:1** |
| `kvLabel` (필드 이름) | `#6B5E93` | **`#6B7684`** | **4.62:1** |

둘 다 4.5:1 통과, 두 층 간격 **1.54배**(라벤더 쌍은 1.59배였다). 브라우저 실측으로 확인했고
design-guard 가 두 쌍 모두 흰 바닥 기준으로 고정한다. hue 가 신호에서 빠졌으므로
`blockLabel` 의 `tracking-[0.02em]` 이 남은 두 번째 신호다 — 지우지 말 것.

### 설치 모드가 카드로 (지시 7-b)

자동/수동은 참고 자료가 아니라 **이 화면에서 할 일이 있는지를 가르는 값**이다.
접힘 뒤가 아니라 식별자와 같은 그리드의 **마지막 행**. 라벨 열을 공유하므로
`Account ID` 와 `설치 모드` 가 같은 x 에서 시작한다.

접힘에 남은 것: **설명**, 그리고 SDU 의 **연동 방식** 한 줄.

접힘 상태 헤더가 184 → 216 으로 **32px 늘었다**. 접힘의 목적(333→195)을 일부 되돌리는
값이고, 대가로 **접지 않아도 클라우드 사실 전부가 보인다** — 지시 4·6·7 이 요구한 것이 이것.

**되돌린 버그 하나**: `summaryFact` 에 `flex-none` 을 박았더니 `flex-shrink:0` 이 고정돼
옆에 붙인 `min-w-0` 이 무력화됐고, 520px 열에서 값이 잘리는 대신 **행이 카드를 넘쳤다**.
`flex-none` 은 이제 호출부에서 프로바이더 셀에만 붙인다. 테스트가 이 줄을 지킨다.

## 3차 라운드 — 로고가 이름이다 (2026-08-22, 커밋 4)

| 지시 | 내용 |
|---|---|
| 8-a | 「AWS Cloud」 표시 제거 |
| 8-b | 아이콘을 더 키워서 표시 |

### 진단

AWS 브랜드 마크는 심볼이 아니라 **워드마크**다 — 그림에 이미 "aws" 라고 쓰여 있다.
그 옆에 「AWS Cloud」를 찍는 건 이름을 두 번 쓴 것. Azure·GCP 의 마크는 워드마크는
아니지만 그 클라우드로 읽히는 브랜드 심볼이다.

반대로 **IDC(서버랙)·SDU(업로드 화살표)의 글리프는 우리가 그린 도형**이고 아무것도
지칭하지 않는다. 여기서 이름을 빼면 중복 제거가 아니라 프로바이더 삭제다.

### 규칙

> 마크가 벤더 로고면 이름을 화면에서 뺀다. 우리 글리프면 잉크로 남긴다.

`PROVIDER_DISPLAY` 에 `brandMark?: true` 한 칸. `CloudProviderIcon` 의 `BRAND_BY_KEY`
와 같은 집합(aws·azure·gcp)을 가리킨다.

**지우지 않고 감춘다** — 로고는 낭독되지 않으므로, 텍스트를 문서에서 아예 없애면 화면을
보지 않는 사용자에게 브랜드 클라우드 3종의 이름이 통째로 사라진다. `sr-only` 로 화면에서만
빼고 접근성 이름은 남긴다. 래퍼는 계속 `aria-hidden` (`ProviderGlyph` 에 aria prop 없음).

### 크기 — 20 → 28px

발명한 값이 아니라 `CloudProviderIcon` 자신의 `lg` 칸(`w-7 h-7`). 20px 은 ops 대시보드
식별 셀의 `md` 칸이었다.

`getBBox()` 실측 — AWS 워드마크의 잉크는 슬롯의 **0.598배**(Azure·GCP 는 0.80), 글자만
보면 **0.32배**다:

| 슬롯 | AWS 잉크 | 글자 |
|---|---|---|
| 20px (이전) | 12.0px | ~6.3px |
| 24px | 14.4px | ~7.6px |
| **28px (채택)** | **16.7px** | **~8.9px** |
| 32px | 19.1px | ~10.1px |

20px 에서 글자가 6px — 읽는 크기가 아니라 짐작하는 크기다. 마크가 프로바이더의 **유일한
이름**이 된 이상 이 상태로는 못 넘긴다. 24px 은 옆의 `Account ID` 라벨보다 작아 보여
주어로 안 읽혔고, 32px 은 2행 블록보다 커졌다. 28px 에서 멈춘다.

### 실측 (1710px 뷰포트, 접힘 상태)

| 대상 | 카드 20px | 카드 28px | 헤더 |
|---|---|---|---|
| AWS 1008 (식별자 1 + 모드) | 100px | **99.8px** | 216px 그대로 |
| Azure 1003 (식별자 2) | 102px | 그대로 | 218px 그대로 |
| GCP 1002 (식별자 1) | 73.8px | **77.8px** | 190 → **194** |
| IDC 1026 (식별자 0) | 70.8px | **77.8px** | 187 → **194** |

행이 2개 이상이면 글리프가 카드 높이를 못 건드린다. 1행 이하에서만 +4~7px 이고, 그 덕에
짧은 카드들이 77.8px 로 수렴한다. 구분선은 `self-stretch` 라 글리프 높이(28px)를 따라간다.

### 뮤테이션 검증

| 뮤테이션 | 깨지는 테스트 |
|---|---|
| 항상 `providerName` (감춤 제거) | `lets a branded logo be the provider name…` 1건 |
| 항상 `sr-only` (전부 감춤) | IDC·SDU 잉크 2건 + 한 줄 정렬 1건 |

## 미착수 / 기각

- **E(우선순위 강등)** 기각 — 데스크톱 전용에서 `ResizeObserver` 가 버는 값이 새 메커니즘 값을 못 넘는다.
- **P1(좌 레일 ↔ 경로의 서비스명 중복)** 미해결 — C 가 감수한 비용. 지우려면 레일 쪽을 건드려야 한다.
- **접힘이 설명 하나뿐인 대상이 있다** — `installMode` 가 없으면(예: Azure 1003) 「설치 대상 정보」
  뒤에 설명만 남는다. 라벨을 바꿀지 접힘을 없앨지는 별도 판단.
- **P7(가이드 레일 Agent 알약 AA 미달)** 미수정 — 이 PR 범위 밖, 별도 지시 필요.
- **`ProjectPageMeta` 의 SDU 분기는 여전히 도달 불가** — `ProjectDetail` 이 `SduUnsupportedNotice` 로
  먼저 가른다. 테스트만 그 경로를 지킨다.
