- **날짜**: 2026-08-14
- **대상 화면**: `/pass/admin/pipelines` (`app/admin/pipelines/page.tsx`)
- **진단 기준**: main `aaee6da0` 코드 정독 + mock dev 실행 화면 1710×1100 브라우저 실측
- **아티팩트**: https://claude.ai/code/artifact/73e66edf-090c-4c05-a312-37d0a733ec39
  (진단 12건 · 레퍼런스 13종 · 바닥 후보 9종 실측 · 개선안 6안 전문)

## 1. 오너가 말한 것

> "색감이 너무 쎄기만 하고 강조될게 강조되지 않은 느낌입니다.
> 그리고 너무 흰 바탕에 흰 카드가 반복되어서 계층이 전혀 안 보여요."

두 문장은 서로 다른 문제가 아니다. **화면이 계층을 명도가 아니라 색상에 맡겼기 때문에**
명도는 평평해지고 색은 과잉이 됐다.

리뷰 과정에서 오너가 세 가지를 더 지시했고, 전부 이 PR 에 들어 있다.

> "PENDING, RUNNING, FAILED, SUCCESS, CANCELD 해당 용어를 모두 한국어로 바꿔줘.
> 그리고 색상이 강하지 않게 표현도 바꿔봐."
> "대상 정보는 다음과 같이 계층을 바꾸자. CSP 아이콘을 좌측에 배치해.
> TargetSource #1023 (코드: IRP) → 태그로 약간 강조해도 됨. 서비스 이름은 아래로 배치.
> 서비스 이름은 12 픽셀로 바꾸고 회색으로 적용해줘." · "분 → 12픽셀로 낮춰"
> "Hover는 서비스 목록 선택시에 보라색으로 표현한 색상을 적용해봐. 명도비만 잘 맞춰봐"

## 2. 실측 (브라우저, `getComputedStyle` + WCAG 상대휘도)

랜딩 상태에서 표면이 일곱 번 바뀌는데 전부 한 대역 안에 있었다.

| 층 | 값 | 아래 층과의 대비 |
|---|---|---|
| ① 페이지 바닥 | `#F9FAFB` | — |
| ② 버킷 타일 idle | `#F2F4F7` | 1.05:1 |
| ③ 목록 카드 | `#FFFFFF` | 1.05:1 |
| ④ 필터 바 | `#F9FAFB` | 1.05:1 |
| ⑤ 표 헤더 밴드 | `#F9FAFB` | 1.00:1 |
| ⑥ 행 | `#FFFFFF` | 1.05:1 |
| ⑦ 행 hover | `#F2F4F7` | 1.10:1 |

카드를 카드로 만드는 유일한 것은 1px `#E4E7EC` 테두리(바닥 대비 **1.19:1**)와
알파 5% 그림자였다. `/design-guide` §3 은 *"인접 계층은 레버 2개 이상 차이 —
1px 차이는 계층이 아니라 오차"* 라고 못 박는데, 바닥→카드는 레버가 **0.5개**였다.

## 3. 기각한 답 — 바닥 내리기 (시안 B)

첫 제안은 형제 화면(`서비스·대상 검색`)의 `serviceListStyles.split` 을 그대로 가져와
바닥을 `--pl-gray-100` 으로 내리는 것이었다. **오너가 즉시 반려했다** — 그래도 흰 위 흰이다.

맞는 지적이었고, 숫자가 그렇게 말한다: **1.05 → 1.10:1.** 여전히 오차 대역이다.
그래서 바닥 후보 9종을 같은 마크업으로 나란히 렌더해 어디서 카드가 "카드"로 읽히기
시작하는지 실측했다(아티팩트 §03).

| 후보 | 바닥 | 대비 | 판정 |
|---|---|---|---|
| ① | `#F9FAFB` (현행) | 1.05 | 경계 안 보임 |
| ② | `--pl-gray-100` | 1.10 | **찾아야 보임 — 첫 제안이 틀린 자리** |
| ③ | `--pl-gray-200` | 1.24 | 면은 읽히나 테두리 소실(§3.1) |
| ⑦ | `--pl-gray-200` + border-strong + shadow-md | 1.24 | 읽힘 |
| ⑧ | 카드 없음 | — | **계층 문제 자체가 없어진다** |

### 3.1 gray-200 바닥이 부르는 함정

`--pl-border` 와 `--pl-gray-200` 은 **둘 다 `#E4E7EC`, byte-identical** 이다.
바닥을 gray-200 으로 내리는 순간 카드 테두리가 바닥과 같은 색이 되어 **1.000:1 로 소실된다.**
코드 칩이 행 hover 틴트와 byte-identical 이라 사라졌던 PR #700 과 같은 병이고,
`bucketTileIdle` 의 hover 도 gray-200 이라 같이 죽는다.

## 4. 채택안: 시안 B′ — 카드를 없앤다

바닥을 더 내리는 대신 **구분해야 할 표면을 만들지 않는다.**
이 페이지의 카드 안에는 목록 말고 들어 있는 게 없었다 — 카드가 묶고 있는 것이 자기 자신뿐이다.

| 변경 | before | after |
|---|---|---|
| 목록 카드 | `card.flush` (흰 면 + 1px `--pl-border` + r12 + shadow-xs) | **삭제** — `dashboard.listBlock` (`-mx-5`) |
| 페이지 바닥 | `--pl-bg-page` `#F9FAFB` | `dashboard.bleed` — 이 라우트에만 `--pl-bg-card` |
| 표 헤더 | `bg-gray-50` + 1px `--pl-border` 밑선 | 면 없음 + **2px `--pl-text-strong` 밑선** |
| 필터 바 | `bg-gray-50` + 1px gray-100 밑선 | 면·선 없음 |
| 버킷 타일 idle | `bg-gray-100`, 투명 테두리 | 흰 면 + `--pl-border-strong` (흰 바탕 대비 **1.41:1**) |
| 버킷 타일 active | 브랜드 스트로크만 | 브랜드 스트로크 + `--pl-shadow-sm` |

표면 **7겹 → 2겹**(페이지 · 행 hover)이 됐고, 남은 경계는 전부 선이 진다.

### 왜 값을 이렇게 골랐나

- **바닥은 `--pl-bg-card`(흰색), `--pl-bg-page` 를 물들이지 않는다.** 그 토큰은 섹션의 것이고,
  운영 알림 요약 타일이 거기서 바로 읽는다. `serviceListStyles.split` 과 같은
  네거티브 마진 탈출로 이 라우트에만 칠한다 — 같은 사고가 그 파일 주석에 기록돼 있다.
- **`listBlock: -mx-5`** — 카드 안에서 px-5 는 카드 모서리에서 잰 값이었다. 카드가 없으면
  행이 위쪽 요소들보다 20px 안으로 들어간다. 20px 을 되돌리면 표 첫 열이 h1·타일과 같은
  세로선에 서고, 행 hover 틴트는 양쪽으로 20px 씩 글자 밖으로 번진다.
- **2px `--pl-text-strong` 헤드 룰** — 카드가 없으면 표에는 "여기서 시작한다"고 말하는
  선이 하나 필요한데, 1px `#E4E7EC`(흰 바탕 1.19:1)는 카드 테두리가 내던 그 속삭임과 같다.
  2px 잉크 룰은 아홉 개의 divider 중 하나가 아니라 **표의 머리**로 읽힌다.
- **타일은 흰 면 + `--pl-border-strong`** — 흰 바닥에서 gray-100 면은 1.05:1 이라
  숫자만 떠 있게 된다. 같은 화면 두 블록 아래 `identityCode` 가 정확히 같은 이유로
  쓰는 "흰 면 + stroke" 를 그대로 쓴다(PR #700, 오너 지시).
- **active 에 shadow-sm** — idle 도 흰 면이 되면서 선택/비선택이 테두리 색 하나로만
  갈리게 됐다. `/design-guide` §3 의 레버 2개를 맞추는 두 번째 채널.

### 건드리지 않은 것

행 hover(`--pl-gray-100`)·divider·`identityCode`·`stripRest` 는 전부 **흰 면 위에서
측정된 값**이고, 바닥을 흰색으로 두었으므로 그 측정이 그대로 유효하다. 바닥을 회색으로
내렸다면 넷 다 다시 골라야 했다 — 이것이 ⑧을 ⑦보다 싸게 만드는 실제 이유다.

## 5. 색 예산 — 오너 판정 뒤집힘

표 안 채도 면적 3,598px² 의 배분은 **초록 62 : 빨강 25 : 파랑 13** 이었다. 가장 큰 색이
"이미 끝난 단계"였고, 가장 조치가 필요한 실패가 그 절반이었다.

`theme.ts` `progress` 주석에 기록된 판정은 *"완료된건 초록색, 현재 진행중인건 파란색"* 이었고,
근거는 *"세 상태가 110px 안에 나란히 붙는데 12px 블록 셋을 명도만으로 구분할 수는 없다"* 였다.
**그 근거는 실행 중인 행에서만 성립한다** — 3/3 완료 행에는 나란히 붙는 다른 상태가 없다.
오너가 판정을 뒤집었다("색상이 강하지 않게").

| 대상 | before | after |
|---|---|---|
| 세그먼트 완료 칸 | `--pl-ok` 초록 | `--pl-gray-400` (CANCELLED 칸이 이미 쓰던 값) |
| 세그먼트 진행 칸 | `--pl-info` 원색 | `--pl-info-text` (6px 블록에선 깊은 쪽이 조용하다) |
| 세그먼트 실패 칸 | `--pl-err` | 유지 — 찾아내야 하는 유일한 칸 |
| 상태 텍스트 | 파랑·초록·빨강 5색 | **실패만 색상**, 실행 중 medium, 나머지 weak (등급 3개) |
| 작업 유형 아이콘 | 파랑·빨강·보라 틴트 | 라벨 색 상속 (`ProvTag` 문법) — DELETE 빨강이 실패 빨강과 충돌했다 |
| 종료 버킷 마크 | `--pl-ok-text` 초록 | `--pl-text-weak` |

`segTone` 의 CANCELLED 분기는 함께 사라졌다 — 초록을 막으려고 있던 분기라, 초록이 없으면
막을 것이 없다. 새 불변식은 테스트로 고정했다: **한 스트립에 색칠된 칸은 최대 하나**
(`PipelineStepStrip.test.tsx` "never colours more than the one step the run is on").

## 6. 한국어 라벨 · 대상 셀 계층 · hover

- **상태 용어**는 공용 `statusKo` 한 벌을 쓴다(대기 / 실행 중 / 완료 / 실패 / 중단).
  새로 만들지 않았다 — `lib/pipeline/format.ts` 에 이미 있던 맵이다. 행·필터 메뉴·필터 칩
  세 곳이 같은 이름을 부른다. (오너가 말한 `SUCCESS` 는 이 계약에서 `DONE`,
  `CANCELD` 는 `CANCELLED` 다.)
- **대상 셀**: CSP 글리프가 왼쪽에 한 번(두 줄에 걸쳐), 1행이 `TargetSource #1023` +
  `코드: IRP`, 2행이 서비스 이름 12px 회색. 식별자를 위로 올린 이유는 **서비스 이름이
  행을 구별해 주지 못하기 때문**이다 — mock 한 페이지에 "PII Agent 설치 - 고객 DB" 가
  세 번 나온다. 1행의 태그는 발명이 아니라 코드 칩이 쓰던 흰 면 + stroke 를 그대로 물려받은
  것이다(PR #700, 오너 지시). 글리프 슬롯은 폭을 고정한다 — `ProviderGlyph` 가 UNKNOWN 에서
  null 이라 그대로 두면 마크 없는 행만 열이 어긋난다.
- **생성시간 12px** (오너) — 14px 일 때 식별자 태그와 같은 등급으로 읽혔다.
- **hover 는 보라**: 앱의 카드 행이 쓰는 `hoverStyles.card` 값을 `--pl-row-hover` 로 옮겼다.
  중립 틴트는 명도로만 갈라져야 해서 gray-50 은 1.03:1, gray-100 도 1.10:1 이었다.
  다만 **원값 `#F3EEFF` 는 쓸 수 없었다** — 이 표의 조용한 층인 `--pl-text-weak` 가 그 위에서
  **4.379:1**, AA 미달이고 그런 텍스트가 세 줄(이름·코드·캡션)에 시간까지 넷이다.
  두 칸 밝은 **`#F6F3FF`** 에서 4.544:1 이 된다. 흰 행과의 대비를 0.04 내주지만,
  이 틴트의 분리는 애초에 명도에서 오지 않았다.

실측(브라우저): text-weak 4.54 · text-medium 9.56 · err-text 6.01 · info-text 5.47 — 전부 AA 위.

## 7. 남은 것 / 감수한 것

- **이 화면만 섹션에서 바닥 UI 가 된다.** 나머지 admin 화면은 전부 카드를 쓴다.
  `pipelines-dashboard.md` 가 진단한 근본 원인이 "이 화면만 혼자 쓰는 문법"이었으므로,
  **방향만 바꿔 같은 병을 되풀이할 위험을 오너가 알고 택한 것**이다.
  `/design-guide` 여백 7원칙 §6 (*"확신이 없으면 카드로 감싸라"*)과도 어긋난다.
  섹션 전체를 바닥 UI 로 옮길 생각이 있다면 이 화면이 그 출발점이다.

## 8. 리뷰 반영 (같은 세션, 2026-08-14)

라이브 화면을 보며 오너가 준 지시들. 앞 절의 결정을 일부 조정한다.

| 지시 | 반영 |
|---|---|
| "Target 으로 바꿔. target 계층을 낮추자. 12픽셀" | `TargetSource` → `Target`, 라벨은 12px 문맥으로 |
| "태그 디자인이 조금 갑갑하다. tag 없애봐" | `identityTag` 삭제 — 1행이 전부 맨 텍스트가 됐다 |
| "코드의 계층은 그대로 두되 값 IRP 는 계층 높여. 14픽셀 semi bold" | `identityCodeValue` 14/600 |
| "1002는 2픽셀 더 키워. 그리고 semi bold" | `identityTargetValue` 14/600 |
| "csp 아이콘은 20x20으로 키워" | `identityGlyphMark` — 공용 `provTag.glyph`(14px)는 라벨 옆 크기라 건드리지 않고 이 셀만 |
| "완료는 초록색으로 표현해" | `statusTextTone.DONE` → `--pl-ok-text` |
| "중단은 옆에 정지 아이콘" | `StatusText` 가 CANCELLED 에만 `stop` 마크 |

결과적으로 1행은 **라벨·값 쌍 둘**이 됐다 — `Target #`/`1002`, `코드:`/`GCP`.
라벨은 12px 문맥, 값만 14/600 으로 올라선다. 라벨까지 올라오면 한 줄에 강조가 넷이 되어
아무것도 강조되지 않는다(테스트로 고정).

**초록이 상태 낱말에는 돌아왔다.** §5 에서 뺀 초록은 세그먼트의 초록이고 이건 낱말 하나다 —
같은 색을 면적이 다른 두 자리에 쓰는 것이라, 하나를 뺐다고 다른 하나가 따라 빠질 이유는 없다.
세그먼트는 여전히 중립이다.

**중단은 색 대신 마크를 받는다.** 완료와 같은 "끝난 상태"인데 초록을 주면 성공했다고 말하게
되고, 회색만 주면 대기와 구별되지 않는다. 색을 셋째로 늘리지 않고 채널을 하나 더 열었다.

실측(브라우저): 완료 초록 흰 행 5.41:1 · hover 4.94:1 · Target 번호 14/600 · 글리프 20×20.

## 9. CSP 마크에 브랜드 색 (2026-08-14)

> "CSP아이콘에 색상을 입혀볼까? CSP 아이콘은 눈에 띄긴 해야 될듯. 실제 색상이 있는 csp 아이콘을 구해와서 적용해줘."

`ProviderGlyph` 의 원래 주석은 브랜드 fill 을 **의도적으로** 거부하고 있었다 —
"색 타일은 글리프보다 정보를 더 주지 않으면서 페이지의 색 하나를 잡아먹는다."
그 전제가 §5 에서 바뀌었다. 상태 색을 페이지당 낱말 둘로 줄여 놓았으니 색 예산이 남았고,
무엇보다 **로고는 상태 채널을 잠식하지 않는다** — 실행이 어떻게 되어가는지에 대해
아무 말도 하지 않기 때문이다. 브랜드 색이 사는 자리는 판정이 아니라 인식이다.

- **opt-in 으로 열었다.** `ProviderGlyph` 에 `tone?: 'mono' | 'brand'` 를 두고 기본은
  `mono` 그대로. 이 대시보드만 `tone="brand"` 를 넘긴다. 공용 글리프를 통째로 뒤집으면
  ProvTag·ProviderLogo·CandidateCard·ProviderGlyphTile·target-source 상세까지 8개 화면이
  한 번에 바뀐다 — 그건 이 요청의 범위가 아니다.
- **IDC·SDU 는 회색 그대로.** 우리 것이라 브랜드가 없다. 없는 브랜드를 지어내지 않는다.
- **색 출처**: 각 벤더의 공개 SVG. AWS 는 이미 이 파일에 있던 Simple Icons 경로를
  절대좌표 subpath 경계에서 워드마크(`#252F3E`)와 스마일(`#FF9900`)로 쪼갠 것이라
  기하는 그대로다. Azure 의 그라디언트는 중점 단색으로 폈다 — 20px 에서 그라디언트는
  보이지 않고, 인라인 `<linearGradient>` 는 문서 유일 id 가 필요한데 같은 마크가
  열두 행에 반복되면 그럴 수가 없다.
- **대비 규칙 밖이다.** 로고타입은 WCAG 1.4.11 면제라 design-guard 가 잴 것이 없다.
  `pr-check` 의 raw-hex 는 걸리는 게 맞다 — 이 파일은 이미 브랜드 hex 를 갖고 있었고
  `design-exempt` 주석으로 표시한다.

**viewBox 는 프레임이 아니라 패딩이다.** 세 마크의 종횡비가 셋 다 달라서 같은 정사각
슬롯에 넣으면 광학 크기가 셋으로 갈린다. Azure 박스를 키워 잉크 높이를 구글 클라우드에
맞췄고(실측 16.0 vs 16.1px), AWS 로고타입은 슬롯 폭 전체를 쓴다 — 원래 가로로 긴 마크라
높이를 심볼에 맞추면 슬롯을 넘는다.

테스트는 브랜드 hex 값을 세지 않고 **다색 경로가 유지되는지**를 센다(AWS 2 · GCP 4 ·
Azure 3, IDC/SDU 0). mono 로 되돌아가면 0 이 되어 깨진다.

## 10. 기본 12px 한 단, 강조만 14px (2026-08-14)

> "기본 픽셀을 12로 모두 수정해봐. 그리고 내가 아까 강조하라고 한 것만 14로 수정"
> "실행중 -> 파란색으로 바꿔봐."
> "실패 행의 왼쪽에 빨간색 띠가 표현되네요. 이 부분 삭제"

**타이포 단이 둘로 줄었다.** 화면에서 실측한 크기가 11·12·13·14 네 단이었고,
그중 셋이 서로 1px 차이라 단이 아니라 흔들림으로 읽혔다. 전부 12 로 모으고,
오너가 강조를 지시했던 **값 둘(`Target #` 번호, `코드:` 값)만 14/600** 으로 남겼다.
h1 24px 과 타일 숫자 32px 은 건드리지 않았다 — "기본"이 아니라 display 단이다.

| 대상 | 전 | 후 | 비고 |
|---|---|---|---|
| 범위 토글(1시간/24시간/7일) | 14 | 12 | `dashboard.periodSeg` |
| 버킷 타일 라벨 | 14 | 12 | `bucketLabel` |
| 검색 입력 | 14 | 12 | `searchBox.inputLg` — `lg` 소비자는 이 페이지뿐 |
| 상태 낱말 | 13 | 12 | `statusText` |
| 진행도 캡션 | 11 | 12 | `progress.stripCaption` |
| 페이저·잘림 안내·빈 상태 | 14 | 12 | `pagerCount` / `pagerTruncated` / `empty` / `stateBox` |
| Target 번호 · 코드 값 | 14 | **14** | 유지 (§8) |

**공용 컴포넌트는 두 갈래로 갈렸다.** `SearchBox` 의 `lg` 변형은 소비자가 이 페이지
하나뿐이라 값을 바로 내렸다. `SegControl` 은 TC 결과 목록과 공유하므로 그쪽 스케일을
지켜야 해서, 크기를 **컨테이너에서 자손 선택자로** 준다(`[&_button]:text-[12px]`).
클래스를 넘기는 방식은 쓸 수 없다 — `seg.button` 이 이미 자기 크기를 선언하고 있고
`cn` 은 단순 join 이라 같은 속성이 둘이면 CSS 출력 순서가 승자를 정한다.

**훅이 잡아낸 선존 위반 3건.** 12px 로 내리며 건드린 `pagerTruncated`·`empty`·`stateBox`
가 `--pl-text-faint`(#98A2B3, 흰 바닥 2.58:1) 를 쓰고 있었다. 14px 때부터 AA 미달이었고
줄을 만진 김에 `--pl-text-weak`(4.97:1) 로 올렸다. design-guard 에 세 쌍 추가.

**실행 중 = 파랑(오너).** `--pl-info-text` — 스트립의 진행 칸과 **같은 토큰**이다.
한 행에서 "지금 여기"를 말하는 두 자리가 다른 파랑을 쓰면 같은 뜻으로 읽히지 않는다.
이로써 색을 받는 상태는 셋(실행 중·완료·실패), 색이 없는 것은 아직/이제 아무 일도
일어나지 않는 둘(대기·중단)이다. §5 의 "끝난 두 상태에만"은 여기서 만료됐다.
실측 파랑 흰 행 5.99:1 · hover 5.47:1.

**실패 레일 삭제(오너).** 3px 열이 통째로 없어지면서 딸린 것들도 같이 나갔다 —
`railCell`·`railErr`·`thBand`(레일 th 전용 헤드룰), 그리고 **`table` 의 `-ml-[3px]`**.
그 -3px 은 레일 폭을 되돌리려고 있던 것이라, 레일만 지우고 두면 표 전체가 3px 왼쪽으로
밀린다. 삭제 후 재실측: h1 248 · 행 글리프 248 로 그대로 붙어 있다.
실패는 이제 낱말 빨강 + 세그먼트 빨강 두 채널로 남는다.
