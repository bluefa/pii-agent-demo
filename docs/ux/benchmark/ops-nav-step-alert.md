## 문제 진단

브라우저 실측(headless Chrome)으로 잡은 것만 적는다. 대비는 계산이 아니라 `getComputedStyle` 로
실제 칠해진 값을 읽어 잰 것이다.

| # | 문제 | 근거 등급 | 증거 |
|---|------|-----------|------|
| P1 | 탭이 스트립의 절반쯤만 쓰고 나머지는 빈 띠다 | 수치 | 탭 폭은 **717.7px(8탭) / 665.9px(7탭)** 두 값으로 **고정**이고 남는 폭은 뷰포트를 따라 늘기만 한다 — 아티팩트의 뷰포트 스윕에서 점유율 **41.4~54.7%**(아래 실측 부록은 좁은 쪽 1440 까지 포함해 다시 잰 값이다). 빈 곳이 늘어날수록 띠는 무엇도 담지 않은 채 길어진다 |
| P2 | 띠를 만드는 두 선이 거의 안 보인다 | 수치 위반 | `--pl-border-strong` 은 워시 위 **1.34:1** — 그래픽 기준 3:1 의 **45%** 다. 선 두 개 사이가 띠라는 문법 전체가 이 대비 위에 서 있었다 |
| P3 | 탭과 마스트헤드의 사실이 **같은 활자**로 선다 | UX 원칙 (계층은 포함) | 탭 14/600, `fmLabel` 14/600. 크롬은 본문보다 두 단 아래여야 하는데([[reference_linear_design]]) 활자 신호가 0 이다 |
| P4 | 묶음이 셋인데 그 사실을 **간격 하나**가 진다 | 수치 | 그룹 안 `gap-1` = 4px, 그룹 사이 = 22px(4 + `tabGap` 14 + 4). 5.5배 차이가 나도 같은 종류의 신호(빈 칸)라, 눈은 "간격이 좀 넓네"까지만 읽는다 |
| P5 | 스페이서 `<span>` 이 `role="tablist"` 안에 산다 | 구조 | 묶음이 마크업에 **탭과 같은 층위**로 들어가 있었다. 그룹이 개념이면 개념의 상자가 있어야 한다 |
| P6 | **일이 남은 대상과 끝난 대상의 탭 줄이 똑같다** | 관측된 결함 | AWS #1010(INSTALLED — 사람이 할 일이 「연결 테스트」 안에 있다)과 #1012(COMPLETED)를 나란히 열면 탭 줄의 마크가 **둘 다 0개**다. 화면은 이미 `processStatus` 를 들고 있으면서 그것을 탭 줄에 한 글자도 쓰지 않았다 |
| P7 | 있는 마크조차 스크린 리더에 안 들린다 | 접근성 | `tabDot` 이 `aria-hidden` 이고 뒤에 낱말이 없다 — 「연결 테스트 실패」가 **0바이트**로 도착한다 |

## 채택안과 이유

**시안 A — 구간 헤어라인.** 아래 선을 그룹마다 따로 긋는다. 선이 그룹 사이 22px 에서 **끊긴다**.
위 선은 통으로 남아 띠의 천장을 진다.

**시안 E — 두 번째 마크.** 밑줄 하나가 두 채널을 지고 있던 것을 둘로 나눈다. 파랑은 "지금 열린
패널", 두 번째 마크는 "지금 일이 걸린 단계".

비교표는 아티팩트 §06 에 있다. 이 조합이 이긴 자리는 표의 점수가 아니라 **비용이 0인 축 넷**이다.

| 축 | 값 |
|----|-----|
| 새 API 요청 | **0** — `processStatus` 는 이미 `OpsTargetView` 가 들고 있다 |
| 새 색 토큰 | **0** — `--pl-current`·`--pl-err-solid` 둘 다 이 콘솔이 이미 쓴다 |
| 새 활자 크기 | **0** — 탭은 14/600 그대로다 |
| 기각 판례 저촉 | **0** — 밴드·카드·full-bleed·배지·16px 탭 어느 것도 건드리지 않는다 |

P4 를 색이나 라벨이 아니라 **선의 단절**로 푼 것이 핵심이다. 이 탭 줄에서 칠은 전부 기각당했고
(아래 표), 남은 재료는 이미 거기 있던 선 하나였다. 선을 더하지 않고 끊었다.

## 오너가 뒤집은 것 — 밑줄 → 우상단 코너 점

같은 날 오너 지시:

> "보라색 밑줄 말고 **확인 필요처럼 보이는** 시각적 요소를 써볼까? **우상단의 빨간색 점**은 어때?"

빨강 전면 도입에 반대한 근거 둘을 그대로 남긴다 — 이 둘이 결론을 좁혔기 때문이다.

- **(a) 빨강에는 이미 임자가 있다.** `tabDotFail` 이 「연결 테스트」 라벨 옆에서 최신 실행 실패를
  말한다. 같은 색이 같은 줄에서 두 가지를 뜻하면 색이 아무것도 안 뜻하게 된다.
- **(b) 모든 대상은 늘 어떤 단계엔가 있다.** 걸렸다는 사실 전체를 빨강으로 칠하면 이 콘솔에서
  빨강이 **상시** 켜진다 — R2 의 "정상은 신호가 아니다"를 정면으로 어긴다.

오너가 두 근거를 받아 **「빨강은 관리자 차례(CONNECTED)에만」** 으로 좁혔다. 6단계만 관리자가
실제로 막혀 있는 자리이고, 나머지 단계는 다른 누군가의 차례이거나 파이프라인이 도는 중이다.

밑줄을 코너로 옮기면서 **겹침 규칙이 통째로 사라졌다.** 밑줄이었을 때는 파랑과 같은 자리를 다퉈
"열린 탭 == 걸린 탭이면 파랑이 이기고 보라가 8px 점으로 물러난다"가 필요했다. 코너는 자리가
달라서 두 사실이 서로를 덮지 않는다 — `tabDotStep` 토큰과 그 분기, 그리고 그것 때문에 존재하던
단계 탭의 슬롯 예약이 함께 삭제됐다.

그래서 「연결 테스트」는 이제 **두 마크를 동시에** 들 수 있다.

| 자리 | 마크 | 뜻 |
|------|------|-----|
| 라벨 옆 (인라인, 흐름 안) | `tabDot` + `tabDotFail`/`tabDotRunning` | 최신 실행이 실패했다 / 아직 열려 있다 |
| 우상단 (코너, 흐름 밖) | `tabCorner` + `tabCornerAlert`/`tabCornerStep` | 지금 단계가 여기 걸려 있다 |

색이 아니라 **자리**가 두 사실을 가른다. 인라인 점은 흐름 안이라 `opacity` 로 슬롯을 예약해야
하고(R1), 코너 점은 `absolute` 라 예약이 필요 없다.

## Step → 탭 매핑

| ProcessStatus | 단계 | 탭 | 코너 점 |
|---|---|---|---|
| `IDLE` | 1 · 연동 대상 DB 선택 | — | **없음** |
| `PENDING` | 2 · 연동 대상 승인 대기 | 연동 요청 정보 | 보라 `--pl-current` |
| `CONFIRMING` | 3 · 연동 대상 반영중 | 확정 정보 | 보라 |
| `CONFIRMED` | 4 · Agent 설치 | 인프라 작업 | 보라 |
| `INSTALLED` | 5 · 연결 테스트 | 연결 테스트 | 보라 |
| `CONNECTED` | 6 · 관리자 승인 대기 | 관리자 승인 | **빨강 `--pl-err-solid`** |
| `COMPLETED` | 7 · 완료 | — | **없음** |

**1·7단계를 억지로 붙이지 않는 이유.** 1단계는 담당자가 아직 사용자 Step1 화면에서 DB 를 고르는
중이라 「스캔」도 「연동 요청 정보」도 이 콘솔의 사실이 아니다. 7단계는 대응하는 탭이 아예 없다.
없는 자리를 가장 가까운 탭으로 반올림하면 마크가 매번 거짓말을 한다 — 그리고 그 순간 P6 이
"마크가 없다"에서 "마크가 틀렸다"로 나빠진다.

## 접근성

점·밑줄은 계속 `aria-hidden` 이되, **낱말이 따로 실린다**(P7).

- 빨강 → `확인 필요 — 6단계 · 관리자 승인 대기`
- 보라 → `현재 5단계 · 연결 테스트`
- TC 점 → `최근 실행 실패` / `최근 실행 진행 중`
- 한 탭에 둘 다 걸리면 **둘 다** 실린다

CDP AX 트리 실측 접근명: `연결 테스트 , 최근 실행 실패, 현재 5단계 · 연결 테스트`.
같은 문장이 `title` 로도 붙어 마우스 사용자에게 hover 툴팁이 된다.

## design-guard

토큰 이름으로 해석하는 테스트라, 키가 사라지면 `key ... not found` 로 던진다.

| 라운드 | 제거 | 추가 |
|--------|------|------|
| 시안 E (밑줄) | — | `tabStep` 밑줄(TEXT, `min: 3`) · `tabStep` 잉크(TEXT) · `tabDotStep`(TEXT, `min: 3`) |
| 코너 점 | 위 세 쌍 | `tabCornerAlert`(TEXT, `min: 3` → **4.38**) · `tabCornerStep`(TEXT, `min: 3` → **4.50**) |

두 쌍 모두 **SURFACES 가 아니라 TEXT** 에 있다. SURFACES 는 ΔE00 을 재고 TEXT 가 대비를 재는데,
8px 점이 워시에서 견디는지는 ΔE00 이 아니라 대비의 문제다 — 과거에 SURFACES 에 넣었더니
`--pl-info`(2.94)로 뮤테이션해도 199개 테스트가 전부 초록이었던 전례가 있다.
두 쌍 다 뮤테이션(`--pl-err-bg`/`--pl-current-bg`)으로 실제로 죽는 것을 확인했다.

**기하**

- 그룹 갭 **22px**(두 곳). `tabGap` 토큰 값은 14 였지만 `gap-1` 이 양쪽에 붙어 실제 거리는
  4+14+4 였다 — 시안 A 는 이 거리를 바꾸지 않으므로 `gap-[22px]` 로 옮겼다.
- 코너 점 인셋 `top+4 right+4`. 스트립 top 224, 점 top 229 → 위 헤어라인에서 **4px** 떨어져
  잘리지 않는다.
- 탭 x 좌표는 대상·마크 조합·클릭 전후에 **한 번도 움직이지 않는다**:
  `248 / 326.61 / 378.38 / 483.83 / 580.44 / 670.92 / 793.41 / 883.89`

| 라벨 바닥 → 첫 사실 | 21px | **28px** |
| 마스트헤드 높이 (AWS 1011) | 202.59 | **211.98** |
| 마스트헤드 높이 (Azure 1801) | 202.59 | **211.98** |
| 마스트헤드 높이 (IDC 1025) | 202.59 | **211.98** |

- **프로바이더 셋이 전부 같다.** kv 그리드가 4열이라 AWS 4칸·Azure 4칸·IDC 2칸이 **항상 1행**에
  앉는다(`gridTemplateRows: "42px"`). 칸 수는 폭만 먹고 높이를 안 바꾼다.
- **요청은 "+8px" 이었으나 실제는 +7px.** 옛 21px 안에 헤어라인 1px 이 들어 있었기 때문이다
  (전 = `pb-1.5` 6 + border 1 + `pt-3.5` 14, 후 = 6 + 0 + 22). 정확히 +8 이려면 `pt-[23px]`.
  **22px 유지는 오너 미결.**
- `fmGlyph` 는 20px 그대로 두었다. 라벨과 수직 중심이 0.01px 차이로 맞고, 다만 관계가 뒤집혔다 —
  전엔 마크 상자(20)가 라벨 줄(19.59)보다 컸는데 이제 라벨 줄(22.39)이 더 크다. 이름이 마크를
  이끄는 쪽이라 위계로는 오히려 맞는다. **관측만 하고 안 고쳤다.**

## 미해결

**① `getProcessStatus` 가 AWS 에서 IDLE 만 준다면 코너 점은 주 트래픽에서 안 켜진다 — BE 확인 필요**

`docs/swagger/install-v1.yaml:4655` 이 이렇게 적는다:

> "Azure와 GCP TargetSource는 설치 진행 상태를 계산하고, **AWS, SDU, IDC TargetSource는 IDLE
> 상태를 반환합니다.**"

사실이면 코너 점은 AWS·IDC 대상에서 영원히 안 켜진다. 그리고 그건 이 마크만의 문제가 아니라
**기존 「진행 상태」 탭과 마스트헤드 StepPill 이 이미 깨져 있다**는 뜻이다 — 같은 값을 읽는다.
목은 반례를 준다(AWS #1011 · IDC #1025 가 CONNECTED). 목이 계약보다 앞서 있는 것인지, 계약
설명이 낡은 것인지 BE 에 물어야 한다. **[[feedback_say_only_what_contract_says]] 대로 계약이
말하는 것만 적어 두고, 목을 근거로 계약을 해석하지 않는다.**

**② `process-status` 응답의 `healthy` 를 화면이 버리고 있다**

응답에 `healthy: 'UNKNOWN' | 'HEALTHY' | 'UNHEALTHY' | 'DEGRADED'` 가 온다
(`app/lib/api/index.ts:726` 에 타입까지 있다). 이 화면의 소비처는 **0곳**이다.
Airflow 헬스 마크를 탭 줄에 얹는다면 **새 요청 0건**으로 가능하다는 뜻이다. 다만 그것은 지금
코너 점이 말하는 것(=단계)과 다른 채널이라, 자리를 하나 더 정해야 한다. 이 라운드에서는 안 했다.

**③ 스켈레톤 kv 가 2행인데 실물은 1행이라 도착 시 탭 줄이 −56.61px 튄다**

스켈레톤이 `[0, 1].map` 으로 kv 두 행을 그리는데 AWS·Azure·IDC **전부 1행**으로 앉는다
(위 마스트헤드 표). 실측 그리드 높이 118 vs 64 → **−54px**, 총 탭 줄 y 이동 **−56.61px**.
이 라운드가 만든 것이 아니고(주석에 "kv 2행"이라 의도적으로 적혀 있다) 스코프 밖이라 두었다.
같은 라운드에서 머리 줄 몫은 잡았다 — 라벨이 16px 이 되며 스켈레톤 바가 2.4px 짧아졌던 것을
`h-5` → `h-[22px]` 로 맞춰 **0.39px** 로 줄였다.
