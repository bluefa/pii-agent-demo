| D4 | ARN 전문(50자+)이 헤더 본문에 노출 — 읽는 값이 아니라 대조하는 값 | 제안 |
| D5 | 마스트헤드·본문·카드가 전부 흰 면 — 표면 계층 없음 | 수치 (선행 리서치 실측: luminance ratio 1.0x) |

## 채택안 — R1 속성 레일 + R1′ V-b 표면 규칙

비교표(아티팩트 §4)에서 R1이 문제 커버리지(D1–D5 전부)·기존 화면 일관성에서 최고,
비용은 콘텐츠 폭 −260px(레일+간격)로 중간. R2(속성 스트립)는 D1을 한 줄로 눌러
검증값이 접히고, R3(2단 헤더)는 D2를 못 풂.

구현 형태:

1. **마스트헤드 압축** — gray-100 워시 한 장에 breadcrumb(서비스 운영 / 서비스 이름 / #id)
   + 정체 한 줄(provider 마크 · `{provider} #{id}` h1 · 단계 알약 · 최초 연동 도장 ·
   서비스가 보는 화면 버튼). 기존 5층 스택의 나머지는 전부 레일로.
2. **카드 탭 (attached)** — idle은 워시 위 조용한 글자, active는 흰 면+획에 아래가 열린
   모양. 보기 4(진행·스캔·요청·확정)와 도구 3(인프라·연결 테스트·승인) 사이 한 칸.
   탭 이름 `Test Connection` → `연결 테스트` (스테퍼가 이미 쓰는 어휘).
3. **본문 = 라벤더 캔버스** — `--pl-bg-canvas`(#F4F4FB, v16 body 값의 토큰 승격)를
   라우트 스코프로 칠함. 흰 카드와는 채도로 분리(ΔE00 4.12), 워시와도 채도로
   분리(ΔE00 2.46) — 명도가 아니라 채도가 계층을 만든다는 선행 리서치 결론.
4. **속성 레일 236px (R1′ V-b)** — 카드가 아니라 캔버스 위 맨몸. 그룹 3개(서비스 /
   클라우드 · 설정 / 검증값)를 헤어라인으로만 구분. **흰 면은 인터랙티브 값에만**
   (설치모드·실데이터 칩, ARN 수정 액션) — "흰 섬 = 터치 대상" 문법. 어느 탭에서든
   같은 자리에 보인다.
5. **ARN 축약** — `awsRoleArnDisplay`: 대상 계정 prefix 와 일치할 때만 role 이름으로
   줄이고, 불일치(교차 계정·파티션)는 전문 유지 — prefix 가 어긋남의 유일한 증거.

### 기각/보류

- **V-a (레일=흰 카드 3장)** 기각 — 콘텐츠 카드와 같은 표면 레시피는 같은 계층으로
  읽힘 ("흰 카드 반복" 지적 그대로).
- **V-c (딥 틴트 패널 #EAEAF6)** 보류 — 레일 그룹이 5개 이상으로 늘어 스크롤이 생기면
  재평가. 표면 종류가 3(캔버스·패널·종이)으로 늘고 신규 토큰이 필요.
- **탭 카운트 배지**(인프라 4 · 승인 2) 이번 PR 제외 — 셸이 새 조회 2건을 항상 물게
  되어 별도 결정 필요.
- **레일의 최초 연동 행** 제외 — 마스트헤드 도장과 중복(도장이 이미 날짜를 품는다).
