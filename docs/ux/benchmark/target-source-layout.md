## 선회 — 레일 이관에서 헤더 디스클로저로

1차 구현은 아티팩트 명세대로 메타를 **우 가이드 레일**의 「설치 대상 정보」 블록으로 옮겼다.
동작은 했지만 대가가 컸다:

- 레일은 797px 고정 열이고 이미 고정 섹션이 넷(협업채널 179 · 탭 63 · 인프라 삭제 63) 있다.
  블록을 펼친 채로 넣으니 **432px을 먹고 가이드 패널에 330px 콘텐츠용으로 61px만** 남았다 —
  vR을 기각시켰던 "레일 과적"의 재현. 접어서 51px로 눌러야 겨우 성립했다.
- 1360px 미만에서 레일이 사라지므로 `metaFallback`으로 헤더에 되살리는 **중단점 한 쌍**이 필요했고,
- 레일이 `identity`를 알아야 해서 `resolveProjectIdentity` + `GuidePanel` 프롭 2개 + `ProjectDetail`
  배선이 따라붙었다.

오너 지시로 **메타를 헤더에 두되 접는** 형태로 바꾸니 위 셋이 전부 사라졌다.
남은 변경은 `theme.ts` 토큰 3개와 `ProjectPageMeta` 한 파일이다.

## 구현 결정

### 1. `설치 대상` 행 전체가 디스클로저의 머리다

`설치 대상 · 서비스명 · 코드칩`은 펼쳐지는 블록이 **무엇을 설명하는지 지목하는 사실**이다.
따라서 접힘 요약(summary)으로 그대로 쓰고, 행 전체를 `<button>`으로 만든다 —
컨트롤이 대상 **옆에** 서지 않고 대상 **자체가** 컨트롤이다.

- 행 안의 사실은 전부 비상호작용 텍스트라 클릭을 뺏는 게 없다(테스트가 `button/a/input` 부재로 고정).
- 왼쪽=사실, 오른쪽=`설치 대상 정보` + 셰브런(`justify-between`).
- **파란색인 이유**: 이 팔레트에서 파랑은 "누를 수 있다"는 뜻 하나로 예약돼 있다
  (`codeChip`이 식별자인데도 슬레이트인 게 같은 규칙의 반대편이다).
  셰브런만으로는 **무엇이** 열리는지 말하지 못하므로 텍스트를 남긴다.
- 면은 **테두리만**(`#E1E4EB`, r10) — 아래 스텝 카드가 카드 크롬을 소유하므로
  헤더의 이 바는 흰 판을 깔지 않는다. hover 에서만 흰 면으로 뜬다.
  `#F4F4FB` 워시 위에서 옅은 틴트는 갈 곳이 없다 — 남은 방향은 더 밝은 쪽뿐이다.

### 2. 펼침 내용은 기존 블록 그대로, 같은 상자 안에서

`설명` + `클라우드 정보 groupRow`(프로바이더 · 식별자 · 설치 모드)를 **한 글자도 바꾸지 않고**
그룹 **안쪽**(`targetBody`, 머리와 헤어라인 하나로 구분)에 넣었다 — 계층은 등급이 아니라 포함이다.
`aria-expanded` + `aria-controls`(→ `#target-source-meta`)로 상태를 보조기술에 알리고,
테스트가 그 상자가 **그룹 안에** 있는지까지 확인한다.

### 3. 우 가이드 레일은 main 그대로

모니터링 스트립을 포함해 손대지 않았다. 1차 구현의 레일 블록·`resolveProjectIdentity`·
`GuidePanel` 프롭·`metaFallback`은 전부 되돌렸다.
