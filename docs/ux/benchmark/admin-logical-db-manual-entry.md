# Admin 제외 DB 관리 — 요청자 표 이식 + 손 입력

- **날짜**: 2026-08-30
- **대상 화면**: Admin 운영 콘솔 → Target Source 상세 → 연결 테스트 탭 → `관리하기` (구 `LdbManageModal`)
- **아티팩트**: https://claude.ai/code/artifact/aadc106c-1a5a-4652-b1b4-da44090a7e51
- **선행 기록**: [`logical-db-save-frame.md`](logical-db-save-frame.md)

## 지시

"거~의 그대로 사용해도 될 것 같아. 다만, 입력정보를 추가하는 부분이 필요할 것 같음."
뒤이어: "논리 DB가 조회 못 하는 상황에선 어떻게 되지? 제외 DB만 조회되는 경우 말이야.
이 경우에도 제외 DB에 값을 추가할 수 있어야됨."

## 왜 그대로 쓸 수 있었나

Admin 모달은 요청자와 **같은 API 모듈**(`app/lib/api/logical-db.ts`)의 같은 세 함수를 쓰고 있었다 —
조회 2개, 저장 1개. PUT 본문도 같다. 표를 못 쓸 이유가 없었다.

결정적인 것은 **손으로 넣은 행이 이미 표가 아는 모양**이라는 점이다. `buildModalData` 는 정책에는
있는데 이번 조회 결과엔 없는 항목을 `excludedToRenderRow` 로 병합하고 `untested: true` 를 찍으며,
표는 그것을 이름 옆 `미조회` 로 그린다. 운영자가 타이핑한 DB 가 정확히 같은 것이다.

**그래서 "추가"의 정의는 하나다** — `untested` 행 하나를 만들고 그 id 를 `excludedIds` 에 넣는다.
상태 점·저장 전 표시·되돌리기·푸터 원장·결과 프레임·부모 접힘 직렬화가 전부 그 행을 이미 처리한다.
새 상태도, 새 열도, 새 패널도 없다.

## 표를 뽑지 않고 모달을 띄운다

`LogicalDbModal.tsx` 1,312줄을 블록별로 쟀다. 재사용 가능한 셋(결과 프레임 146 · 행 122 ·
사유 팝오버 91)은 이미 컴포넌트지만, **표 셸·툴바·높이 핀·페이징은 같은 여섯 개 `useState` 에
용접돼 있다.** 공용 `<LogicalDbTable>` 을 뽑으려면 그 상태를 부모로 올리거나 context 를 새로
만들어야 하고, 그것은 Admin 을 위해 요청자 화면을 리팩터링하는 일이다.

→ **Admin 이 `LogicalDbModalLoader` 를 마운트한다.** 새 표면은 선택적 prop 두 개
(`manualEntry`, `notice`)뿐이고, 없으면 요청자 화면은 지금 그대로다.

## 조회가 없을 때 — 한 경우가 아니라 셋

`useLogicalDatabases` 는 두 GET 을 `Promise.all` 로 묶고 있었다. **두 실패는 대칭이 아니다.**

| 경우 | 상태 | 저장 | 문구 |
|---|---|---|---|
| 조회 0건 | `ready` | 가능 | 이번 Test Connection에서 조회된 논리 DB가 없어요. |
| 조회 실패 · 정책 OK | **`partial`** (신설) | **가능** | 최근 연결 테스트의 논리 DB 조회가 안 되나, 논리 DB 제외 목록은 편집하고 수정할 수 있어요. |
| 정책 조회 실패 | `error` | **차단** | 논리 DB 정보를 불러오지 못했습니다. |

조회 실패는 "이번에 뭐가 있는지 모른다"일 뿐, 정책은 손에 있으니 편집·저장이 안전하다.
정책 조회 실패는 다르다 — PUT 이 **전체 교체**라서 못 읽은 정책 위에 저장하면 남의 제외 항목이
지워진다. `Promise.all` 이 이 둘을 같은 실패로 접고 있었다. → `allSettled` + `partial`.

**빈 상태 문구의 특수 분기는 제거했다**(커밋 `e9f2aba1`). 전에는 목록에 뭐라도 있으면
`아래 제외 목록만 남아 있어요 — 복원하면 다음 테스트부터 다시 조회돼요` 로 갈렸는데,
**그 목록도 0건일 수 있어** 화면에 없는 것을 가리키는 문장이 됐다. 두 경우에 다 참인 것은 앞 절뿐이다.
복원 안내는 정책 행이 제 자리에 든 `복원` 버튼이 대신한다.

## 입력이 앉을 자리 — 표 위 한 줄 (A)

기각한 대안 B(표 마지막에 입력 행): 표에 **필터와 페이지가 있어서 입력창 자체가 사라진다** —
`제외` 탭에서는 있고 `수집 대상` 탭에서는 없고, 10개가 넘으면 입력하러 페이지를 넘겨야 한다.
열 폭(이름 240 / 단위 96 / 상태 160)에 입력·선택을 욱여넣어야 하고 리사이즈로 깨진다.
B 의 장점 하나("타이핑한 자리 = 행이 될 자리")는 A 가 **추가된 행을 잠깐 틴트해서** 갚는다.

## ⛔ 함정 둘 (테스트로 박음)

1. **`draftToExcludedItems` 는 `databases` 에 없는 id 를 조용히 버린다**(`logical-db-deny.ts:191`).
   저장 경로에 `allRows`(조회 + 손 입력) 대신 `databases` 를 넘기면 **손 입력 행이 에러 없이 사라진다.**
   트리·스테이징 diff·중복검사·원장·저장·재시도 전부 `allRows` 를 받는다.
2. **`logicalDbUnit` 은 `databases` 만 받아야 한다.** 단위 칩은 조회 결과가 정하는 것이고,
   정책은 토폴로지보다 오래 산다. ⚠️ 이 불변식은 **이중으로** 지켜진다 — 호출부가 `databases` 를
   넘기고, 헬퍼도 내부에서 `!d.untested` 를 거른다. 그래서 **한 줄 뮤테이션으로는 테스트가 안 빨개진다.**
   살아 있는 트립와이어인 척하지 않고 테스트에 그 사실을 적어 뒀다.

## 버린 것 · 지킨 것 · 공짜로 얻은 것

- **버림**: 좌우 두 패널(`연동 대상` / `연동 제외`) · 날 것 enum `STG`/`DEV`/`TEMP` → 한국어 라벨 ·
  자체 `add()`/`remove()` · `LdbManageModal.tsx` 375줄 삭제(`ldbPanel` 은 유일한 소비자
  `LdbViewModal` 로 이전)
- **지킴**: 전체 교체 경고 → `저장하면 제외 목록 전체가 교체돼요. 목록에서 뺀 항목은 제외가 해제됩니다.`
- **공짜**: 부모가 제외되면 자식을 안 보내는 규칙(전에는 `db` + `db.schema` 중복 쌍을 보낼 수 있었다) ·
  `type` 이 입력창이 아니라 행에서 나오는 것

## 검증 (브라우저 실측, dev :3001 · targetSourceId 1010)

- Admin 모달 = 요청자 표 920px, 트리·필터·검색·리사이즈 그대로
- 빈 이름 → `Database 이름을 입력해 주세요.` / 중복 → `이미 목록에 있습니다.`(조회된 행·저장된 정책 양쪽)
- **손 입력 행이 PUT 에 실린다**: `stg/STG`, `dev/DEV`, `legacy/TEMP`, `ops_sandbox/TEMP/DATABASE`
- 사유 표시 ↔ 실제 값 일치(select `임시` = 행 `임시` = 본문 `TEMP`)
- `partial`: 정책 4건 전부 `미조회`, 배너 표시, 추가 폼 있음, **추가하면 저장 활성**
- `error`: 표도 추가 폼도 없음, `다시 시도`만

뮤테이션으로 고정한 트립와이어 5건(+ 위 ⚠️ 1건은 이중 방어라 뮤테이션 불가):
`partial`→`ready` · 정책 실패→`partial` · `untested` 스탬프 제거 · `onSave(…, databases)` · 툴바 강제 노출.

교차 리뷰 P1·P2·P3 **0건**.

## 범위 밖 — 오너 대기

**Admin 에는 엔진 게이트가 없다.** `grep -rn "hasLogicalDatabases" app/admin/` → 0건.
`관리하기` 는 모든 행에 무조건 그려지고(`ConfirmedInfoCard.tsx`), `databaseType` 은 모달까지
내려가지만 태그를 그리는 데만 쓰인다. Athena · DynamoDB 리소스에서도 운영자가 아무 문자열이나
타이핑해 정책을 PUT 할 수 있다. 요청자 화면은 같은 리소스에 `제외 불가` 라고 쓴다.
서버 검증까지 묶인 별건이라 이 PR 에서 손대지 않았다.
