   **배치 반전**.
2. **P2 드로어 본문에서 가장 먼저 읽히는 줄이 타임스탬프다** — `UX 원칙`

3. **P8 "이번 실행의 판정"이라는 객체가 UI에 없다** — `UX 원칙` · **이번 PR 범위 밖**

## 채택안: 시안 F — Task Card 실행 요약

비교표에서 A·B·F·C 묶음이 11건 중 10건을 덮었고, 그중 **F를 먼저 적용**하기로 결정
(오너: "우선 정보 정리부터 하자"). F는 라우팅·계약 변경이 없고 카드 규격을 그대로 쓴다.

카드 하단에 hairline으로 구분된 **라벨-값 2행**을 붙인다(오너 지정 배치).

```
PLAN  서비스측
AWS Service Level 테라폼          ← 제목에서 Plan/Apply/Destroy 제거
대상 AWS service level 인프라의…
──────────────────────────────
시작 시간  2026-08-14 20:19
완료 시간  2026-08-14 20:21   소요 2분
```

**제목의 실행 종류 접미사를 뗀다.** 바로 위 `JobKindTag`가 이미 `PLAN`/`APPLY`를 말하고
있어 이름에서는 중복이다(오너: "제목에서 Plan, Apply, Destroy는 없애보자"). 드로어 제목은
그대로 둔다 — 드로어에는 `JobKindTag`가 없어 이름이 실행 종류의 유일한 전달자다.

**실행 블록은 카드 전폭을 쓴다.** 처음엔 `.nd-body`(제목 열) 안에 넣었는데, 56px 로고마크
옆이라 폭이 **162px**뿐이라 `완료 시간` 행이 **39px 넘쳐** 잘렸다. 카드를 넓히는 대신
노드를 `[아이콘+제목 행]` / `[실행 블록]` 2단 컬럼으로 바꿨다. 실측: `소요 2시간 5분`까지
한 줄에 들어가고, 그보다 긴 `소요 12시간 45분`은 `flex-wrap`으로 다음 줄에 떨어진다.

**카드 폭 288 → 352px, 이름은 절대 두 줄이 되지 않는다**(오너: "AWS BDC Common 테라폼
이렇게 2줄로 표현되면 안 된다"). 폭은 **가장 긴 카탈로그 이름**에서 역산했다 —
`AWS BDC Service Level 테라폼` 실측 **217px**(16px/700) → 제목 열 226px 확보.
288px에서는 제목 열이 162px라 AWS 계열 이름이 전부 2줄이었다.
캔버스는 **드로어를 연 순간 이미 가로 스크롤**이다(뷰포트 992px 대 트랙 1320px, 288px 기준)
— 넓힌 폭은 새 어포던스를 만들지 않고 한 줄 제목만 산다.
이름이 한 줄로 줄면서 카드 높이는 235 → **213px**.

**소요는 숫자만 한 단계 올린다**(오너: "숫자는 2px 키우고 굵기 한 단계 / 분 12픽셀").
`소요` 라벨도 단위(`분`·`시간`·`초`)도 12px/600 그대로고, **자릿수만 14px/700**이다
(`elapsedDigits`가 `/(\d+)/`로 쪼갠다 — `2시간 5분`이면 `2`와 `5` 둘 다). 카드에서 유일하게
파생된 수치라 양옆 타임스탬프보다 한 급 위이고, 베이스라인은 `.nd-run-row`가 잡는다.

**판정어는 넣지 않는다.** 1차 구현에서 `● 완료` / `● 실패` 를 함께 넣었다가 오너가
"완료/실행중 이런 상태 표시는 하지마, 어차피 stroke를 보고 알 수 있는 정보야"로 잘라냈다.
카드에는 이미 상태 채널이 둘(테두리 색 + 코너 배지)이고, FAILED 카드는 `nd-meta`가
"2회 실패했습니다. 원인은 JOB_FAILED."로 세 번째를 말하고 있었다. 그래서 이 행은
**시간만** 맡는다 — 카드에 없던 정보만 더한다.

### 갈래 규칙 (`taskRunLine`)

| 조건 | 시작 시간 | 완료 시간 | 소요 |
|---|---|---|---|
| `started_at` 없음 | `-` | `-` | 없음 |
| `started_at` 만 있음 | `YYYY-MM-DD HH:mm` | `-` | 없음 |
| 둘 다 있음 | `YYYY-MM-DD HH:mm` | `YYYY-MM-DD HH:mm` | `fmtElapsedMs` |

빈 칸은 `fmtDateTime(null) === '-'` 이 그대로 처리하므로 별도 갈래를 두지 않는다.

- **진행 중 카드에 두 번째 시계를 두지 않는다.** 라이브 경과는 실행 밴드가 이미 담당하고,
  렌더 중 `Date.now()`는 React compiler lint가 막는다(선행 기록 `pipeline-detail.md` 함정).
- **FAILED는 `finished_at`이 비어 올 수 있어**(`runWindow` 주석) 자동으로 "시작만" 갈래로
  떨어진다 — 별도 분기 없음.
- `finished < started`(음수)면 `fmtElapsedMs`가 `-`를 돌려주므로 **소요를 지어내지 않고 비운다.**
- 모든 갈래가 2행을 채우므로 **카드 높이가 상태와 무관하게 균일**하다(실측 235px, 전 상태 동일).

### 접근성

테두리 색은 스크린리더에 묵음이고 코너 배지는 `aria-hidden`이라, 상태를 시각 채널에만
두면 판정이 아예 전달되지 않는다. 카드에서 판정어를 뺀 대신 **접근 이름에는 남겼다**:
`aria-label={이름} · {판정} · 상세 열기`. (`aria-label`이 자식 텍스트를 대체하므로
자식에 넣는 방법으로는 해결되지 않는다.)

## 2차: 시안 A + B (패널 재정리)

F가 시각을 카드로 올린 뒤 패널을 다시 재고, 진단 8건을 새로 잡았다(2차 아티팩트).
그중 **2건은 F가 만든 문제**다 — 패널 첫 블록 `진행 기록`이 카드의 사본이 됐고,
같은 소요를 카드는 `2분`(`fmtElapsedMs`), 시도 정보는 `2m 0s`(`spanLabel`)로 쓴다.
오너 지시는 "이대로 적용" — 비교표대로 **A + B를 한 커밋**, C는 다음, D는 보류.

### 시안 A — 판정 히어로 (진단 01 · 03)

`진행 기록` 블록과 `시도 횟수` 독립 행을 걷어내고 그 자리에 **판정**을 놓는다.

```
● 실패  [JOB_FAILED]        ← 20px/700 + 점, 코드는 흰 면+stroke 칩
시도 2/2회 · 다음 확인 …     ← 14px text-weak
```

- 틴트 판을 깔지 않는다 — 판정은 타입 크기와 점, 사실은 한 급 아래(기존 규칙).
- `TerraformExec`/`ConditionExec` 둘 다 같은 문법. 조건 확인은 판정이
  `충족`/`미충족`이고 코드 칩 자리에 **외부 상태**(`READY`)가 들어간다.
- 카드가 이미 말하는 시각(Started/Finished)은 **되풀이하지 않는다**. `다음 확인`만
  사실줄로 살아남는다 — 카드에 없는 값이라서다.
- 아티팩트 목업의 `Job 3개 중 1개 실패`는 **넣지 않았다**. B의 집계 줄이 바로 아래에서
  같은 수를 세므로 한 화면에 두 번 적힌다. 사실은 한 번씩만.

### 시안 B — Job 현황을 루트로 (진단 04 · 05 · 08)

최초 요청("각 Job의 상태가 먼저 눈에 들어와야 한다")에 직접 답하는 블록.

- **집계 줄** — `1 실패 · 2 성공 … 총 3개`. 숫자는 16px/700 + 판정 색, `jobVerdict`로 센다.
- **실패 우선 정렬** — 실패 → 진행 중 → 기록 없음 → 성공. 안정 정렬이라 같은 판정끼리는
  계약 순서를 지킨다.
- **`last_fail_reason`을 실패 행 아래 인라인** — 원인까지 **3홉 → 0홉**. 계약이 이미
  주고 있으면서 아무 데서도 안 쓰던 필드다(진단 05).
- **`PlPagination` 제거** — 21개가 5페이지로 흩어지던 걸 접기 하나로 바꿔 패널의
  넘침 문법을 통일했다(진단 08). 6개 이상일 때만 **성공만** 접힌다.
- 같은 블록을 시도 드릴다운도 쓴다 — 루트는 최신 시도, 드릴다운은 그 시도.
  시도가 2개 이상이면 `최신 시도 #2 기준` 힌트로 주어를 못박는다.

### 시안 C — 시도 드릴다운을 접기로 (진단 02 · 06)

시도 행을 누르면 **헤더까지 통째로 바뀌던**(← 뒤로) 화면 전환을 없애고 제자리에서 편다.

- `DrawerView`·`j.subHeader`/`back`/`subTitle`/`subCrumb` 삭제 → **Esc 계층이
  뷰어 → 드로어 2단**으로 줄었다. 드로어는 이제 헤더가 하나뿐이다.
- `시도 정보` 3행 kv → **한 줄**: `실행  2026-08-15 07:29 → 07:34 · 5분`.
  끝 시각은 **날짜가 다를 때만** 날짜를 반복한다(자정을 넘긴 시도).
- **`spanLabel` 삭제, `fmtElapsedMs`로 통일** — 카드가 `21분`이라 쓰는 값을 한 클릭
  거리에서 `21m 0s`로 쓰던 문법 분기를 없앴다(진단 02). 문법은 이제 화면 전체에 하나.
- **미니 배지 10px → 12px**(`d.miniBadge`·`j.miniBadge`) — 판정을 나르는 칩이
  타입 세트 최소 아래에 있었다(진단 06).
- **한 번에 하나만 열린다.** 시도 2개 × Job 21개를 다 펴면 패널이 끝없이 길어진다.
- `Response 원문`은 **접힌 채로 시작**한다 — 접기 안의 접기라서.
- **최신 시도를 펼치면 `Job 현황`을 다시 그리지 않는다**(`jobsShownAbove`). 루트가
  이미 그 시도의 Job을 보여주고 있어, 같은 화면에 같은 블록이 두 번 나오는 걸 막는다
  — 진단 01이 지적한 그 중복이다. 이전 시도(#1)를 펼치면 그 시도의 Job이 나온다.

실측: 판정 칩 **12px**, Esc 한 번에 드로어가 닫히고(시도 계층 없음), 뷰어가 열려 있으면
드로어는 닫히지 않는다. 시도 #2 펼침 = `실행 · 확인 요약 · Response`,
#1 펼침 = `실행 · Job 현황 · 확인 요약 · Response`.
