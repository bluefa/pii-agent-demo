# Step 5 연결 테스트 카드 — 진행 중이 멈춰 보이는 문제

- 날짜: 2026-08-22
- 대상: `TcSummaryCard.tsx`(클라우드·IDC 공용) · `lib/test-connection-summary.ts` · `lib/theme.ts` `idcStyles.connProgress`
- 리서치 아티팩트: https://claude.ai/code/artifact/3ff95923-f167-41b6-8c1c-eb4dd3a2d10d
- 3라운드. 1라운드 `tc-card-surface.md`(표면) · 2라운드 `tc-counts-row.md`(카운트 줄·파형 글리프, #746)

시작점: #746 에서 도는 시계를 활동 파형으로 바꾼 뒤에도 "동작 중이라는 느낌이 강하게 들지 않는다"(오너).

## 문제 (증거 등급)

진단하면서 나온 핵심은 **정지가 한 종류가 아니라 셋**이라는 것이었다. 그래서 시안 하나로는 덮이지 않는다.

| # | 진단 | 등급 |
|---|------|------|
| P1 | **시작 구간** — 아직 아무것도 정착하지 않아 트랙이 폭 0 의 빈 회색 바다. 코드는 `queued` 에서 바로 이 그림을 거부하는데("빈 0% 바는 멈춤으로 읽힌다", `showTrack` 주석), 같은 그림이 `running` 안에서 재현된다 | 수치 위반 (자기 규칙 위반) |
| P2 | **중간 구간** — 폴이 4초(`useTestConnectionPolling` 기본값)라 폴 사이에는 데이터가 바뀔 수 없다. 리소스 6개짜리 40초 실행이면 값이 바뀌는 순간은 여섯 번 × 250ms = **1.5초(3.75%)** 뿐 | 수치 위반 (측정) |
| P3 | 진행 중 메타가 `09:00 요청` 한 줄로 **고정 문자열** — 실행이 시작된 뒤 카드에서 스스로 변하는 값이 하나도 없다 | 수치 위반 |
| P4 | 움직이는 픽셀이 15px 글리프 안의 마디 하나(약 8px²) — 카드 면적의 **0.007%**, 트랙까지 세도 0.18% | 수치 위반 (측정) |
| P5 | 예상 소요를 아무도 말하지 않는다. 스캔은 "약 5분 이내"라고 말하는데(`ScanRunningState.COPY`) 이 화면엔 근거가 없다 | UX 원칙 (NN/g: 불확정 대기의 핵심 결핍) |
| P6 | **꼬리 구간** — 모든 유닛이 답했는데 실행은 아직 정착하지 않은 창. 바는 가득 찼고 `남음` 도 사라졌는데 문장만 "연결 테스트 진행 중". 스캔은 같은 자리를 `finalizing` 프레임으로 이미 풀었고, 그 수정이 이 화면엔 오지 않았다 | UX 원칙 (앱 내 선례 불일치) |

## 채택 — B + A + E (C·D 보류)

셋이 각각 다른 구간을 맡는다. **적용 순서는 E → B → A** — 문장이 먼저, 그다음 사실, 마지막이 연출.

### E — 문장에 `집계 중` 국면 (P6)

`tcSummarySentence` 의 `running` 분기 하나. `total > 0 && reported === total` 이면 `결과를 집계하고 있어요`.

- 어휘는 스캔에서 그대로 가져온다 — `ScanRunningState`: "리소스 탐색은 끝났고 **결과를 집계하고 있어요**". 두 화면이 같은 국면을 다른 말로 하지 않는다.
- `미확인`도 답으로 센다(`reported = ok + fail + unknown`). 읽을 수 없을 뿐 보고는 됐으므로 기다릴 것이 남지 않았다.
- `total === 0` 은 별도 가드 — 대상이 없으면 `reported === total` 이 저절로 성립하는데, 그건 집계가 아니다.
- 정착 홀드(`useTcSettleHold`, 400ms)도 이 프레임을 지난다. 바가 끝까지 차는 그 박자에 문장이 "집계 중"이라고 말하는 것이 정확하다.

### B — 메타 줄이 경과를 센다 (P2·P3)

`09:00 요청` → `09:00 요청 · 1분 12초 경과`. `tcElapsedLabel(requestedAt, now)`.

- **다섯 시안 중 유일하게 새 사실을 말한다.** A·C 는 "돌고 있다"를 연출할 뿐이고, 얼마나 기다렸는지는 계속 기다릴지 판단하는 유일한 근거다(NN/g, Designing for Long Waits — 이 리서치의 반증 레퍼런스이기도 하다).
- 계약 변경이 없다. `requested_at` 은 `TestConnectionVersionResult` 가 이미 준다.
- `queued` 에서도 센다. 그 국면은 트랙조차 없어(`showTrack` 이 false) 이 수가 유일하게 변하는 값이다.
- 정착하면 계약의 `completed_at` 을 쓰고 시계는 멈춘다 — `소요`이지 `경과`가 아니다.
- 시계는 `useNowTick`(외부 스토어). state 로 들면 켜지는 순간의 값을 이펙트에서 써 넣어야 하고 그게 연쇄 렌더, 렌더에서 `Date.now()` 를 읽으면 순수하지 않은 렌더 — 컴파일러 규칙이 둘 다 막는다. 구독은 그 둘을 피하면서 켜진 첫 프레임부터 정확하고, 카드가 몇 장이든 타이머는 하나다.

### A — 미판정 구간의 행진 무늬 (P1·P2)

트랙에서 아직 판정이 오지 않은 만큼이 오른쪽→왼쪽으로 흐른다. CSS 만.

- **채움 아래에 깔린다.** 불투명한 성공·실패 채움이 덮고 남은 구간만 저절로 드러나므로 폭 계산도, 250ms transition 과의 좌표 맞춤도 없다. 시작 직후엔 트랙 전체가 흘러 P1 이 닫히고, 모두 보고되면 행진할 구간이 없어 저절로 멈춘다 — 그 프레임을 E 가 받는다.
- 방향은 취향이 아니다. Harrison et al., UIST '07 — 진행 방향의 **역행** 파동이 같은 길이의 대기를 더 짧게 느끼게 한다.
- 8px 타일 · 45° 는 Bootstrap `.progress-bar-striped` 의 기하 그대로(퍼센트 정지점이라 타일 경계에 이음매가 없다). 주기 1400ms 는 글리프의 `tcActivityMarch` 와 같은 값이라 두 모션이 서로 다른 박자로 뛰지 않는다.
- **색은 브라우저에서 네 후보를 1:1 로 놓고 골랐다.** `#BAC4D1`, 트랙(#E4E7EC) 대비 1.42:1. 한 단계 위 `#8B95A1`(중립 점과 같은 값)은 남은 구간이 채워진 **세 번째 띠**로 읽혀 카운트 줄의 점 범례가 가리키는 축이 셋이 되고, 한 단계 아래 `#CDD5DE`(1.20:1)는 등배에서 질감이 사라져 모션이 보이지 않는다. 판정 두 색(3.07:1 · 3.63:1)보다는 반드시 약해야 한다.
- 모션이 꺼지면 무늬만 정지한 채 남는다 — "미판정"은 애니메이션이 아니라 형태가 말한다(Primer).

## 보류

**C — 물결 트랙.** 글리프와 트랙이 같은 파형 어휘를 쓰게 되어 일관성은 가장 높지만, **A 와 같은 문제만** 풀면서 트랙을 SVG 로 갈아야 한다. A 를 먼저 넣고 부족하면 그때 교체한다.
⛔ 어느 쪽이든 파형을 **회전시키지 않는다** — 도는 대신 흐른다(2라운드 규칙).

**D — 방금 응답한 리소스 티커.** 가장 정직한 신호지만 40초에 사건이 6번뿐이라 사건 사이를 메울 폴백 문구가 필요하고, 그것이 #746 에서 한 축으로 정리한 줄을 도로 둘로 만들 소지가 크다. 오너 지적 두 가지가 더 붙었다 — Resource Name 이 길어 2줄이 필요할 수 있고, IDC 는 이름만이 아니라 **IP 목록·Domain 까지** 실어야 한다. 설계가 더 필요하다.

## 덧붙임 — 문장 왼쪽 글리프를 Figma에 맞춤 (2026-08-22, 오너 지적)

벤치마크와 별개 건. 글리프 삼항의 **마지막 가지가 폴백인데 기본값처럼 쓰이고 있었다** — `fail` 이 거기로
떨어져 실패 카드가 `idle`·`queued` 와 같은 **시계**를 달았다. 표면과 문장만 붉을 뿐 글리프는 아무 판정도
하지 않았고, 색을 빼면 세 상태가 같은 그림이었다(WCAG 1.4.1).

Figma(`H2kRxFxOqqeTrPceFU4zMM`)가 지정한 대로 가른다. 18px 렌더의 잉크 맵으로 대조해 두 글리프의 출처를
확인했다 — 둘 다 Lucide다.

| 상태 | 전 | 후 | 근거 |
|---|---|---|---|
| `fail` | 시계 | **x-circle** (`CircleXIcon`, 신규) | Figma `card/fail` 의 `x-circle` 프레임. 기하는 Lucide `circle-x` 그대로 |
| `queued` | 시계 | **모래시계** (`HourglassIcon`, 신규) | Figma `card/queued` 의 `hourglass` 프레임. 세트에 모래시계가 없어 새로 만들었고, 기하는 Lucide `hourglass` 그대로 — 같은 슬롯의 `ClockIcon` 도 Lucide라 획과 여백이 맞는다 |

폴백에 남는 것은 `idle` 하나다 — 실행이 없다는 사실만 말하므로 시계가 맞다. 이제 네 국면(미실행·시작
대기·진행 중·실패)이 **색 없이도 네 가지 그림**으로 갈린다. 테스트가 그 넷의 유일성을 직접 잰다.

글리프는 슬롯을 꽉 채워 **18×18** 로 그린다. `connProgress.icon` 슬롯은 처음부터 18×18 이었는데 안의
SVG 만 15px 이라 사방 1.5px 씩 비어 있었고, 그 탓에 상태 글리프가 16px 굵은 제목보다 작게 읽혔다.
Figma 의 `title/icon-slot` 도 18×18 이다. 슬롯 크기가 그대로라 카드 높이는 변하지 않는다(135px, 실측
134.8). 메타 서브라인의 시계는 12px 그대로 둔다 — 같은 18px 슬롯을 공유해 열은 맞되, 시각 표식은
판정 글리프가 아니다(Figma `meta/icon-slot` 안의 프레임도 12×12).

`fail` 은 처음엔 앱이 이미 쓰는 에러 글리프 `StatusErrorIcon` 을 재사용했다. 그런데 그건 Heroicons
계열이라 원 반지름이 9(박스의 83%)여서, 같은 슬롯에 서는 Lucide 글리프들(시계·모래시계, 둘 다
r=10 = 92%)과 어긋난다 — 15px 에선 1.25px 차라 넘어갔지만 **18px 로 키우자 1.5px 로 드러났다**(잉크
지름 15.0px 대 16.5px, 브라우저 실측). 그래서 `CircleXIcon` 을 따로 들였고, 이제 **16.5px 대 16.5px**
로 정확히 맞는다.

⚠️ Toast·ErrorState 의 에러 글리프는 여전히 `StatusErrorIcon` 이다. 이 카드가 앱의 에러 어휘를
말하는 것보다 Figma 가 지정한 기하를 따르는 쪽을 골랐다는 뜻이고, 두 아이콘이 한 화면에 나란히
서는 자리는 없다. 체크·경고는 Figma 가 기하를 지정하지 않아 그대로 둔다 — 이 슬롯의 글리프가
68~92% 로 흩어져 있는 건 그 때문이다.

## 남는 것

P5(예상 소요)는 셋을 다 넣어도 열려 있다. 실제 실행 시간을 한 번 재서 "보통 N분"을 문장에 넣는 것이 위 셋을 합친 것보다 클 수 있다 — 계약에 진행률도 ETA 도 없으므로(`TestConnectionVersionResult` 는 `requested_at`·`completed_at` 뿐) 이건 측정과 문구의 문제이지 구현의 문제가 아니다.

## 검증

목 dev 서버에서 40초 실행을 120ms 간격으로 기록해 세 채널을 한 번에 확인했다.

```
+1.0s   연결 테스트 시작을 기다리고 있어요 · 1초 경과      march=no
+8.0s   연결 테스트 진행 중 · 8초 경과   성공1 실패0 남음3  march=yes/running
+23.0s  연결 테스트 진행 중 · 23초 경과  성공3 실패0 남음1  march=yes/running
+24.0s  결과를 집계하고 있어요 · 24초 경과 성공3 실패1      march=yes/running
+25.0s  연결에 실패한 리소스가 있어요 · 소요 24초           march=no
```
