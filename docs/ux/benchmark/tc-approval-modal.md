# Step 5 완료 승인 요청 모달 — 확인 문법으로 이관

- 날짜: 2026-08-22
- 대상: `CloudReqApprovalModal` (클라우드 5단계) · `IdcReqApprovalModal` (IDC 5단계)
- 구현 PR: (아래 §7)
- 선행: [tc-running-liveness.md](./tc-running-liveness.md) (#750) — 이 모달을 여는 `승인 요청` CTA

## 1. 제기된 문제

사장님 지적 네 가지:

1. 리소스 테이블 디자인이 영 별로다
2. 모달 타이틀·구성이 기존 모달과 달라 이질감이 있다
3. 완료 버튼을 눌렀을 때 Step 1처럼 자연스럽게 넘어가는 UI가 있으면 좋겠다
4. 요약 정보에서 왜 로딩 시간이 걸리는가 — Step 5의 API 결과를 그대로 쓸 수 없나?

### 4번 질문에 대한 답

**"Step 5의 API 결과를 그대로" 는 불가능하다.** 카드가 폴링하는 것은 job status(리소스별
연결 판정)이고, 논리 DB 개수는 `GET .../test-connection/latest-results` 라는 별도 계약이다.
카드는 이 엔드포인트를 한 번도 부르지 않는다.

다만 **전제가 사라졌다** — 프로덕션에는 컴파일 단계가 없고 응답은 8ms다. 그래서 "열을
버려서 API를 피한다"가 아니라 **D2를 고치는 것**이 실제 처방이다.

## 3. 채택안

사장님 선택: **Step 5 표 문법 + 논리 DB 열 유지**, IDC도 같이.

### 3.1 chrome → `ConfirmStepModal` (D6, D4)

두 모달 모두 공용 확인 문법으로 옮긴다. 1단계 승인 요청(`IdcSubmitModal`)과 같은 껍데기다:
질문형 제목 `연동 완료 승인을 요청할까요?`, 원인→결과 한 문장, 통계 타일, `머무르기`/`요청하기`.

`ConfirmStepModal` 에 더한 것 둘:

- `wide?: boolean` → `size?: 'sm' | 'md' | 'lg'` (480 / 560 / 760). 표를 든 확인이 세 번째다.
- **뷰포트 천장** `max-h-[86vh]` + 본문만 `min-h-0 overflow-y-auto`, 헤더·푸터는 `shrink-0`.
  86vh는 `pipelineStyles.modal.dialogTask` 가 같은 이유로 이미 쓰던 값이다.
  `min-h-0` 이 없으면 flex 아이템이 콘텐츠 아래로 못 줄어들어 넘침이 푸터로 밀린다.

부수 효과로 두 모달이 **포커스 트랩·`aria-labelledby`·`body.overflow` 복원**을 얻는다 —
손으로 뜬 쪽에는 셋 다 없었다.

### 3.2 요청 → 확인 프레임 → 전환 (3번)

`useConfirmSubmit` 을 재사용한다. 성공해도 화면을 곧바로 갱신하지 않는 것이 핵심이다:
`refreshProject()` 가 상태를 CONNECTION_VERIFIED 로 바꾸는 순간 5단계가 통째로 교체되고,
안에 있던 모달은 프레임을 보여주기도 전에 언마운트된다. 갱신은 1초 홀드가 끝난 뒤다.

훅에 `pendingStatus` 를 인자로 뺐다 — 재요청 직전 조회의 기준 상태다. 1단계는
`WAITING_TARGET_CONFIRMATION`, 5단계는 `WAITING_CONNECTION_TEST`. **기본값을 두지 않았다**:
남의 단계 상태로 판정하면 이미 접수된 요청을 한 번 더 보낸다.

PUT도 훅으로 올라갔다. 전에는 모달이 스스로 보내고 실패하면 `toast.error(err.message)` —
BFF가 쓴 문장이 그대로 UI 카피가 되는 ADR-008/ADR-013 위반이었다. 이제 코드로 문구를
고른다(`approvalFailureCopy`, 1단계와 공유). IDC 쪽은 `handleSubmitApproval` 에 catch가
아예 없어 실패가 unhandled rejection 으로 사라지던 것도 같이 닫혔다.

실측: 확인 → `승인 요청을 보냈어요` (~1s 홀드) → 6단계.

### 3.3 표 (1번, D3, D5, D7)

- 행 집합을 카드와 **한 함수에서** 만든다. `TestUnit` / `toTestUnits` 를
  `ConnectionTestCard` 에서 `lib/resource-grouping` 으로 옮겼다 — 각자 접었기 때문에 8 vs 6이 났다.
- 문법도 카드 그대로: 한 줄 고정 이름 + 툴팁, `RDS Cluster`/`EC2` 태그, `approvalCell` 토큰,
  열 순서 정체성 → 속성 → 이 화면이 묻는 것.
- 접힌 Athena 행에는 `데이터베이스 N개` 를 붙인다 (N ≥ 2일 때만). 카드에서는 펼쳐 볼 수 있지만
  여기서는 없으므로, 말하지 않으면 데이터베이스가 조용히 사라진다.
- 논리 DB 두 열은 6·7단계가 쓰는 `LogicalDbCountCell` 로 통일 — 어휘도 `연동 논리 DB`/`연동 제외`
  (D7 해소), 두 열 다 중립색(머리글이 이미 어느 쪽인지 말했다).
- IDC 는 `IdcResourceTable` 을 그대로 쓴다 (D8 해소). 열은 §3.4 참고.

실측 후: 6줄, 740px(뷰포트 861px 안), 넘침 없음.

### 3.4 IDC 열 — 1차 오답과 정정

1차에는 `cols={['conn']}` 만 세웠다. **논리 DB 두 열을 뺐고, 그건 틀렸다** — IDC 5단계 표는
`['cred','conn','logicalro','src']` 로 그 두 열을 이미 보여주고 있었다. 승인의 근거인 값이
바로 뒤 표에는 있고 승인 화면에만 없는 것은, 이 PR 이 클라우드에서 고친 **그 불일치**를
IDC 에 다시 만든 것이다. (사장님 지적: "IDC엔 왜 논리 DB 개수가 없지?")

`['conn','logicalro']` 로 여섯 열을 세워 실측하니 712px 안에서 `연동 제외` 가 **43px** 로
눌려 머리글이 세로로 한 글자씩 쪼개졌다. 폭 걱정 자체는 맞았고, 처방이 틀렸다 —
**뺄 열은 논리 DB 가 아니라 연결 상태였다.**

최종 `cols={['logicalro']}`:

- 클라우드 모달과 **같은 모양**이 된다 — 정체성 · 종류 · 논리 DB 구성. 클라우드도 판정
  열이 없다.
- 이 모달은 **모두 성공했을 때만 열린다**(카드 CTA 가 `buckets.ok === live.length` 로 잠금).
  판정 열은 전부 같은 칩 하나가 되고, 판정 자체는 위 타일(`연결 성공 5건`)이 센다.
- 실측: `연동 제외` 138px, 머리글 한 줄, 행 53px, 5줄 전부 보임(스크롤 없음).

딸린 수정: `IdcResourceTable` 의 `onOpen={() => onLogicalOpen?.(r)}` — 화살표 함수는 언제나
truthy 라, `onLogicalOpen` 없이 쓰면 **눌러도 아무 일 없는 버튼**이 됐다.
`LogicalDbCountCell` 이 "아무 일도 안 하는 컨트롤 대신 평문" 이라고 정해 둔 바로 그 상태다.
`onLogicalOpen ? () => onLogicalOpen(r) : undefined` 로 고쳤고 뮤테이션으로 고정했다.
확인 모달 위에 또 모달을 얹지 않으므로 여기서는 평문이 맞다.

### 3.5 0을 말하지 않는다 (D2)

- `StatTile.value: number | null` — `null` 은 `—` 를 찍고 **단위도 붙이지 않는다**.
  "— 개" 는 세지 않은 것의 단위를 주장한다.
- 합계 reduce가 `{target: null, excluded: null}` 에서 시작한다. 이것이 실제 수정이다 —
  뮤테이션으로 확인: 초기값을 `{0, 0}` 으로 되돌리면 해당 테스트가 깨진다.
- 조회가 실패하면 맵을 비운 채 둬서 모든 수가 `—` 로 남는다.

### 3.6 페이지 바와 숫자 크기 (2차 피드백)

**바가 스스로를 반박했다.** 클라우드 모달은 `initialPageSize: 5` 로 페이징하면서
`pageSizeOptions` 는 기본값(`[10, 20, 50, 100]`)을 그대로 썼다. 5가 목록에 없으니 select
는 그 값을 고를 수 없어 첫 옵션을 그렸고, 한 줄 안에서 **"표시 10 건씩 · 1–5 / 전체 6건"**
이 됐다. 모달 크기의 목록은 `ScanHistoryModal` 과 같은 `[5, 10]`.

**바가 표에 붙지 않았다.** 표는 `idcStyles.table.frame`(12px 라운드 + 그림자), 바는
`rounded-b-[10px]` + `border-t-0` + `#E5E7EB`. 표가 제 라운드로 아래를 **닫고** 그림자를
바 위에 드리워, 바는 이어진 게 아니라 끝난 카드 밑에 매달렸다(모서리에서 눈에 보인다).
`framePaged` 를 만들어 — `rounded-t-[10px]` · 바와 같은 테두리색 · 그림자 없음 — 표가
아래를 열어 두고 바가 닫는다. 실측: 표 `10px 10px 0 0` / 바 `0 0 10px 10px`, 두 요소 모두
704px, 테두리 `rgb(229,231,235)` 로 일치, 이음매는 직선 하나.

앱 전체에서 `Pagination` 을 이는 다른 표는 모두 테두리 없는 연결 스킨이라 이 문제가 없었다.
같은 짝을 쓰는 곳은 `IdcResourceTable` 의 non-connected 갈래뿐이고, 그 갈래는 **항상**
아래에 바를 단다 — 그래서 `framePaged` 로 바꿨다(그 갈래의 프로덕션 소비자는 IDC 승인
모달 하나뿐이다. `IdcStep4Installing` 은 `SourceIpHeader` 만 가져다 쓴다).

**숫자 40px → 24px** (`StatTile.scale: 'page' | 'dialog'`). 제목이 26px 인 상자 안에서
40px 숫자가 위계의 꼭대기를 가져갔다. 기본값 `page` 는 그대로 40px — 2단계 카드의 필터
타일은 페이지 폭 위의 표시 숫자다. 두 완료 승인 모달만 `dialog`.

**제목 26px 은 그대로.** `modalStyles.toss.title` 은 `Modal chrome="toss"` 를 쓰는 모든
단계 모달의 제목이다(26/800/-0.03em). 브라우저 실측도 26px — 이 모달은 이미 다른 모달과
같은 크기였다. `toss-compact` 의 20px 는 푸터 없는 읽기 전용 알림용이라 여기 해당 없음.

## 5. 기각·보류

- **표를 통째로 5단계 표로 재사용(연결 상태 열 포함, API 0회)**: 논리 DB 개수·제외가 사라져
  "각 리소스의 논리 DB 구성을 확인한 뒤 요청" 이라는 모달의 존재 이유가 없어진다. 사장님 기각.
- **표를 빼고 요약만**: 리소스별 확인을 뒤 표로 미룬다. 사장님 기각.
- **통계 타일 제거**: 표 바로 위에서 표의 합을 다시 말하는 중복이지만, 지적된 범위 밖이라
  건드리지 않았다.
- **결과 프레임의 여백**: `ConfirmStepModal` 이 확인 프레임 높이를 `min-height` 로 고정하므로
  (결과 순간에 상자가 줄면 그 움직임이 가장 먼저 읽힌다), 760×740 모달에서 결과 프레임은
  ~200px 콘텐츠가 740px 상자 가운데 뜬다. 공용 컴포넌트의 규칙이라 그대로 뒀다 — 바꾸면
  1단계도 같이 바뀐다.
- **뷰포트 천장에서 본문이 스크롤될 때 페이지네이션도 함께 스크롤**: 푸터는 고정이므로
  `요청하기` 는 항상 닿는다. 페이저를 푸터로 올리는 것은 별건.

## 6. 딸려 정리된 것

- `StatTile` 의 `variant` 제거 — `modal`(회색 웰) 변형의 소비자가 이 두 모달뿐이었고,
  둘 다 `card`(1단계 타일 문법)로 옮겼다. 단위 suffix 13px → 12px (디자인 가드는 짝수만
  받고, 12는 제거된 `modal` 변형이 이 자리에 쓰던 값이다).
- `ConnectionTestCard` 의 `providerLabel` prop 제거 — 유일한 소비자가 없어진 eyebrow 였다.
  `WaitingConnectionTestStepProps` 의 것은 형제 step 들과 공유하는 계약이라 남겼다.
- 실패 문구 표를 `app/components/ui/confirm-failures.ts` 로 추출 — 1·5단계가 같은 행위,
  같은 코드 집합에 부딪히므로 각자 들면 같은 실패가 화면마다 다른 말을 한다.
